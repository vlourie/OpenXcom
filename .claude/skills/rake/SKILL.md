Событие: **$ARGUMENTS**

## Сначала проверь, не повтор ли это

!`python tools/rake.py list`

Если в списке уже есть эти грабли — это **повтор**, а не новая запись:

```
python tools/rake.py hit R-0NN
```

Счётчик дошёл до 2 — текстовое правило не сработало. Дальше по протоколу ты **обязан** сделать защиту, а не переписать формулировку покрасивее:

- регрессионный тест, названный по номеру: `tests/test_r0NN_<кратко>.py`;
- либо проверку в `.claude/hooks/`, если тестом не ловится.

Готово — `python tools/rake.py disarm R-0NN tests/test_r0NN_....py`.

## Если это новые грабли

Сформулируй четыре поля. Ключевое — **Причина**: без неё запись бесполезна, потому что через месяц симптом будет выглядеть иначе.

```
python tools/rake.py add \
  --title   "<одна строка, узнаваемо>" \
  --files   "<глобы файлов, к которым это относится>" \
  --symptom "<что видно снаружи>" \
  --cause   "<что происходит на самом деле>" \
  --rule    "<что делать вместо этого>"
```

Требования к записи:

- **Файлы** обязательны и как можно точнее — по ним хук находит грабли перед правкой. Без них запись сработает только на старте сессии.
- **Правило** пишется как действие, а не как запрет. «Перед правкой спрайтов свериться с docs/research/sprite-format.md» лучше, чем «не ошибаться с размерами».
- Если причина ещё не ясна — не пиши грабли. Сначала выясни, иначе запись будет вводить в заблуждение.
