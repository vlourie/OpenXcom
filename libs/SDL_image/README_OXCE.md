# SDL_image 1.2 — исправленная сборка в составе игры

Игра читает картинки модов через SDL_image (`Surface::loadImage`, после lodepng). Пакет MSYS2
`mingw-w64-x86_64-SDL_image 1.2.12-8` (и `-9`) собран из архива 2012 года без единого исправления
безопасности. Здесь лежат исходники официальной ветки **SDL-1.2**; они компилируются вместе с игрой в статическую
библиотеку `oxce_sdl_image`, системная `libSDL_image.a` в линковку не попадает.

| ветка | `SDL-1.2` |
| коммит | `2ffb2e3e1eba037897164e3ac6c67570d8bccd79` (05.07.2026) |
| версия по заголовку | 1.2.13 |
| лицензия | zlib (`COPYING`), та же, что у 1.2.12 |

| контрольные суммы | `SHA256SUMS.upstream` — файлы ветки как есть; `SHA256SUMS` — они же с правками OXCE и `IMG_oxce.h` (байты файлов; `.gitattributes` запрещает git менять концы строк) |

Не взято: `external/` (копии libpng, libjpeg, libtiff, libwebp, zlib — берутся из MSYS2, они свежие),
проекты Xcode / VisualC, `IMG_ImageIO.m`, `IMG_UIImage.m`, `showimage.c`, сборка autotools.

## Почему эта ветка, а не Debian

Сравнены три варианта: архив 2012 года (`SDL_image-1.2.12.tar.gz`, SHA-256 `0b907229…5e699` — он же в пакете
MSYS2 и в `orig` Debian), Debian `1.2.12-14` (24 патча) и ветка SDL-1.2 (114 коммитов после 1.2.12).

- Все 20 патчей безопасности Debian (CVE-2017-2887, -12122, -14440, -14441, -14442, -14448, -14450,
  CVE-2018-3837, -3838, -3839, -3977, CVE-2019-5052, -5058, -5059, -5060, -7635, -12218, -13616,
  `IMG_pcx-out-of-bounds`) в ветке есть — теми же строками или равнозначным кодом (PCX переписан: строка
  распаковывается во временный буфер длиной `bpl`, копирование ограничено шириной). Остальные четыре патча Debian —
  сборка с libpng 1.6, libwebp и ключи `showimage`; первые два в ветке тоже есть.
- Сверх Debian в ветке — исправления 2021–2026 годов, которых в Debian нет: чтение за границей в PCX и GIF,
  XCF (CVE-2026-35444, `678ac6a4`; декодер RLE, `do_layer_surface`, разыменование нуля), переполнение палитры LBM,
  TGA с нулевым размером, XPM без `QUICK_COLORHASH`, BMP с нулевой глубиной и проверкой размера, ICO на 4 бита.
- Патчи Debian поверх ветки накладывать не нужно: дублей нет.

## Правки OXCE

Ветка SDL-1.2 как есть проверена на 106 570 повреждённых файлах под ASan + UBSan (`tests/sdl_image`): 224 файла
дали запись или чтение за буфером либо бесконечный цикл. Ни одного из этих исправлений в ветке нет (два есть в
основной ветке upstream, для SDL 3). Правки точечные, поведение на корректных файлах не меняют
(69 917 картинок игры и модов декодируются побайтно так же, как до правок и как старой библиотекой).

| # | Файл | Что было | Правка |
|---|---|---|---|
| 1 | `IMG_oxce.h`, строка `#include` в 13 декодерах | размер и глубина поверхности из файла уходят в `SDL_CreateRGBSurface` без проверки; SDL 1.2 пропускает отрицательную ширину и глубину больше 255 (в формате остаётся младший байт), поверхность выходит несогласованной — запись и чтение за пикселями (BMP, PCX, XCF) | одна проверка на входе: ширина и высота больше нуля и в пределах самой SDL (16384 × 65536), глубина 1–32, объём пикселей меньше 2 ГиБ; иначе отказ |
| 2 | `IMG_gif.c` | LZW: коды, ссылающиеся друг на друга по кругу, переполняют стек декодера — запись за буфером | проверка заполнения стека, перенос из основной ветки upstream (`b0c94a0b`, 26.08.2026) |
| 3 | `IMG_lbm.c` | блок IFF короче прочитанного из него или длиной от 2 ГиБ превращает пропуск блока в переход назад — те же блоки читаются без конца | отказ «invalid IFF chunk size» |
| 4 | `IMG_xcf.c` | чтение за концом файла возвращает мусор (`SDL_ReadBE32` SDL 1.2), списки смещений и свойств не кончаются | за концом файла читается 0 — конец любого списка |
| 5 | `IMG_xcf.c` | свойство длиной от 2 ГиБ — переход назад, те же свойства без конца | такое свойство считается концом списка |
| 6 | `IMG_png.c` | обратный вызов чтения не сообщает libpng о конце файла: в буфере остаётся прежний заголовок блока, libpng разбирает его снова и снова | за концом файла отдаются нули (блок без типа, libpng отказывает); в основной ветке upstream здесь `png_error` (`99982b9b`) |

После правок: те же 106 570 файлов — 0 отчётов санитайзера, 0 сбоев, 0 зависаний. Старая библиотека 2012 года на
первых 104 438 из них: 6 118 сбоев и зависаний (GIF 5 703, BMP 171, PCX 101, XCF 77, LBM 65, PNG 1) и
бесконечный цикл на корректном XCF.

Чего правки не дают: это не доказательство отсутствия ошибок. Образцы — обрезанные файлы, изменённые поля
заголовков и перевёрнутые байты; направленного поиска (libFuzzer с покрытием) не было. Декодер XCF остаётся самым
слабым: вложенные списки слоёв, уровней и плиток на специально собранном файле могут дать очень долгую загрузку.
Игра результат XCF, JPG, TIF и WEBP всё равно не принимает (нужны 8 бит с палитрой), но декодер при этом отрабатывает.

## Сборка

Отдельных шагов нет: `cmake` + `ninja` в `build-release`, как всегда. Сети не нужно — исходники в репозитории.
`CMakeLists.txt` (корень) при `OXCE_BUNDLED_SDL_IMAGE=ON` (по умолчанию для MinGW) не ищет системный SDL_image и
не кладёт `-lSDL_image` в линковку; `src/CMakeLists.txt` собирает `oxce_sdl_image` со всеми форматами прежней
библиотеки: BMP, GIF, JPG, LBM, PCX, PNG, PNM, TGA, TIF, WEBP, XCF, XPM, XV (и CUR, ICO в составе BMP).
libpng, libjpeg, libtiff, libwebp, zlib линкуются статически из MSYS2, как и раньше.

Защита от старой библиотеки: каталог `libs/SDL_image` стоит первым в путях заголовков, `Surface.cpp` не
компилируется с заголовком старше 1.2.13, а в строке линковки нет `-lSDL_image`. На других платформах
(`OXCE_BUNDLED_SDL_IMAGE=OFF`) берётся системная библиотека, как раньше.

## Обновление

1. `git clone --branch SDL-1.2 https://github.com/libsdl-org/SDL_image.git` в отдельную папку.
2. Скопировать те же 17 файлов (`IMG_oxce.h` — наш, не трогать), пересчитать
   `sha256sum IMG.c IMG_bmp.c … SDL_image.h COPYING CHANGES > SHA256SUMS.upstream` (без `IMG_oxce.h`).
3. `py -3 libs/SDL_image/oxce_patch.py libs/SDL_image` — ставит правки 1–6; каждая замена обязана найтись ровно
   один раз, иначе скрипт останавливается (место в upstream изменилось — правку сверить руками, возможно, она
   больше не нужна). Затем `sha256sum IMG*.c IMG_oxce.h SDL_image.h COPYING CHANGES > SHA256SUMS` и обновить
   `OXCE.diff` (`diff -u` против файлов upstream без CR).
4. Записать здесь новый коммит. Прогнать `tests/sdl_image` (сравнение со старой сборкой и повреждённые образцы
   под ASan + UBSan) — см. `tests/sdl_image/README.md`.

Проверка, что файлы не менялись: `cd libs/SDL_image && sha256sum -c SHA256SUMS`.
