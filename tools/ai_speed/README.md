# Замер скорости стенда ИИ

Скрипты аудита `docs/research/ai-sim-speed-audit-2026-09-30.md`. Все запускают игру только
невидимо (`ai_probe.Hidden`: свой рабочий стол + SDL dummy, R-124) и пишут итоги в `runs/`
(в гит не идёт). Интерпретатор — `py -3.13` (R-101), в трубу — с `PYTHONIOENCODING=utf-8` (R-001).

| Скрипт | Что делает |
|---|---|
| `run_one.py` | один бой: время процесса и боя, ЦП, память, доля E-ядер, размер лога → `runs/<имя>.json` |
| `cmp_runs.py` | таблица вариантов против базы: ускорение и **побайтное совпадение семи потоков записи** |
| `series_eq.py` | две серии `ai_arena.py` побайтно по каждому бою (таблица, запись, кандидаты, клетки, пути, потери): шлюз пассивности на `fair22` |
| `par_test.py` | N одинаковых боёв одновременно: боёв в минуту на этой машине |
| `hang_count.py` | сколько из N запусков не вышли сами (гонка `~StartState`, R-150) |
| `prof_battle.py` | выборочный профиль главного потока (StackWalk64 по `.pdata`, имена из `nm`) → `runs/<имя>.samples.json` |
| `prof_report.py` | отчёт по выборкам: плоский, включающий, дерево от `Game::run`; `--phase battle` — только бой |
| `attach_all.py` | по стеку каждого потока живого (повисшего) процесса игры → `runs/<имя>.samples.json` |
| `hang_stack.py` | самый частый стек из выборок с ближайшими экспортами системных DLL — чем занят повисший процесс |

## Порядок

```powershell
$env:PYTHONIOENCODING = "utf-8"
py -3.13 tools/ai_speed/run_one.py --build build-ai36 --mission STR_LOC_SPACE_STATION_1 --seed 201 --name st_base
py -3.13 tools/ai_speed/run_one.py --build build-ai36 --mission STR_LOC_SPACE_STATION_1 --seed 201 --name st_tools --opt oxceHdKillCam=false --opt oxceHdUi=0 --penv SDL_AUDIODRIVER=none --display 640x400
py -3.13 tools/ai_speed/cmp_runs.py st_base st_tools
```

`--build` принимает имя каталога от корня (`build-ai36`) или абсолютный путь к опытной сборке
(с патчем `docs/research/ai-sim-speed-exp.patch` флаги `--env OXCE_AI_FASTLOG=1` и остальные `OXCE_AI_*`).

Флаг считается пассивным, только если в строке варианта все семь потоков стоят с `=`
(`=result =decide =rec =cand =state =path =casualty`) — на станции **и** на городе (R-149),
потом на 22 боях `fair22` (R-113): две серии `ai_arena.py` на одной сборке, без флага и с ним,
и `series_eq.py` — таблица без `seconds`, запись, кандидаты, клетки, пути и потери побайтно по
каждому бою. Рядом обязателен контрольный опыт: заведомо непассивный флаг (`OXCE_AI_TICK=100`
в опытном патче) на той же станции даёт `!result`, другое зерно — `!` по всем потокам.

## Быстрый режим стенда — `OXCE_AI_FAST` (с build-ai39)

`AiProbe::fast()`: стенд пропускает всё, на что никто не смотрит, — ни одного кадра
(`Game::run`, `Map::draw`), ни одной анимации тайлов кроме дверей НЛО (у них кадр 7 — это
«дверь открыта», `Tile::openDoor`, а `Tile::getTUCost` при кадре больше 1 отдаёт проход через
дверь за 0 ОВ — механика), нет сцены добивания (`UnitDieBState::finalBlow` ждала до 4 с реального
времени на смерть), нет звука (`Game::initAudio` → `Options::mute`), лог держится одним
открытым файлом с буфером 1 МБ (сброс четыре раза в секунду и на каждой ошибке; раньше файл
открывался на каждую строку — треть короткого боя), процесс выходит сразу за строкой итога
(`CrossPlatform::exitNow`, без выгрузки мода и сохранения настроек). Пока грузится мод, главный
цикл спит по 1 мс (`StartState::think`): без кадров он крутился 3 млн раз в секунду и отбирал
кучу у потока загрузки (картинки интерфейса грузились 28 с вместо 1 с).

`tools/ai_probe.py` включает его по умолчанию (`OXCE_AI_FAST=1`, если не задано); контрольный
опыт — `--env OXCE_AI_FAST=0`. В `cfg` записи (`[AIRECHEAD]`, `[AIREC]`) переменная не входит:
она не меняет, как стенд играет. В сборке для игроков `fast()` — заглушка `false`.

Приёмка на build-ai39 (зерно 201, все семь потоков `=` против той же сборки без флага):

| бой | без флага | FAST | ускорение боя |
|---|---|---|---|
| бомбардировщик сектоидов (28 ходов, тормозит картинка) | 62,0 с | 17,8 с | ×3,5 |
| станция (15 ходов, тормозит ИИ) | 112,9 с | 111,8 с | ×1,0 (на опытной сборке ×1,1–1,3, шум ±15 %) |
| город мёртвых (61 ход, тупик; опытная сборка) | 375 с | 174 с | ×2,2 |
| охота на шамблера (39 ходов) | 50,0 с | 16,8 с | ×3,0 |

Старт процесса (всего минус бой) 6,7 → 3,0 с; контрольный опыт — другое зерно с флагом даёт `!` по
всем потокам.

Серия `fair22` (22 боя): `p39a` без флага = `p39f2` с флагом по `series_eq.py` — IDENTICAL 22 из 22,
сумма боёв 1951 → 767 с (×2,5), средний бой 89 → 35 с, 22 боя на 4 потоках за 209 с (см. журнал в
`docs/research/ai-sim-speed-audit-2026-09-30.md`, «Сделано»). Память процесса 1,0 ГБ → 0,6 ГБ.

Чего в быстром режиме **нет** и почему: короткий цикл ходьбы «вне экрана» (`UnitWalkBState`,
2 фазы вместо 8/16) прошёл все семь потоков на трёх одиночных боях, а на `fair22` разошёлся в
2 боях из 22 (`p39f`): число тиков между шагами юнита решает, в каком кадре его встречает
дверь НЛО, а от кадра зависит цена прохода (`Tile::getTUCost`). Длина цикла ходьбы — механика
(R-155); в стенде она прежняя.

Профиль:

```powershell
py -3.13 tools/ai_speed/prof_battle.py --build build-ai36 --mission STR_LOC_SPACE_STATION_1 --seed 201 --name st
py -3.13 tools/ai_speed/prof_report.py tools/ai_speed/runs/st.samples.json --phase battle --top 40
```

Шум: повтор того же боя на той же сборке расходится до ±15 % (планировщик кладёт процесс с
BELOW_NORMAL + EcoQoS на E-ядра, доля печатается в строке итога). Разницу меньше 15 %
подтверждать повтором и `--unthrottle 1`, а не одним прогоном (R-091).

Повис процесс (нет ЦП, лог кончился на `[AIRESULT]` или на загрузке) — сначала стеки, потом объяснение (R-150):

```powershell
py -3.13 tools/ai_speed/attach_all.py <pid> hang build-ai36
py -3.13 tools/ai_speed/hang_stack.py tools/ai_speed/runs/hang.samples.json
```

Отчётные строки стенда, по которым считается время: `[AIRESULT] ... ms=<реальное> vms=<виртуальное>`;
`[AIPROBE] battle` — начало боя. Полные тексты граблей стенда — `docs/rakes/aibench.md`.
