# Сборка OXCE HD в один клик

Двойной клик по `E:\OpenXCom\Выпуск\OXCE_Build.cmd` — окно с тремя кнопками.
Сборка вместе с подписью и публикацией релиза — `Выпуск\OXCE_Release.cmd`, см. `Выпуск\README.md`.

| Кнопка | Что делает | Результат в `E:\OpenXCom\dist` |
|---|---|---|
| **EXE** | проверки → `ninja` → поиск нужных DLL → Enigma Virtual Box | `OpenXComEx_<дата>_<время>.exe` |
| **Мод** | моды + `common`/`standard` → zip и патч | `OXCE-HD_…_mod.zip`, `OXCE-HD_…_mod_patch.zip` |
| **Оба** | всё вместе в один архив | `OXCE-HD_…_full.zip`, `OXCE-HD_…_full_patch.zip` |

Галочка «Пересобрать (ninja)» снята — упаковывается уже собранный `build-release\bin\openxcom.exe`.

Архив — «накатка»: распаковать в папку игры на другой машине (где `OpenXcomEx.exe` и `user`)
с заменой файлов и запускать `openxcom_hd.exe`. Внутри лежат `HD_README.txt` (что делать)
и `HD_VERSION.txt` (ветка, коммит, какие моды и откуда взяты).

Без окна (PowerShell, из `E:\OpenXCom`):

```powershell
.\tools\build\build.ps1 -Target Both
.\tools\build\build.ps1 -Target Exe -NoNinja
.\Выпуск\OXCE_Build.cmd mod
```

## Что попадает в архив

- **Моды** — список в ключе `Mods` (сейчас `hd` и `intro_voice`). У мода бывает две копии:
  в репозитории (`user\mods\<имя>`, туда по умолчанию пишут `gen_hd` и `build_pack`) и
  в установке игры. Сборщик обходит обе, печатает размер и время свежайшего файла и берёт
  свежую — это грабли R-015. Если свежая заметно меньше другой (больше чем на десятую часть
  файлов), сборка останавливается: так в релиз ушёл бы огрызок. Выбрать раз и навсегда —
  ключ `ModSource`, например `{"hd": "game"}` (`repo` или `game`).
- **Данные движка** — `bin\common` и `bin\standard`. Кладутся в каждый zip, а не только в «Оба»:
  без них у игрока вместо строк опций видны `STR_…`.
- **Записки** `HD_README.txt` и `HD_VERSION.txt` в корне архива.

## Проверки: на чём сборка останавливается

| Что проверяется | Почему |
|---|---|
| `CMAKE_HOME_DIRECTORY` в `CMakeCache.txt` равен `RepoDir` | грабли R-023: рядом бывает вторая копия дерева, и ninja собирает её |
| exe новее самого свежего `.cpp`/`.h`/`CMakeLists.txt` в `src` | иначе `-NoNinja` молча упакует вчерашнюю сборку |
| `bin\common` и `bin\standard` совпадают с установкой игры побайтно | Святое правило, грабли R-003; сверяются размер и MD5 каждого файла |
| в каждом моде есть то, что перечислено в `ModRequire` | без `hd\UI\*.ttf` и `hd\UI\fonts` HD-текст у игрока молча станет классическим |

Проверка данных движка сверяет 856 файлов примерно за секунду, так что она стоит в каждой сборке.

## Патч изменений

Полный архив — почти два гигабайта, и гонять его ради правки в три файла незачем. После
каждого zip сборщик сравнивает файлы стейджа со слепком прошлой сборки того же вида
(`dist\_work\manifest_full.txt`, `manifest_mod.txt`) и кладёт рядом второй архив — только
изменившееся, с той же раскладкой внутри. Распаковывается поверх игры так же, как полный.

Внутри патча `HD_PATCH.txt`; если с прошлого раза файлы пропали, их имена перечислены там же —
распаковка чужие файлы не удаляет, это надо сделать руками. Слепка ещё нет (первая сборка) или
ничего не изменилось — патч просто не создаётся.

## Как это устроено

- **DLL** не перечисляются вручную: скрипт читает таблицу импорта `openxcom.exe` (и самих DLL)
  и берёт всё, что лежит в `C:\msys64\mingw64\bin`. Сейчас это `libFLAC.dll`, `libogg-0.dll`,
  `libwinpthread-1.dll`. Плюс `DynamicDlls` — то, что SDL_mixer грузит сам во время игры
  (`libvorbisfile-3.dll` → `libvorbis-0.dll`, `libogg-0.dll` — музыка ogg); в таблице импорта
  их нет. Если внешних DLL не останется, Enigma пропускается.
- **Enigma**: проект `dist\_work\openxcom.evb` создаётся заново при каждой сборке (формат
  один в один как ваш `openxcom.evb`) и отдаётся `enigmavbconsole.exe`.
- **Моды** зеркалятся в `dist\_stage` через `robocopy /MIR`, поэтому повторная сборка копирует
  только изменённое. Архив делает 7-Zip (если установлен, быстрый режим `-mx=1`),
  иначе встроенный в Windows `tar.exe`.
- Хранятся последние `KeepLast` (5) результатов каждого вида, старые удаляются.

## Настройки — `tools\build\build_config.json`

| Ключ | Значение |
|---|---|
| `BuildDir` | папка ninja (`E:\OpenXCom\build-release`) |
| `MsysBin` | `C:\msys64\mingw64\bin` — добавляется в PATH, отсюда берутся DLL |
| `GameDir` | установка игры (`…\Dioxine_XPiratez`): вторая копия модов и сверка `common`/`standard` |
| `Mods` | какие моды класть в релиз, по именам папок |
| `ModSource` | для мода назвать копию явно: `"repo"` или `"game"`. Не задано — берётся свежая |
| `ModRequire` | что обязано лежать в моде; чего нет — сборка останавливается |
| `ModExcludeDirs` / `ModExcludeFiles` | что не класть в архив |
| `DataDirs` | папки движка рядом с exe (`common`, `standard`) |
| `EnigmaConsole` | путь к `enigmavbconsole.exe`, если он не в `Program Files (x86)\Enigma Virtual Box` |
| `SevenZip`, `Ninja` | явные пути, если не находятся сами |
| `ExeName` | имя exe внутри архива и в `CopyExeTo` |
| `ExeResultName` | образец имени готового exe в `dist`. Подстановки: `{stamp}` (2026-09-19_1543), `{date}`, `{time}`, `{hash}`, `{branch}`. По нему же считается маска для `KeepLast`, поэтому без подстановок старые не чистятся |
| `CopyExeTo` | папка, куда дополнительно положить свежий exe (например, установка Пираток для локальной проверки) |
| `KeepLast` | сколько старых результатов хранить (0 — не удалять) |
| `DynamicDlls` | DLL, которые exe подгружает сам (по умолчанию `libvorbisfile-3.dll`); скрипт пишет, какие ещё такие имена есть в exe |
| `ExtraDllDirs`, `FallbackDlls` | запасные места и список DLL, если импорт не прочитался |
