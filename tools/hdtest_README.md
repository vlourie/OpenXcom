# HD-render regression test (этап 0)

Цель: любая правка рендера проверяется побайтно, а не «на глаз».

## Снимок в игре

В бою нажать **Ctrl+F8** (опция `keyBattleHdTestDump` в options.cfg; просто F8 открывает отчёт игрока). В папке пользователя
(там же, где `screen000.png` от F12) появятся три файла:

| файл | что это |
|---|---|
| `hdtestNNN_map.png` | поверхность карты (без UI), базовое разрешение, до xBRZ/шейдеров |
| `hdtestNNN_frame.png` | весь кадр базового разрешения (с UI, без курсора мыши) |
| `hdtestNNN.json` | состояние: камера, разрешение, k, моды, сейв, ночное зрение и т.д. |

На этот кадр движок замораживает анимацию (кадр 0, дым/огонь/двери/частицы в нулевой фазе)
и прячет 3D-курсор, поэтому два снимка одного сейва с одной позицией камеры обязаны
совпасть до байта. После снимка игра продолжается как обычно.

Правила съёмки эталона: загрузить сейв, **не трогать камеру и мышь**, нажать Ctrl+F8.
Снимок с другой позицией камеры сравнивать бессмысленно — скрипт это заметит по json.

## Сравнение

Файлы лежат в пользовательской папке мастер-мода — там же, где сейвы и `screen000.png`
(для портативной установки это `<папка игры>\user\<мастер-мод>`, например `...\user\piratez`).
Найти: `Get-ChildItem -Recurse -Filter hdtest000.json <папка игры>`.

Если в PATH первым стоит `C:\msys64\mingw64\bin`, команда `python` — это python из MSYS2 без Pillow;
вызывайте системный интерпретатор явно (`py -3` или `C:\Python313\python.exe`).

```powershell
py -3 -m pip install pillow
$d = "C:\...\user\piratez"
py -3 tools\hdtest_compare.py "$d\hdtest000" "$d\hdtest001"
```

Выход: `RESULT: IDENTICAL` (код 0) или `RESULT: DIFFERENT` (код 1) с числом отличающихся
пикселей, грубой картой отличий и файлом `hdtestNNN_map_diff.png` (A | B | отличия красным).

Для этапа 2 (эталон k=1 против сборки k=4): `--scale 4` — эталон увеличивается nearest ×4
перед сравнением.

Другие ключи: `--map-only`, `--frame-only`, `--out DIR`, `--no-diff`, `--quiet`.

## Этап 2b: проверка при k=4

Мод `tools\hd_test_mod` переключает бой на масштаб 4 (BLANKS.PCK кадр 0 = 128×160).
Скопировать папку в `<папка игры>\user\mods\hd_test`, включить в списке модов, перезапустить.
Нужен 32-битный вывод (OpenGL или xBRZ/HQx) — в 8-битном режиме карта будет обрезана
(в лог пишется предупреждение). Шейдер лучше поставить `Raw`: SABR/xBR на картинке 1:1
только размывает.

Снимок Ctrl+F8 с модом даёт карту и кадр в 4 раза больше; сравнивать с эталоном k=1 так:

```powershell
py -3 tools\hdtest_compare.py "$d\hdtest000" "$d\hdtest00N" --scale 4
```

Ожидание: `IDENTICAL` по карте и по кадру. Производительность на этом этапе не оценивается —
рисование идёт тем же 8-битным софтверным путём на площади в 16 раз больше.

## Этап 3c: HD-паки и сглаживание

С этой сборкой 32-битный холст боя (`Canvas32`) умеет три режима рисования спрайтов;
**F9** (опция `keyBattleHdModeToggle`) переключает их по кругу, текущий режим пишется
внизу экрана и в json снимка (`hdMode`). Режим сохраняется в options.cfg (`oxceHdMode`,
по умолчанию 2).

| режим | что рисуется |
|---|---|
| 0 nearest | палитровые спрайты 1:1 — картинка побайтно классическая (так делались все эталоны) |
| 1 HD packs | кадры, для которых мод положил HD-версию; остальное как в 0 |
| 2 HD packs + xBRZ | как 1, а всё остальное движок сглаживает xBRZ сам (шахматный «дизеринг» превращается в полупрозрачность) |

Сравнение с эталонами имеет смысл только в режиме 0 — скрипт `hdtest_compare.py` откажется
сравнивать снимки с другим `hdMode`.

Формат HD-пака: мод кладёт RGBA PNG в `hd/<имя набора>/<номер кадра>.png` размером
k× исходного кадра (при k=4 — 128×160 для 32×40), для террейна — `hd/TERRAIN/<имя>.PCK/<номер>.png`.
Кадры без PNG рисуются как раньше. Затенение HD-кадра — тоновая кривая, снятая с рамп
самой палитры (по каналам, поэтому «посинение» тёмных тонов сохраняется); в ночном зрении
пиксель постеризуется в цветовую группу палитры, как классический перекрас.

Демо в `hd_test_mod/hd/`: курсор (CURSOR.PCK 0–5, сглаженный каркас) и дым (SMOKE.PCK 8–19,
мягкие полупрозрачные облака, сделаны из листа дыма X-Piratez). Генератор —
`make_demo_frames.py --smoke <Smoke_DIO.gif>`.

Порядок проверки: обновить `hd_test` (скопировать папку целиком), F9 до режима 0, Ctrl+F8,
сравнить с эталоном (`--scale 4`) — `IDENTICAL`; затем F9 в режим 1 (курсор и дым в HD),
F9 в режим 2 (всё сглажено), посмотреть глазами и на задержку.

## Этап 3d: скорость

Картинка не меняется (режим 0 по-прежнему побайтно эталонный), меняется только то, как она считается:

- холст `Canvas32` теперь не рисует сразу, а записывает команды кадра и выполняет их
  горизонтальными полосами на всех ядрах (`oxceHdThreads` в options.cfg: 0 = по числу ядер;
  в лог пишется `HD render: N render thread(s)`);
- скрипты перекраски юнитов/предметов выполняются в базовом разрешении 32×40, результат
  масштабируется — в k² раз меньше работы скрипта при том же результате;
- кадр мира отдаётся OpenGL напрямую, без промежуточной копии; копия холста в мир и
  наложение интерфейса тоже идут параллельно.

В json снимка Ctrl+F8 появились `hdThreads`, `drawMs` (полная отрисовка карты) и `flipMs`
(наложение интерфейса + вывод на экран) — пришлите их вместе с ощущениями по скорости.
Для живого счётчика включите в настройках `FPS counter` (Options → Video).

### 3d, вторая часть (по замерам Фотки6: draw 3.3 / 12.7 мс, flip 7.7 мс на 16 потоках)

- HD-кадры с уже наложенной тенью кэшируются (LRU до 256 МБ): затенённый HD-блит стал
  простым копированием с альфой, а сплошные участки строк копируются без проверок.
  В бенчмарке режим 2 сравнялся с режимом 0.
- Текстура OpenGL хранится как RGBA8 вместо RGB16: загрузка кадра без конвертации в драйвере.
- Скорость юнитов и ползунки: движок делает один шаг игры на кадр, поэтому при кадре дольше,
  чем интервал ползунка, ползунок «не работает». В HD-бою включается догон до
  `oxceHdFrameSkip` (по умолчанию 4) шагов за кадр — скорость держится по ползунку,
  анимация при медленных кадрах становится дискретнее. 0 в options.cfg — как раньше.

## Этап 3e: HD как обычная настройка

Масштаб больше не берётся из подменённого BLANKS.PCK: в Настройки → Дополнительно → вкладка OXCE →
раздел «Поле боя» появились два пункта:

- **Масштаб поля боя (HD)** — 1 (классика) … 4; действует со следующего боя (террейн грузится в этом
  масштабе). При значении больше 1 экран автоматически переводится в 32-битный режим, даже без OpenGL.
- **HD-спрайты** — 0/1/2, то же, что F9 в бою; меняется сразу.

Тестовый мод `hd_test` больше не нужен — удалите его из `user\mods`. Его демо-кадры переехали в
`tools\hd_demo_mod` (id `hd_demo`), это обычный HD-пак: скопировать в `user\mods\hd_demo`, включить.
Скрипт сравнения игнорирует `hd_test`/`hd_demo` в списке модов.

## Этап 4a: HD-свет

В режимах HD-спрайтов 1/2 (опция «HD-свет», по умолчанию включена) свет на карте рисуется
полем, а не одним числом на тайл: у каждого тайла девять узлов (центр — его собственная
освещённость, рёбра — общие с соседом за ребром, углы — общие с тремя соседями), и каждый
пиксель спрайта, нарисованного с тенью тайла, получает интерполированную яркость и цвет света.
Цвет — из слоёв света тайла: ночной ambient холодный (сила зависит от globalShade), огонь тёплый,
фонари/ламп желтоватые, персональный свет юнитов холодно-белый. Ровное поле рисуется через кэш
затенённых кадров (быстро), градиентное — попиксельно. Правила видимости (целочисленный
`getShade`) не тронуты; режим 0 по-прежнему побайтно классический.

## HD-картинки (без HD-интерфейса)

Опция `oxceHdPictures` (по умолчанию вкл.): картинки модов из `hd/UI/<имя>.png` (+ `.pal.txt`)
показываются в разрешении дисплея там, где рисуется классическая картинка с теми же пикселями
(иллюстрация уфопедии, полноэкранный фон): `Surface::blit` на экран → `HdUiArt::drawIfPicture` —
картинка (в масштабе мирового слоя, перекрашенная под палитру поверхности) идёт в мировой слой, а
классические пиксели не рисуются (остаются 0 = прозрачные), так что текст и кнопки поверх неё видны.
Вне боя мировой слой берёт масштаб дисплей/база (`Screen::resetDisplay`, пока состояние не задало свой:
бой), классический слой ложится на него через xBRZ (`Screen::composeSmooth`, опция `oxceHdUiSmooth`;
выкл — nearest, как в бою). Картинки регистрируются при загрузке модов (`Mod::loadHdUiArt`: по имени
спрайта и по имени файла одиночного спрайта, только размер PNG), декодируются при первом показе, в
памяти до 768 МБ последних. Проверка без экрана: `OXCE_HD_DUMP=<png>`, `OXCE_HD_DUMP_AFTER=<с>`,
`OXCE_HD_START=options|newbattle|load|geoscape|save|ufopaedia` (+ `OXCE_HD_ARTICLE=STR_...`),
`OXCE_HD_MOUSE/CLICK/TYPE`, `SDL_VIDEODRIVER=dummy`; тест-мод в облаке: статьи `STR_HD_PEDIA_TEST`.

## HD-юниты: паки `pack.hdp` и выгрузка наборов

`OXCE_HD_EXPORT=<папка>` (+ `OXCE_HD_EXPORT_SETS=units|all|имена`) после загрузки модов пишет наборы
спрайтов как 8-битные листы (`Mod::exportHdSets` → `HdSprites::exportSet`) и выходит; из них
`tools/hdart/upscale_units.py` делает `hd/<набор>/pack.hdp` (формат: `HdSprites::PACK_MAGIC`, таблица
кадров, PNG-блобы). `HdSprites::loadPack(set, scale)` регистрирует пак и россыпь `<n>.png` лениво
(`setLazy`), `find` читает кадр при первом обращении (пересчёт `resample`, если масштаб пака другой),
`trim` (конец `Canvas32::flush`) выбрасывает давние кадры сверх бюджета (384 МБ;
`OXCE_HD_PACK_BUDGET=<МБ>` — для проверки выбрасывания). Кэш тонированных копий (`tonedFor`) больше не
чистится посреди записи кадра (иначе команды указывали на освобождённые копии — так падало при
регистрации набора во время отрисовки): при смене `generation` копии одноразовые, чистка — в конце flush.

Бой без экрана: `OXCE_HD_START=battle OXCE_HD_CLICK="320,253;414,91;320,180"` (брифинг → снаряжение →
«ход 1»; клики через 1,2 с, последний за 1,2 с до дампа, `OXCE_HD_DUMP_AFTER=20`). В облаке нет
`ROUTES/*.RMP` оригинала — в тест-моде лежат копии `CULTA05.RMP` под именами недостающих блоков CULTA
и пустой `PLANE.RMP`; тест-паки: `hd/XCOM_0.PCK`, `hd/HANDOB.PCK`, `hd/SECTOID.PCK` (гладкие, без модели).

Потоки отрисовки (`oxceHdThreads`, 0 = авто) берут не все аппаратные потоки машины, а на два
меньше: когда заняты все, колбэку SDL_mixer не достаётся времени и короткие звуки (шаги юнита)
пропадают. На 24-поточной машине это 22 потока.

Картинки `hd/UI` не берутся для изображений, которые движок дорисовывает сам после загрузки модов
(`Mod::modResources`: `UNIBORD.PCK` — сетка строк экрана статов в бою, `BACK06.SCR` — сетка графиков,
`ALTBACK07.SCR`, `ALTGEOBORD.SCR`). Картинка делается из файла, где сетка ещё старая (в UNIBORD линии
через 10 строк), а движок стирает их и рисует свои через 9 — в игре это выглядело как лишние полосы
поверх экрана статов. `Mod::isPatchedSurface`, в логе строка «is of an image the engine redraws
itself - not used».
