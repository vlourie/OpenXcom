Lua API для модов OXCE-HD, версия 2

Мод пишется в файле lua/main.lua своей папки, в metadata.yml стоит luaApi: 2. Lua запускает только игра, лаунчер код мода не исполняет. API покрывает большую часть возможностей Y-script и не выходит за них. Страница описывает его полностью: чего здесь нет, того из Lua сделать нельзя. Имена обработчиков и выходных значений те же, что у Y-script.

Где это работает

Только в нашей сборке OXCE-HD. Обычный OXCE не знает ключ luaApi и запустит мод без Lua: рулсеты мода будут работать, а код нет. Если мод нужен и там, пишите его на Y-script.

С чего начать

  1. В лаунчере: Настройки, «Режим мододела», «Создать мод». Появится папка с рабочим примером.
  2. Запустите игру и начните бой. Строки game.log и print идут в user/openxcom.log.
  3. Поправьте main.lua и нажмите Ctrl+F5 в бою: код всех модов перечитается, итог на экране. Обычное быстрое сохранение F5 работает как раньше.

Папка Ruleset/ мода с файлами .rul подключается как у любого мода: там меняются числа предметов, брони и юнитов, исследования и всё остальное, что умеют рулсеты, в том числе Y-script. Нужна новая возможность в Lua — напишите нам тикет с описанием, что мод должен делать.

Рецепты

Каждый рецепт — целый файл lua/main.lua. Все проверены в настоящем бою. В одном файле может быть сколько угодно подписок, в том числе на один обработчик: они идут в порядке записи.

Регенерация

Каждый живой юнит в начале своего хода получает 1 здоровья. newTurnUnit приходит на ход каждой стороны, поэтому side сравнивается со стороной юнита.

game.on("newTurnUnit", function(unit, battle, turn, side)
  if side == unit:getFaction() and not unit:isKilled() and not unit:isStunned() then
    unit:addHealth(1)
  end
end)

Попадание в голову и сообщение на экране

Сила удваивается до вычитания брони, игрок видит сообщение.

game.on("hitUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, orig_power, damaging_type, battle_action, out)
  if out.part == game.BODYPART_HEAD then
    out.power = out.power * 2
    battle:flashMessage("Head hit! Power {0}", out.power)
  end
end)

Своё оружие

Прибавка к силе по типу оружия из рулсета. Подставьте свои типы. weapon_item может быть nil, поэтому сначала проверка.

local BONUS = { STR_PISTOL = 5, STR_RIFLE = 10 }

game.on("hitUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, orig_power, damaging_type, battle_action, out)
  local bonus = weapon_item and BONUS[weapon_item:getRuleItem():getType()]
  if bonus then
    out.power = out.power + bonus
  end
end)

Ранение отнимает очки времени

Сколько здоровья снято, столько же снимается очков времени.

game.on("damageUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, currPower, orig_power, part, side, damaging_type, battle_action, out)
  if out.to_health > 0 then
    out.to_time = out.to_time + out.to_health
  end
end)

Память в теге: ярость

Ранения копятся в теге и в начале своего хода возвращают боевой дух. Переменная Lua обнулилась бы при загрузке сейва, тег сохраняется. Тег объявляется в файле Ruleset/my_mod.rul:

extended:
  tags:
    BattleUnit:
      MY_RAGE: int

game.on("damageUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, currPower, orig_power, part, side, damaging_type, battle_action, out)
  if out.to_health > 0 then
    unit:setTag("MY_RAGE", unit:getTag("MY_RAGE") + 1)
  end
end)

game.on("newTurnUnit", function(unit, battle, turn, side)
  local rage = unit:getTag("MY_RAGE")
  if side == unit:getFaction() and rage > 0 then
    unit:addMorale(rage * 5)
    unit:setTag("MY_RAGE", 0)
  end
end)

Подзарядка патронов

В начале хода игрока каждый заряженный в оружие магазин получает 1 патрон, у всех сторон. Владельца у него нет: он лежит в оружии.

game.on("newTurnItem", function(item, battle, turn, side)
  if side == game.FACTION_PLAYER and item:isAmmo() then
    local now, max = item:getAmmoQuantity(), item:getAmmoQuantityMax()
    if now < max then
      item:setAmmoQuantity(now + 1)
    end
  end
end)

Аптечка лечит вдвое

Здоровье возвращается, только если на этой части тела есть рана.

game.on("healUnit", function(actor, item, battle, target, battle_action, out)
  out.health_recovery = out.health_recovery * 2
end)

Быстрое выздоровление

После миссии солдат лечит раны вдвое быстрее. Деление целое: в out принимаются только целые числа, / дал бы ошибку.

game.on("returnFromMissionUnit", function(unit, battle, soldier, out)
  out.recovery_time = out.recovery_time // 2
end)

Офицер поднимает дух

Пока в отряде стоит на ногах сержант или старше, каждый свой ход боевой дух +5. Список юнитов берётся раз в ход, а не на каждого юнита: он стоит тактов.

local seen_turn, officer
game.on("newTurnUnit", function(unit, battle, turn, side)
  if side ~= game.FACTION_PLAYER or unit:getFaction() ~= side then
    return
  end
  if seen_turn ~= turn then
    seen_turn = turn
    officer = false
    for _, u in ipairs(battle:getUnits(side)) do
      if u:getRankUnified() >= game.UNIT_RANK_SERGEANT and not u:isStunned() then
        officer = true
      end
    end
  end
  if officer then
    unit:setMorale(unit:getMorale() + 5)
  end
end)

Закалка в бою

Каждый свой ход храбрость юнита +1. addStat у юнита действует только на этот бой, постоянно менять характеристику можно у soldier.

game.on("newTurnUnit", function(unit, battle, turn, side)
  if side == unit:getFaction() then
    unit:addStat("bravery", 1)
  end
end)

Опыт вдвое

Имя experience_multipler с опечаткой пришло из Y-script. Здесь только out: этот обработчик только читает.

game.on("awardExperience", function(attacker, unit, weapon, battle_action, out)
  out.experience_multipler = out.experience_multipler * 2

Удар в спину

Шанс удара сбоку и сзади +20. ИИ считает так же и свои прогнозы: без math.random, без журнала на каждый вызов.

Страна ценит победы

Цена в магазине

Всё продаётся на четверть дороже. Обработчик приходит при каждой строке магазина: случайных чисел в нём быть не может, тяжёлых расчётов не нужно.

  out.cost_current = out.cost_current * 125 // 100

Свой шанс реакции

Реакция на цель сзади вдвое вероятнее. Шанс считается перед каждым выстрелом реакции и идёт дальше в reactionUnitReaction.

    out.reaction_chance = out.reaction_chance * 2

Камуфляж

Юнит с тегом брони MY_CAMO не виден дальше 10 клеток. Обработчик идёт на каждую пару юнитов при каждом шаге: только простой расчёт, без журнала.

    RuleArmor:
      MY_CAMO: int

game.on("visibilityUnit", function(observer_unit, target_unit, target_tile, distance, distance_max, distance_target_max, smoke_density, fire_density, smoke_density_near_observer, fire_density_near_observer, out)
  if target_unit and target_unit:getRuleArmor():getTag("MY_CAMO") == 1 and distance > 10 * 16 then
    out.current_visibility = 0
  end

Раненый устаёт

Раненый вполовину юнит получает за ход на 10 очков времени меньше. out.bonus приходит с расчётом рулсета, так же устроены сила и точность оружия, защита от пси и уклонение.

game.on("timeRecoveryBonusStats", function(unit, external_bonuses, weapon, ammo, battle_action, skill, out)
  if unit:getHealth() * 2 < unit:getHealthMax() then
    out.bonus = out.bonus - 10
  end
end)

Свой экран: пиратский банк

Экран нужно объявить и разрешить: в metadata.yml мода luaApi: 2 и luaCaps: [screens]. Благодаря menu игрок найдёт его на экране модов: кнопка в меню паузы или клавиша. Деньги лежат в теге кампании и живут в сейве.

  end }

Обработчики

Подписка: game.on("имя", функция). Аргументы идут в порядке входа Y-script, последним — таблица out с выходными значениями, если они есть. Значения в out принимаются целыми и только все разом: одно плохое значение — ошибка, остальные не применяются. Обработчики с пометкой «только читает» меняют только out: как и в Y-script, объекты там неизменяемые, и вызов set... или add... в них — ошибка. На одном обработчике сначала работает Y-script, затем Lua в порядке загрузки модов.

Аргументы

Обработчики получают их в порядке из таблицы выше. Значения, которые могут быть nil, проверяйте перед вызовом метода, иначе будет ошибка.

  • unit: юнит, с которым это произошло
  • item: предмет; в healUnit и skillUseUnit то, чем действуют, в skillUseUnit может быть nil
  • battle: бой
  • turn: номер хода
  • side: в newTurn* чей сейчас ход, FACTION_*; в обработчиках урона сторона юнита, SIDE_*
  • damaging_item: чем нанесён урон, обычно патрон; может быть nil
  • weapon_item: оружие; может быть nil
  • attacker: кто атаковал; может быть nil, например огонь или среда
  • skill: навык; в обработчиках урона обычно nil
  • orig_power: сила попадания после сопротивления брони типу урона, до правок скриптов и до вычитания брони
  • damaging_type: тип урона, DT_*
  • battle_action: действие, BA_*
  • currPower: сила после вычитания брони, бывает ноль и меньше
  • part: часть тела, BODYPART_*
  • health_damage: сколько снято здоровья, итог to_health
  • actor: кто действует
  • target: кого лечат
  • have_tu: 1, если очков времени на действие хватает, иначе 0
  • soldier: солдат игрока
  • weapon: чем действовали
  • victim: цель
  • is_same_faction: 1, если цель на той же стороне
  • attack_strength: сила атаки
  • defense_strength: сила защиты
  • distance: расстояние: в tryPsiAttackItem в вокселях, в detectUfo* в морских милях
  • distance_strength_reduction: на сколько расстояние снижает силу
  • arc_to_attacker: с какой стороны атакуют: 0 спереди, 4 сзади
  • defense_strength_penalty: штраф защиты за атаку сбоку и сзади
  • walking_phase: фаза шага
  • unit_sound_index: звук юнита из рулсета
  • tile_sound_index: звук клетки
  • base_tile_sound_index: начало звуков шагов в наборе
  • base_tile_sound_offset: смещение звука клетки
  • base_fly_sound_index: звук полёта
  • move: как идёт, BAM_*
  • country: страна
  • geoscape_game: геоскейп
  • totalXcomScore: очки игрока за месяц
  • totalAlienScore: очки врага за месяц
  • ufo: НЛО
  • craft: корабль
  • already_tracked: 1, если уже отслеживается
  • radar_total_strength: общая сила радаров
  • radar_max_distance: дальность радаров
  • hyperwave_total_strength: общая сила гипердетекторов
  • hyperwave_max_distance: дальность гипердетекторов
  • bonus: бонус солдата
  • external_bonuses: добавка от движка, с неё начинается out.bonus
  • ammo: патрон или nil; в обработчиках без выстрела nil
  • action_unit: кто действует
  • reaction_unit: кто реагирует
  • reaction_weapon: чем реагирует, может быть nil
  • reaction_battle_action: каким действием реагирует, BA_*
  • reaction_count: счётчик реакций этого юнита
  • action_target: цель действия, клетка; может быть nil
  • arc_to_action_unit: с какой стороны действующий: 0 спереди, 4 сзади
  • battle_game: бой
  • observer_unit: кто смотрит
  • target_unit: цель; в visibilityUnit nil, если проверяется клетка
  • target_tile: клетка цели
  • distance_max: наибольшая дальность зрения для цели, в вокселях
  • distance_target_max: наибольшая дальность зрения для цели, в клетках

  • fire_density: огонь на пути

  • fire_density_near_observer: огонь у смотрящего

Таблица game

game.on(имя, функция) подписывает функцию на обработчик, только пока грузится main.lua. game.log(...) и print(...) пишут строку в журнал игры. game.getRules() даёт все правила игры, в том числе из других модов, таблица rules выше. Разрешения и свои экраны

С luaApi: 2 у мода есть разрешения: слова в metadata.yml, например luaCaps: [screens]. Без слова метода для мода нет: вызов даёт ошибку Lua с названием разрешения. Неизвестное слово или luaCaps при luaApi: 1 отключают Lua мода. Сейчас есть одно слово: screens.

  • Экран строится из виджетов игры в координатах 320×200, поэтому работает при любом разрешении и масштабе.
  • Открывает его игрок на экране модов, если у game.screen есть menu, или обработчик через game.openScreen: тогда экран откроется, когда игра закончит свой шаг, в бою это может быть после анимации или после брифинга. Пока экран открыт, игра под ним стоит.
  • Функция построения и onClose только читают: без случайных чисел, записи и openScreen. Открытый и закрытый экран не меняет игру. В щелчке можно всё, что можно в обработчике.
  • Обработчики только для чтения, в том числе все обработчики геоскейпа и страниц для нердов, экран не открывают.
  • Esc закрывает экран всегда. Ошибка в построении закрывает экран и пишется в журнал. Кадровых обработчиков и таймеров нет: только реакция на действие.
  • Ручки виджетов живут, пока экран открыт, после закрытия: ошибка Lua.
  • Потолки: 64 виджета, 2000 строк списка, 8 столбцов, 256 пунктов, 64 экрана на мод, вложенность и очередь вместе 4, один экран на вызов, 8 экранов за ход боя или день кампании. Сверх потолка: ошибка мода, игра живёт.

Теги: память между сохранениями

Переменные Lua обнуляются при загрузке сейва, в новом бою и по Ctrl+F5. Долгая память — только теги. Тег объявляется в рулсете мода, например в файле Ruleset/my_mod.rul:

extended:
  tags:
    BattleUnit:
      MY_REGEN: int
    BattleItem:
      MY_CHARGE: int
Разделы по объектам: BattleUnit, BattleItem, BattleGame, GeoscapeGame, GeoscapeSoldier, Country, Ufo, Craft, RuleArmor, RuleItem, RuleSoldier, RuleSoldierBonus, RuleUfo, RuleCraft, RuleCountry, RuleResearch. Имя тега одно на всю игру: то же имя во втором разделе движок отбросит с ошибкой в своём журнале. В коде имя без приставки: unit:getTag("MY_REGEN"). Чтение и запись незнакомого тега — ошибка: опечатка видна сразу. Тег с одним именем в двух модах — один на двоих. Значение живёт, пока мод стоит: сейв без мода грузится и играется, но новое сохранение без мода значения теряет.

Что есть в самой Lua

Базовые функции: assert error getmetatable ipairs next pairs pcall print rawequal rawget rawlen rawset select setmetatable tonumber tostring type xpcall. Библиотеки string (без dump), table, math (без randomseed), utf8. Нет io os debug package require load dofile loadfile coroutine collectgarbage, байткод не загружается. math.random идёт через генератор игры; пока грузится main.lua, он даёт ошибку: загрузка не должна сдвигать сид боя. Часов и времени нет.

Лимиты

  • Память: 32 МБ на мод.
  • Один вызов обработчика: 2 000 000 инструкций, 5 000 000 тактов функций на C (шаблоны строк, string.rep, table.*). main.lua при загрузке получает в 10 раз больше инструкций.
  • 5 ошибок подряд выключают мод до Ctrl+F5 или новой загрузки. Игра не падает и не зависает.
  • Сообщение flashMessage: до 200 байт текста.

Ошибки

Ошибка или превышение лимита: выходные значения остаются как до вызова, в user/lua_errors.log пишутся мод, файл, строка, обработчик и текст. На экране показывается первая ошибка мода за загрузку и его отключение, а не каждая ошибка. Журнал начинается заново при каждой загрузке игры.

Что важно знать

  • Объект живёт только внутри обработчика, который его получил. Сохранённый в переменной даёт ошибку Lua, игра не падает.
  • Порядок pairs постоянен только у строковых ключей. Ключи-таблицы и tostring(таблица) зависят от адресов: у двух игроков тот же мод даст разный итог.
  • health_recovery у healUnit действует только на часть тела с раной, как и у Y-script.
  • Обработчик hitUnit, damageUnit, damageSpecialUnit, их ...Ammo, damageBonusBonusStats или meleeBonusBonusStats лишает ИИ точного прогноза выстрела: он считает результат неизвестным и может стрелять по неуязвимой цели.
  • Обработчики с пометкой «без случайных чисел» приходят из списков, подсказок и прогнозов, и сколько раз, игра не определяет: случайное число там сдвинуло бы общий генератор, поэтому math.random, randomRange и randomChance в них — ошибка. Изменить что-то кроме out там тоже нельзя.
  • visibilityUnit, бонусы и цены идут очень часто: на каждую пару юнитов при каждом шаге, на каждую строку магазина. Тяжёлый код или журнал на каждый вызов замедлят игру, а расчёт списков упрётся в лимит.
  • Там, где движок считает те же формулы в фоновых потоках, Lua не вызывается: остаётся значение Y-script. Итог действия считается в основном потоке и учитывает Lua.
  • Методы set... и add... сами держат значение в границах: здоровье и очки времени не выше максимума, боевой дух от 0 до 100. Поэтому прибавка очков времени в начале хода обычно ничего не даёт: они уже полные.
  • damageSpecialUnit приходит и при нулевом уроне, damageUnit только при силе попадания больше нуля.
  • getUnits, getItems и другие списки делают новую таблицу при каждом вызове и платят за каждый элемент. Лимит памяти или тактов даёт ошибку not enough memory или про лимит: вызывайте их редко, а не на каждый предмет каждого хода.
  • tryPsiAttack* и tryMeleeAttack* приходят и при прогнозах ИИ, поэтому там нет места побочным эффектам. math.random, randomRange и randomChance там сдвигают общий генератор, у двух игроков бой разойдётся.
  • Ошибка мода вне боя пишется в журнал сразу, а на экране появится в ближайшем бою.
  • Локальный мод может менять механику и сломать сейв. Для опытов лучше отдельная сборка в лаунчере.
  • В отчёт об ошибке уходят только id мода, версия и отметка [lua local], код и файлы мода не уходят. Журнал ошибок прикладывается, только если вы сами отметите его в форме.
