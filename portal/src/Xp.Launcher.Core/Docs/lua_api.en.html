Lua API for OXCE-HD mods, version 1

A mod is written in lua/main.lua in its folder, metadata.yml says luaApi: 1. Only the game runs Lua, the launcher never executes a mod's code. The API covers most of what the Y-script can do and does not go beyond it. This page describes all of it: what is not here cannot be done from Lua. The names of the handlers and of the output values are those of the Y-script.

Where it works

Only in our OXCE-HD build. Plain OXCE does not know the luaApi key and runs the mod without Lua: the mod's rulesets work and its code does not. If the mod is needed there too, write it in the Y-script.

Getting started

  1. In the launcher: Settings, "Modding mode", "Create mod". A folder with a working example appears.
  2. Start the game and begin a battle. Lines from game.log and print go to user/openxcom.log.
  3. Change main.lua and press Ctrl+F5 in battle: the code of all mods is read again, the result is on the screen. The usual quick save F5 works as before.

From Lua you cannot:
  • touch bases, research, production, money: the geoscape can be read, and only tags, a country's month, UFO detection and prices can be changed;
  • create or move units and items, change the map;
  • touch sprites and recolouring: those Y-script handlers come from the drawing threads on every frame, the Y-script is there for them;
  • make your own screens or choose the AI's actions, except a target's weight.
Plain OXCE works next to the code. The mod's Ruleset/ folder with .rul files is loaded as for any mod: the numbers of items, armor and units, research and everything else rulesets can do are changed there, the Y-script included. If you need something new in Lua, send us a ticket saying what the mod should do.

Recipes

Each recipe is a whole lua/main.lua file. All are checked in a real battle. One file can hold any number of subscriptions, several on one handler too: they run in the order they are written.

Regeneration

Each living unit gets 1 health at the start of its own turn. newTurnUnit comes on the turn of each side, so side is compared with the unit's side.

game.on("newTurnUnit", function(unit, battle, turn, side)
  if side == unit:getFaction() and not unit:isKilled() and not unit:isStunned() then
    unit:addHealth(1)
  end
end)

A head hit and a message on the screen

The power doubles before the armor is subtracted, the player sees a message.

game.on("hitUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, orig_power, damaging_type, battle_action, out)
  if out.part == game.BODYPART_HEAD then
    out.power = out.power * 2
    battle:flashMessage("Head hit! Power {0}", out.power)
  end
end)

A particular weapon

A bonus to the power by the weapon type from the ruleset. Put your own types in. weapon_item may be nil, so it is checked first.

local BONUS = { STR_PISTOL = 5, STR_RIFLE = 10 }

game.on("hitUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, orig_power, damaging_type, battle_action, out)
  local bonus = weapon_item and BONUS[weapon_item:getRuleItem():getType()]
  if bonus then
    out.power = out.power + bonus
  end
end)

A wound takes time units

As much health as is taken, as many time units are taken.

game.on("damageUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, currPower, orig_power, part, side, damaging_type, battle_action, out)
  if out.to_health > 0 then
    out.to_time = out.to_time + out.to_health
  end
end)

Memory in a tag: rage

Wounds add up in a tag and return morale at the start of the unit's own turn. A Lua variable would be reset when a save is loaded, a tag is saved. The tag is declared in the file Ruleset/my_mod.rul:

extended:
  tags:
    BattleUnit:
      MY_RAGE: int

game.on("damageUnit", function(unit, damaging_item, weapon_item, attacker, battle, skill, currPower, orig_power, part, side, damaging_type, battle_action, out)
  if out.to_health > 0 then
    unit:setTag("MY_RAGE", unit:getTag("MY_RAGE") + 1)
  end
end)

game.on("newTurnUnit", function(unit, battle, turn, side)
  local rage = unit:getTag("MY_RAGE")
  if side == unit:getFaction() and rage > 0 then
    unit:addMorale(rage * 5)
    unit:setTag("MY_RAGE", 0)
  end
end)

Rounds recharge

At the start of the player's turn each clip loaded into a weapon gets 1 round, on all sides. It has no owner: it lies in the weapon.

game.on("newTurnItem", function(item, battle, turn, side)
  if side == game.FACTION_PLAYER and item:isAmmo() then
    local now, max = item:getAmmoQuantity(), item:getAmmoQuantityMax()
    if now < max then
      item:setAmmoQuantity(now + 1)
    end
  end
end)

A medikit heals twice as much

Health returns only if this body part has a wound.

game.on("healUnit", function(actor, item, battle, target, battle_action, out)
  out.health_recovery = out.health_recovery * 2
end)

A quick recovery

After a mission a soldier heals wounds twice as fast. The division is whole: out takes only whole numbers, / would give an error.

game.on("returnFromMissionUnit", function(unit, battle, soldier, out)
  out.recovery_time = out.recovery_time // 2
end)

An officer lifts morale

While a sergeant or higher in the squad is on their feet, morale goes up by 5 every turn of the side. The list of units is taken once a turn, not for every unit: it costs ticks.

local seen_turn, officer
game.on("newTurnUnit", function(unit, battle, turn, side)
  if side ~= game.FACTION_PLAYER or unit:getFaction() ~= side then
    return
  end
  if seen_turn ~= turn then
    seen_turn = turn
    officer = false
    for _, u in ipairs(battle:getUnits(side)) do
      if u:getRankUnified() >= game.UNIT_RANK_SERGEANT and not u:isStunned() then
        officer = true
      end
    end
  end
  if officer then
    unit:setMorale(unit:getMorale() + 5)
  end
end)

Hardened in battle

Every turn of the side a unit's bravery goes up by 1. addStat of a unit works only for this battle, a stat changes for good at soldier.

game.on("newTurnUnit", function(unit, battle, turn, side)
  if side == unit:getFaction() then
    unit:addStat("bravery", 1)
  end
end)

Double experience

The misspelt name experience_multipler comes from the Y-script. Only out changes here: this handler only reads.

game.on("awardExperience", function(attacker, unit, weapon, battle_action, out)
  out.experience_multipler = out.experience_multipler * 2
end)

A stab in the back

The chance of a hit from the side and the rear goes up by 20. The AI's forecasts work it out too: no math.random, no log on every call.

game.on("tryMeleeAttackItem", function(item, attacker, victim, is_same_faction, skill, attack_strength, defense_strength, battle_action, arc_to_attacker, defense_strength_penalty, battle, out)
  if arc_to_attacker >= 2 then
    out.melee_attack_success = out.melee_attack_success + 20
  end
end)

A country values victories

If the player scored more than the enemy this month, a country does not cut the funding.

game.on("newMonthCountry", function(country, geoscape_game, totalXcomScore, totalAlienScore, out)
  if totalXcomScore > totalAlienScore and out.fundingChange < 0 then
    out.fundingChange = 0
  end
end)

A price in the shop

Everything sells a quarter dearer. The handler comes for each row of the shop: there can be no random numbers in it, and heavy work is not needed.

game.on("sellCostItem", function(item_rule, geoscape_game, difficulty_coefficient, out)
  out.cost_current = out.cost_current * 125 // 100
end)

A reaction chance of your own

A reaction to a target from behind is twice as likely. The chance is worked out before each reaction shot and goes on to reactionUnitReaction.

game.on("reactionUnitReaction", function(action_unit, reaction_unit, reaction_weapon, reaction_battle_action, reaction_count, weapon, skill, battle_action, action_target, move, arc_to_action_unit, battle_game, out)
  if arc_to_action_unit >= 3 then
    out.reaction_chance = out.reaction_chance * 2
  end
end)

Camouflage

A unit in armor with the tag MY_CAMO is not seen beyond 10 tiles. The handler comes for each pair of units at each step: only simple work, no log.

extended:
  tags:
    RuleArmor:
      MY_CAMO: int
armors:
  - type: STR_NONE_UC
    tags:
      MY_CAMO: 1

game.on("visibilityUnit", function(observer_unit, target_unit, target_tile, distance, distance_max, distance_target_max, smoke_density, fire_density, smoke_density_near_observer, fire_density_near_observer, out)
  if target_unit and target_unit:getRuleArmor():getTag("MY_CAMO") == 1 and distance > 10 * 16 then
    out.current_visibility = 0
  end
end)

The wounded get tired

A unit at half health gets 10 time units less per turn. out.bonus comes with the ruleset's calculation, the power and accuracy of a weapon, psi defence and dodge work the same way.

game.on("timeRecoveryBonusStats", function(unit, external_bonuses, weapon, ammo, battle_action, skill, out)
  if unit:getHealth() * 2 < unit:getHealthMax() then
    out.bonus = out.bonus - 10
  end
end)

A row on the nerds' page

A row of your own on an item's page. The player only reads it, it does not affect the battle.

game.on("statsForNerdsItem", function(item_rule, nerds, geoscape_game)
  if item_rule:isTwoHanded() then
    nerds:addTextRow("My mod", "two-handed: slower reactions")
  end
end)

Looking up another mod's rule

A mod checks whether another mod is installed: without such a rule getRuleItem returns nil, there is no error.

local other = game.getRules():getRuleItem("STR_ALIEN_ALLOYS")
if other then
  game.log("found: " .. other:getType())
end

Handlers

To subscribe: game.on("name", function). Arguments come in the order of the Y-script's input, the last one is the table out of output values, if there are any. Values in out are taken as whole numbers and only all at once: one bad value is an error, the others are not applied. Handlers marked "only reads" change only out: as in the Y-script, the objects there cannot be changed, and calling set... or add... in them is an error. On one handler the Y-script runs first, then Lua in the mods' load order.

Arguments

Handlers get them in the order of the table above. Check values that may be nil before calling a method on them, otherwise it is an error.

  • unit: the unit it happened to
  • item: the item; in healUnit and skillUseUnit the one used, in skillUseUnit it may be nil
  • battle: the battle
  • turn: the turn number
  • side: in newTurn* whose turn it is, FACTION_*; in the damage handlers the side of the unit, SIDE_*
  • damaging_item: what did the damage, usually a round; may be nil
  • weapon_item: the weapon; may be nil
  • attacker: who attacked; may be nil, for example fire or the environment
  • skill: the skill; usually nil in the damage handlers
  • orig_power: the power of the hit after the armor's resistance to the damage type, before scripts and before the armor is subtracted
  • damaging_type: the damage type, DT_*
  • battle_action: the action, BA_*
  • currPower: the power after the armor is subtracted, may be zero or less
  • part: the body part, BODYPART_*
  • health_damage: how much health was taken, the final to_health
  • actor: who acts
  • target: who is healed
  • have_tu: 1 if there are enough time units for the action, otherwise 0
  • soldier: the player's soldier
  • weapon: what was used
  • victim: the target
  • is_same_faction: 1 if the target is on the same side
  • attack_strength: the attack strength
  • defense_strength: the defense strength
  • distance: the distance: in tryPsiAttackItem in voxels, in detectUfo* in nautical miles
  • distance_strength_reduction: how much the distance reduces the strength
  • arc_to_attacker: from where the attack comes: 0 the front, 4 the rear
  • defense_strength_penalty: the defense penalty for an attack from the side or the rear
  • walking_phase: the phase of the step
  • unit_sound_index: the unit's sound from the ruleset
  • tile_sound_index: the tile's sound
  • base_tile_sound_index: the start of the step sounds in the set
  • base_tile_sound_offset: the offset of the tile's sound
  • base_fly_sound_index: the flying sound
  • move: how it moves, BAM_*
  • country: the country
  • geoscape_game: the geoscape
  • totalXcomScore: the player's score for the month
  • totalAlienScore: the enemy's score for the month
  • ufo: the UFO
  • craft: the craft
  • already_tracked: 1 if it is already tracked
  • radar_total_strength: the total strength of the radars
  • radar_max_distance: the range of the radars
  • hyperwave_total_strength: the total strength of the hyperwave decoders
  • hyperwave_max_distance: the range of the hyperwave decoders
  • bonus: the soldier's bonus
  • external_bonuses: the engine's addition, out.bonus starts from it
  • ammo: the round or nil; nil in handlers with no shot
  • action_unit: who acts
  • reaction_unit: who reacts
  • reaction_weapon: what it reacts with, may be nil
  • reaction_battle_action: by which action it reacts, BA_*
  • reaction_count: the count of this unit's reactions
  • action_target: the action's target, a tile; may be nil
  • arc_to_action_unit: where the acting unit is: 0 the front, 4 the rear
  • battle_game: the battle
  • observer_unit: who looks
  • target_unit: the target; nil in visibilityUnit if a tile is checked
  • target_tile: the target's tile
  • distance_max: the greatest view distance for the target, in voxels
  • distance_target_max: the greatest view distance for the target, in tiles
  • smoke_density: the smoke on the way
  • fire_density: the fire on the way
  • smoke_density_near_observer: the smoke near the observer
  • fire_density_near_observer: the fire near the observer
  • ai_unit: the AI's unit
  • item_rule: the item rules
  • armor_rule: the armor rules
  • craft_rule: the craft rules
  • ufo_rule: the UFO rules
  • difficulty_coefficient: this game's price multiplier, in percent
  • nerds: the nerds' page, rows are added to it

Tags: memory between saves

Lua variables are reset when a save is loaded, in a new battle and by Ctrl+F5. Tags are the only long memory. A tag is declared in the mod's ruleset, for example in the file Ruleset/my_mod.rul:

extended:
  tags:
    BattleUnit:
      MY_REGEN: int
    BattleItem:
      MY_CHARGE: int
The sections go by object: BattleUnit, BattleItem, BattleGame, GeoscapeGame, GeoscapeSoldier, Country, Ufo, Craft, RuleArmor, RuleItem, RuleSoldier, RuleSoldierBonus, RuleUfo, RuleCraft, RuleCountry, RuleResearch. A tag name is one for the whole game: the same name in a second section is dropped by the engine with an error in its log. In the code the name has no prefix: unit:getTag("MY_REGEN"). Reading or writing an unknown tag is an error: a typo shows at once. A tag of the same name in two mods is shared by them. A value lives while the mod is installed: a save without the mod loads and plays, but a new save made without the mod loses the values.

What Lua itself has

Base functions: assert error getmetatable ipairs next pairs pcall print rawequal rawget rawlen rawset select setmetatable tonumber tostring type xpcall. Libraries string (no dump), table, math (no randomseed), utf8. There is no io os debug package require load dofile loadfile coroutine collectgarbage, bytecode is not loaded. math.random goes through the game's generator; while main.lua loads it is an error: loading must not shift the battle's seed. There are no clocks and no time.

Limits

  • Memory: 32 MB per mod.
  • One handler call: 2 000 000 instructions, 5 000 000 ticks of C functions (string patterns, string.rep, table.*). main.lua gets ten times the instructions while it loads.
  • 5 errors in a row switch the mod off until Ctrl+F5 or a new load. The game neither crashes nor hangs.
  • A flashMessage: up to 200 bytes of text.

Errors

An error or a limit reached: the output values stay as they were before the call, user/lua_errors.log gets the mod, file, line, handler and text. The screen shows a mod's first error of the load and its switching off, not every error. The log starts anew at each start of the game.

Good to know

  • An object lives only inside the handler that received it. One kept in a variable gives a Lua error, the game does not crash.
  • The order of pairs is stable only for string keys. Table keys and tostring(table) depend on addresses: the same mod gives two players different results.
  • health_recovery of healUnit works only on a body part with a wound, as in the Y-script.
  • A hitUnit, damageUnit, damageSpecialUnit, their ...Ammo, damageBonusBonusStats or meleeBonusBonusStats handler takes the AI's exact forecast of a shot away: it treats the result as unknown and may shoot at an invulnerable target.
  • Handlers marked "no random numbers" come from lists, tooltips and forecasts, and how many times is not up to the game: a random number there would shift the common generator, so math.random, randomRange and randomChance in them are an error. Nothing but out can be changed there either.
  • visibilityUnit, the bonuses and the prices come very often: for each pair of units at each step, for each row of the shop. Heavy code or a log line on every call slows the game, and working out lists will hit the limit.
  • Where the engine works the same formulas out in background threads, Lua is not called: the value of the Y-script stays. The outcome of an action is worked out in the main thread and takes Lua into account.
  • set... and add... methods keep the value within its limits themselves: health and time units no higher than the maximum, morale from 0 to 100. So adding time units at the start of a turn usually does nothing: they are already full.
  • damageSpecialUnit comes at zero damage too, damageUnit only when the power of the hit is above zero.
  • getUnits, getItems and other lists make a new table on every call and pay for each element. The memory or tick limit gives an error not enough memory or about the limit: call them rarely, not for every item of every turn.
  • tryPsiAttack* and tryMeleeAttack* come during the AI's forecasts too, so they are no place for side effects. math.random, randomRange and randomChance shift the common generator there, and two players' battles will diverge.
  • A mod's error outside a battle goes to the log at once and shows on the screen in the next battle.
  • A local mod can change game mechanics and break a save. A separate build in the launcher is better for experiments.
  • A bug report carries only the mod's id, version and the mark [lua local], not its code or files. The error log goes with it only if you tick it in the form yourself.
