Сайт OXCE-HD - установка и обновление
=====================================

В архиве: исходники сайта (portal\), описание для разработчика (docs\portal\) и вики, собранная
из рулсетов (portal\deploy\wiki\*.json). Секретов тут нет: .env и portal.env остаются на сервере.

Данные сайта - база, вложения, ключи входа, сертификаты - лежат в томах Docker. Ни обновление,
ни пересборка их не трогают. Единственная команда, которая их убивает, - 'docker compose down -v';
её не звать НИКОГДА.


ЧТО В ЭТОМ ОБНОВЛЕНИИ
---------------------

- разделы модов: у каждого мода своя страница, описание и картинка;
- вики по модам - 13 563 страницы, собранные из рулсетов X-Piratez (оружие, броня, исследования,
  производство, корабли, постройки), с поиском и перекрёстными ссылками;
- форум: доски, темы, ответы, закрепление и закрытие;
- главная страница и весь облик сайта - в цветах и рамках самой игры.

База получит новые таблицы; старые не меняются. Тикеты, пользователи и вложения на месте.


ОБНОВЛЕНИЕ СЕРВЕРА (Linux, docker compose)
------------------------------------------

1. Распаковать архив ПОВЕРХ папки сайта, где лежат .env и portal.env. Файлы .env, portal.env и
   тома Docker в архиве не лежат и перезаписаны не будут.

2. Из папки portal/deploy:

       ./update.sh

   Скрипт пересоберёт образ, поднимет контейнеры, приведёт схему базы, применит каталог разделов
   и загрузит вики, а в конце покажет ответ /ready. Первая пересборка - несколько минут.

То же самое руками, если хочется видеть каждый шаг:

       docker compose up -d --build
       docker compose run --rm migrate seed --file /seed/community.json
       docker compose run --rm migrate wiki import --file /wiki/piratez.json

Вики можно не загружать (--no-wiki): сайт работает и без неё, просто раздел вики пуст.


ОБНОВЛЕНИЕ ТЕСТОВОЙ СТАНЦИИ (Windows 11 + Docker Desktop)
---------------------------------------------------------

Распаковать архив поверх папки сайта и в PowerShell из portal\deploy:

       powershell -ExecutionPolicy Bypass -File .\station.ps1

Команда up делает всё то же самое: сборка, схема, каталог, вики, проверка. Обновление - это она.

Команда .\station.ps1 content перезагружает только каталог и вики (образ при этом сверяется с
исходниками: старый образ не знает слова seed и вместо загрузки молча поднял бы веб-сервер).


ПЕРВАЯ УСТАНОВКА
----------------

Сервер (Linux):

       cd portal/deploy
       cp .env.example .env               # PORTAL_HOST, POSTGRES_PASSWORD (openssl rand -hex 24)
       cp portal.env.example portal.env   # Portal__Secret (openssl rand -base64 48), почта, бот
       ./update.sh
       docker compose run --rm -it migrate admin create --email you@example.com --name Vitali

   Нужны порты 80 и 443 с роутера на сервер: без 80 Let's Encrypt не выдаст сертификат, а без
   сертификата вход и формы не работают. Подробности - portal/deploy/README.md.

Станция (Windows): распаковать в любую папку, например C:\xp-portal, и запустить

       powershell -ExecutionPolicy Bypass -File .\station.ps1
       powershell -ExecutionPolicy Bypass -File .\station.ps1 admin you@example.com Vitali

   Первый раз 5-10 минут: качаются образы .NET, PostgreSQL и антивируса. В конце скрипт напишет
   адрес, например https://192.168.1.50:8443 - чужие сайты в Docker не трогаются, порты 80 и 443
   остаются им. Браузер один раз предупредит о сертификате: он выдан самим сайтом. Чтобы
   предупреждения не было (и чтобы лаунчер мог слать отчёты), см. команду root-cert.

   Доступ из интернета (настоящий сертификат, https://x-piratez.mywire.org:8443):
   вписать в portal\deploy\.env строку DYNU_API_KEY=<ключ с dynu.com, API Credentials>,
   пробросить на роутере TCP 8443 на этот компьютер и открыть 8443 в брандмауэре, затем
   .\station.ps1 internet   (назад: .\station.ps1 lan). Проверять с телефона по мобильному
   интернету, не по Wi-Fi: из своей сети на свой внешний адрес многие роутеры не пускают.

Дальше в обоих случаях: войти на сайт, «Безопасность» -> включить двухфакторную проверку
(Google Authenticator и т.п.), выйти и войти снова с кодом. Без этого страницы команды не
открываются. Первый администратор создаётся только из консоли, через веб - никогда.


ПРОВЕРКА, ЧТО ОБНОВЛЕНИЕ ДОЕХАЛО
--------------------------------

       curl -s https://<адрес>/ready      -> Healthy

Глазами: /mods - список модов с картинками; /wiki/piratez - оглавление вики по разделам
(«Исследования 2565», «Товары 1291» и так далее); /forum - доски. Если вики пуста, значит шаг
'wiki import' не прошёл - смотреть его вывод, он печатает 'written N, removed N'.


ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
------------------------

       docker compose logs -f portal migrate      (на станции: .\station.ps1 logs)

Откат: распаковать поверх предыдущий архив и повторить обновление. Новые таблицы останутся в
базе и старой версии не помешают - она про них не знает.


ВИКИ ПРИ НОВОЙ ВЕРСИИ МОДА
--------------------------

Вики собирается на машине, где установлен сам мод, и пересобирается, когда мод обновился:

   py -3 tools/portal_wiki.py --mod "Пиратки/Dioxine_XPiratez/user/mods/Piratez"
       --base bin/standard/xcom1 --slug piratez --lang ru --lang en --out dist/wiki/piratez.json

Готовый файл положить в portal/deploy/wiki/ на сервере и повторить шаг 'wiki import'. Импорт
удаляет собранные страницы, которых больше нет в рулсетах, и не трогает написанные человеком.

Тексты самих разделов (названия модов, описания, список досок форума) правятся не на сайте, а в
файле portal/deploy/seed/community.json - он источник правды, и шаг seed переписывает по нему
страницы модов. Доска, убранная из файла, не удаляется: у неё остаются темы, прячут её руками.
