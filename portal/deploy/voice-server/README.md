# Голосовой сервер X-Piratez — боевой

LiveKit со встроенным TURN за Caddy — по схеме генератора самого LiveKit (`github.com/livekit/deploy`).
Сайт остаётся на станции, здесь только медиа: лаунчер подключается сюда по пропуску, который выдал
сайт, а сайт управляет комнатами через API этого сервера и получает от него события. Решение и
порядок выпуска — `docs/portal/VOICE_RELEASE.md`. Станция со своей пробой голоса этим не задета.

## Что нужно от машины

- **Linux** (Ubuntu 22.04 или 24.04) с Docker Engine и `docker compose`. Windows и macOS не годятся:
  сервер работает в сети хоста, а Docker Desktop её не даёт.
- **Постоянный публичный IPv4**, порты 80 и 443 на машине ничем не заняты.
- **Два имени DNS** на этот адрес (A-записи): имя сервера (например `voice.example.org`) и имя TURN
  (например `turn.example.org`). Имена разные обязательно: Caddy делит порт 443 между ними по имени.
- Каталог этой папки целиком: `portal/deploy/voice-server` из архива станции.

## Порты

| Порт | Что |
|---|---|
| 80/TCP | выпуск сертификатов Let's Encrypt |
| 443/TCP | по имени сервера — сигналинг лаунчера и API сайта; по имени TURN — TURN/TLS |
| 7881/TCP | голос, если у игрока закрыт UDP |
| 7882/UDP | голос, основной путь: все участники на одном порту |
| 3478/UDP | TURN/UDP для строгих NAT |

7880 (LiveKit) и 5349 (TURN без TLS) **не открывать**: к ним ходит только Caddy на этой же машине.

## Первый запуск

```bash
cd voice-server
chmod +x setup.sh
./setup.sh voice.example.org turn.example.org https://x-piratez.mywire.org:8443
```

Третье значение — адрес сайта, на него LiveKit шлёт события комнат. Скрипт создаёт ключи LiveKit
(в `.env`, читать может только владелец), пишет `livekit.yaml` и `caddy.yaml`, поднимает сервер,
ждёт ответа LiveKit и печатает правила брандмауэра и то, что вводится на станции.

На станции, в `C:\xp-portal\portal\deploy`:

```powershell
.\station.ps1 livekit
```

Спросит адрес (`wss://` имя сервера), ключ (печатает `setup.sh`) и секрет — строку
`LIVEKIT_API_SECRET` из `.env` медиасервера (`grep LIVEKIT_API_SECRET .env`), ввод скрытый. Запишет
в `portal.env`, перезапустит сайт и проверит связь. **Секрет не пересылать ни в чат, ни в почту.**

## Проверка

- `curl https://voice.example.org` с любой машины отвечает `OK` — сертификат выдан, Caddy пускает
  к LiveKit (первые минуту-две после запуска сертификата ещё нет).
- На станции `.\station.ps1 voice-test` пишет `the media server answers: N room(s) open`. `FAILED`
  с `401` — не тот ключ или секрет; с ошибкой соединения — имя, DNS или 443.
- Вход в комнату из лаунчера, потом в журнале сайта (`.\station.ps1 logs`) нет строк `401` на
  `/api/v1/voice/webhook`: события LiveKit подписаны тем же ключом, что знает сайт.

## Обновление и смена настроек

- Версия LiveKit закреплена в `compose.yaml` (та, что прошла пробу на станции). Сменить —
  `LIVEKIT_TAG=v...` в `.env` и `./setup.sh` без аргументов, после пробы новой версии на станции.
- Любая правка `.env` — `./setup.sh` без аргументов: файлы настроек пересобираются из `.env`, правки
  руками в `livekit.yaml` и `caddy.yaml` пропадут.
- Новые ключи: удалить строки `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` из `.env`, `./setup.sh`, затем
  `.\station.ps1 livekit` с новыми значениями. До этого голос в лаунчерах не работает.
- Папку `caddy_data` не удалять: в ней сертификаты, а Let's Encrypt ограничивает частоту выдачи.
