# Серверная часть портала

Всё, что крутится на домашнем сервере с Docker. Пока здесь только обновление динамического DNS.

## ddns — адрес x-piratez.mywire.org всегда указывает на сервер

У провайдера меняется внешний IP. Контейнер `ddns` раз в 5 минут узнаёт текущий адрес
(`checkip.dynu.com`) и, **только если он изменился**, сообщает его Dynu по их протоколу
(`api.dynu.com/nic/update`, HTTPS). Раз в неделю адрес отправляется повторно, даже если не менялся.
Частые одинаковые обновления Dynu считает злоупотреблением, поэтому контейнер их не шлёт.

### Один раз

1. В Dynu: Control Panel → **Manage Credentials** → задать IP update password,
   отдельный от пароля аккаунта. Украдут его с сервера — смогут только переставить IP, не войти в аккаунт.
2. На сервере:

   ```sh
   cd portal/deploy
   cp .env.example .env
   printf '%s' 'IP-update-пароль' | sha256sum     # хэш вписать в DYNU_PASSWORD_SHA256
   docker compose up -d --build
   docker compose logs -f ddns
   ```

   В логе должно появиться `good x-piratez.mywire.org -> <IP>` или `nochg ...`.

`.env` в гит не идёт. Пароль уходит в Dynu только SHA-256-хэшем, по HTTPS.

### Что значит лог

| Строка | Что делать |
|---|---|
| `good` / `nochg` | всё в порядке |
| `IP changed: A -> B` | провайдер сменил адрес, запись обновлена |
| `dynu busy (911)` | у Dynu работы, повтор через 10 минут сам |
| `FATAL dynu answered 'badauth'` | неверный пароль или хэш; контейнер останавливается после трёх попыток, чтобы Dynu не заблокировал за перебор. Исправить `.env`, затем `docker compose up -d` |
| `FATAL ... 'nohost'` / `'notfqdn'` | опечатка в `DYNU_HOSTNAME` |

### Проверка без сервера

`python ddns/test_dynu.py` прогоняет скрипт против поддельного Dynu: первое обновление,
отсутствие повторных вызовов при том же IP, смену IP, недельный повтор, `badauth`, `911`,
`nochg`, запуск без пароля. Нужны `sh` и `curl` (Linux или Git Bash).

### Дальше

DNS — только половина дела. Чтобы лаунчеры игроков достучались до сервера, на роутере нужен
проброс портов 80 и 443 на сервер. Порт 80 нужен ещё и Let's Encrypt, чтобы выдать сертификат
на `x-piratez.mywire.org`. Это будет вместе с сайтом на этапе 2.
