# Серверная часть портала

Всё, что крутится на домашнем сервере с Docker: сайт с тикетами, его база, антивирус, HTTPS
и обновление динамического DNS.

| Контейнер | Что делает |
|---|---|
| `portal` | сайт и API `/api/v1` (ASP.NET Core, порт 8080 внутри сети) |
| `migrate` | один раз при каждом запуске приводит схему базы к текущей версии и выходит |
| `db` | PostgreSQL 18 |
| `clamav` | проверяет вложения; пока он грузит базы (пара минут), файлы ждут в статусе «проверяется» |
| `caddy` | HTTPS снаружи, сертификат Let's Encrypt сам получает и продлевает |
| `ddns` | держит `x-piratez.mywire.org` на текущем IP сервера |

## Сайт

Тестовая машина, где в Docker уже живут другие сайты и порты 80/443 заняты, — не этот раздел, а
`station.ps1` поверх `compose.station.yaml` (свой порт, свой сертификат, без ddns). Архив для обеих
машин собирает `pack.ps1`, инструкция для человека — `README.txt`, для Claude на той машине —
`station/CLAUDE.md`.

### Один раз

```sh
cd portal/deploy
cp .env.example .env                # DNS, PORTAL_HOST, POSTGRES_PASSWORD (openssl rand -hex 24)
cp portal.env.example portal.env    # Portal__Secret (openssl rand -base64 48), почта, токен бота
./update.sh
docker compose logs -f migrate portal
```

### Каждое обновление

```sh
./update.sh          # сборка, схема базы, каталог разделов, вики, проверка /ready
./update.sh --no-wiki
```

Данные в томах это не трогает. Три шага, которые скрипт делает за один заход, по отдельности:

| Шаг | Команда | Откуда файл |
|---|---|---|
| схема базы | `docker compose up -d --build` | контейнер `migrate` сам |
| разделы и доски | `docker compose run --rm migrate seed --file /seed/community.json` | `deploy/seed/` |
| вики из рулсетов | `docker compose run --rm migrate wiki import --file /wiki/piratez.json` | `deploy/wiki/` |

Обе папки контейнер видит только на чтение: образ собирается без `deploy/` (см. `.dockerignore`),
поэтому файлы приходят монтированием. Каталог применяется сколько угодно раз: записи сверяются по
адресу и переписываются, ничего не удаляется. Вики переписывается целиком, но страницы, написанные
человеком, импорт не трогает. Собирает её `tools/portal_wiki.py` — на машине, где установлен мод,
см. `wiki/README.md`.

Первый SuperAdmin создаётся только из консоли сервера, через веб — никогда:

```sh
docker compose run --rm -it migrate admin create --email you@example.com --name Vitali
```

Пароль спросит, не показывая набранное. Дальше: войти на сайт, «Безопасность» → включить
двухфакторную проверку, выйти и войти снова с кодом. Страницы команды без этого не открываются.
Потерян телефон и резервные коды:

```sh
docker compose run --rm migrate admin reset-2fa --email you@example.com
```

### Что обязательно для работы

- **Порты 80 и 443** на роутере ведут на сервер. Без 80 Let's Encrypt не выдаст сертификат,
  без сертификата сайт не работает вовсе: вход и формы требуют HTTPS.
- **`Portal__Secret`** задаётся один раз. Из него выводятся личные ссылки гостей на тикеты и
  подписи ссылок на файлы: смена секрета гасит все уже разосланные гостевые ссылки.
- **Почта** (`Email__Smtp*`) нужна для подтверждения регистрации и сброса пароля. Гостевые тикеты
  работают и без неё.
- **Telegram**: `Telegram__BotToken` в `portal.env`, а куда слать — на сайте, «Управление →
  Telegram»: чат по умолчанию и, если нужно, отдельный чат или тема на раздел (графика → художникам).
  Кнопка «проверить» кладёт в очередь пробное сообщение.

### Где лежат данные

| Том | Что там | Терять нельзя, потому что |
|---|---|---|
| `db-data` | база | тикеты, пользователи, журнал |
| `portal-files` | вложения под случайными именами | ссылки из базы указывают на них |
| `portal-keys` | ключи Data Protection | без них все выходят из аккаунтов, ссылки из писем перестают работать |
| `caddy-data` | сертификаты | Let's Encrypt ограничивает частые перевыпуски |

Ключи Data Protection лежат на томе незашифрованными — доступ к тому равен доступу к сессиям.

### Проверка

```sh
curl -s https://x-piratez.mywire.org/health    # Healthy — процесс жив
curl -s https://x-piratez.mywire.org/ready     # Healthy — и база отвечает
```

Описание API: `https://x-piratez.mywire.org/openapi/v1.json`, зафиксированная копия —
`docs/portal/openapi-v1.json`.

## ddns — адрес x-piratez.mywire.org всегда указывает на сервер

У провайдера меняется внешний IP. Контейнер `ddns` раз в 5 минут узнаёт текущий адрес
(`checkip.dynu.com`), и если он изменился, переписывает запись в Dynu. Входить можно двумя способами,
годится любой:

| | API-ключ (`DYNU_API_KEY`) | Пароль обновления IP (`DYNU_PASSWORD_SHA256`) |
|---|---|---|
| Где взять | Control Panel → API Credentials → API Key | Control Panel → Manage Credentials |
| Протокол | `https://api.dynu.com/v2/`, заголовок `API-Key` | `https://api.dynu.com/nic/update` |
| Что делает | читает запись, и только если IPv4 в ней другой — записывает новый, остальные настройки записи сохраняет | шлёт новый IP; тот же IP — не чаще раза в неделю, иначе Dynu считает это злоупотреблением |
| Раз в час | сверяет живую запись: если её поменяли руками, вернёт на место | — |
| Если украдут с сервера | **полный доступ к аккаунту**: можно удалить домен | можно только переставить IP |

Если заданы оба, работает ключ. Ключ удобнее, пароль безопаснее: берите пароль, если раздел
Manage Credentials у вас есть.

### Один раз

```sh
cd portal/deploy
cp .env.example .env          # вписать DYNU_API_KEY или хэш пароля
docker compose up -d --build ddns
docker compose logs -f ddns
```

В логе должно появиться `good x-piratez.mywire.org -> <IP>` или `nochg …`.
`.env` в гит не идёт. Пароль уходит в Dynu только SHA-256-хэшем, всё — по HTTPS.

### Что значит лог

| Строка | Что делать |
|---|---|
| `good` / `nochg` | всё в порядке |
| `IP changed: A -> B` | провайдер сменил адрес, запись обновлена |
| `dynu busy (911)` | у Dynu работы, повтор через 10 минут сам |
| `FATAL dynu API refused the key (401)` / `FATAL dynu answered 'badauth'` | неверный пароль или хэш; контейнер останавливается после трёх попыток, чтобы Dynu не заблокировал за перебор. Исправить `.env`, затем `docker compose up -d` |
| `FATAL ... 'nohost'` / `not among the domains` | опечатка в `DYNU_HOSTNAME`, или домен в другом аккаунте |

### Проверка без сервера

`python ddns/test_dynu.py` — 20 проверок против поддельного Dynu, обоими способами: обновление,
тишина при том же IP, смена IP, повторы, неверный ключ и пароль, чужой домен, ошибки сервера,
сохранение настроек записи при записи через API. Нужен только Python.

DNS — только половина дела: без проброса портов 80 и 443 (см. «Сайт») адрес указывает на
сервер, но до него никто не достучится.
