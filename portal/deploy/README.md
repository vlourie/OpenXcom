# Серверная часть портала

Всё, что крутится на домашнем сервере с Docker. Пока здесь только обновление динамического DNS.

## ddns — адрес x-piratez.mywire.org всегда указывает на сервер

У провайдера меняется внешний IP. Контейнер `ddns` раз в 5 минут узнаёт текущий адрес
(`checkip.dynu.com`), и если он изменился, переписывает запись в Dynu. Входить можно двумя способами,
годится любой:

| | API-ключ (`DYNU_API_KEY`) | Пароль обновления IP (`DYNU_PASSWORD_SHA256`) |
|---|---|---|
| Где взять | Control Panel → API Credentials → API Key | Control Panel → Manage Credentials |
| Протокол | `https://api.dynu.com/v2/`, заголовок `API-Key` | `https://api.dynu.com/nic/update` |
| Что делает | читает запись, и только если IPv4 в ней другой — записывает новый, остальные настройки записи сохраняет | шлёт новый IP; тот же IP — не чаще раза в неделю, иначе Dynu считает это злоупотреблением |
| Раз в час | сверяет живую запись: если её поменяли руками, вернёт на место | — |
| Если украдут с сервера | **полный доступ к аккаунту**: можно удалить домен | можно только переставить IP |

Если заданы оба, работает ключ. Ключ удобнее, пароль безопаснее: берите пароль, если раздел
Manage Credentials у вас есть.

### Один раз

```sh
cd portal/deploy
cp .env.example .env          # вписать DYNU_API_KEY или хэш пароля
docker compose up -d --build
docker compose logs -f ddns
```

В логе должно появиться `good x-piratez.mywire.org -> <IP>` или `nochg …`.
`.env` в гит не идёт. Пароль уходит в Dynu только SHA-256-хэшем, всё — по HTTPS.

### Что значит лог

| Строка | Что делать |
|---|---|
| `good` / `nochg` | всё в порядке |
| `IP changed: A -> B` | провайдер сменил адрес, запись обновлена |
| `dynu busy (911)` | у Dynu работы, повтор через 10 минут сам |
| `FATAL dynu API refused the key (401)` / `FATAL dynu answered 'badauth'` | неверный пароль или хэш; контейнер останавливается после трёх попыток, чтобы Dynu не заблокировал за перебор. Исправить `.env`, затем `docker compose up -d` |
| `FATAL ... 'nohost'` / `not among the domains` | опечатка в `DYNU_HOSTNAME`, или домен в другом аккаунте |

### Проверка без сервера

`python ddns/test_dynu.py` — 20 проверок против поддельного Dynu, обоими способами: обновление,
тишина при том же IP, смена IP, повторы, неверный ключ и пароль, чужой домен, ошибки сервера,
сохранение настроек записи при записи через API. Нужен только Python.

### Дальше

DNS — только половина дела. Чтобы лаунчеры игроков достучались до сервера, на роутере нужен
проброс портов 80 и 443 на сервер. Порт 80 нужен ещё и Let's Encrypt, чтобы выдать сертификат
на `x-piratez.mywire.org`. Это будет вместе с сайтом на этапе 2.
