# Генераторы HD-арта: все команды и параметры

Справочник по тому, чем мы рисуем и собираем HD-картинки. Значения в таблицах — **умолчания
из кода**, не из памяти: сверено с `argparse` каждого скрипта на 21.09.2026.

## Порядок конвейера

```
extract_pck.py      лист набора (original.png + layout.json)
        |
        +-- gen_hd.py --painter qwen21     весь набор разом, поле полов
        +-- gen_tile.py                    одна плитка, два прохода
        +-- gen_fire.py                    огонь: петля кадров
        +-- человек / GPT в чате           картинки руками в папку
        |
tile_forge.py fit   нарисованное -> клетки пака (геометрия навязывается кодом)
build_pack.py       нарезка целого нарисованного ЛИСТА в пак
        |
optimize_hd.py      сжатие пака на месте
```

Два окружения, не перепутать:

| что | чем запускать |
|---|---|
| Qwen-Image-2.1 (`gen_tile.py`, `gen_fire.py`, `gen_hd.py --painter qwen21`) | `tools\hdart\.venv-qwen21\Scripts\python.exe` |
| всё остальное (`tile_forge.py`, `build_pack.py`, `optimize_hd.py`, `extract_pck.py`) | `tools\hdart\.venv\Scripts\python.exe` или `py -3` |

Модели — в `E:\models` (переопределяется `--models` или переменной `HD_MODELS`).

## extract_pck.py — лист набора

Распаковывает PCK/TAB в сетку кадров, с которой работают все остальные.
Пишет в `<out>\<НАБОР>\`: `original.png` (палитровый), `original_x4.png` (RGBA, вход художника),
`mask_x4.png`, `layout.json` (размер кадра, число, колонки, поля, типы клеток из MCD).

| параметр | умолчание | что делает |
|---|---|---|
| `--data` | — (обязателен) | папка данных UFO: GEODATA, TERRAIN, UNITS, UFOGRAPH |
| `--out` | — (обязателен) | куда положить листы |
| `--scale` | `4` | во сколько раз увеличить `original_x<k>.png` |
| `--columns` | `8` | кадров в ряду |
| `--margin` | `4` | поле вокруг кадра (в исходных пикселях), чтобы сосед не подтекал |
| `--sets` | — | какие наборы, например `TERRAIN/CULTIVAT.PCK UNITS/XCOM_0.PCK` |
| `--all` | выкл | все боевые наборы ванильного UFO |
| `--palette` | — | своя палитра |

Набор без PCK (например `SMOKE.PCK` из гифа мода) этим не распаковать — лист собирается отдельно,
геометрия та же: `margin + c*(fw + 2*margin)`.

## gen_hd.py --painter qwen21 — весь набор

Полный конвейер покраски набора. Много ключей, ниже только те, что относятся к 2.1.

| параметр | умолчание | что делает |
|---|---|---|
| `--painter` | `sdxl` | `sdxl` \| `qwen` \| `qwen21` |
| `--qwen21-model` | `Qwen/Qwen-Image-2.1` | какой слепок брать |
| `--qwen21-steps` | `40` | шагов (как советует карточка модели) |
| `--qwen21-cfg` | `1.0` | `true_cfg_scale`. **2.1 рассчитана рисовать без направляющей**; >1 включает негатив, но уводит модель из привычного режима |
| `--qwen21-res` | `2048` | `output_resolution` конвейера: по нему он приводит и вход, и выход. У diffusers по умолчанию 1024 — вдвое ниже, чем училась модель, и ровно на нём открыт баг #14824 (правка вырождается в гало) |
| `--qwen21-mp` | `2.0` | мегапикселей на вход (2.0 — родные 2K; 0 — как есть) |
| `--qwen21-strength` | `0.0` | сила правки, если конвейер её принимает (у 2.1 параметра нет) |
| `--qwen21-offload` | `model` | `model` \| `seq` \| `none` |
| `--qwen21-prompt` | `strict` | `strict` — строгая реставрация; `paint` — «улучши до HD» |
| `--qwen21-hint` | `on` | дописывать ли, ЧТО нарисовано в кадре |
| `--qwen21-ref` | — | эталон материала (делается `make_ref.py`); если пусто, берётся `<sheets>\<набор>\ref.png` |
| `--no-ref` | выкл | не подхватывать `ref.png` |
| `--qwen21-ref-order` | `ref-first` | 2.1 держится за ПЕРВУЮ картинку сильнее, чем за текст |
| `--qwen21-ref-mp` | `1.0` | мегапикселей на эталон |
| `--qwen21-thrifty` | выкл | нарезка внимания и VAE: меньше видеопамяти, медленнее |

## gen_tile.py — одна плитка, два прохода

Для плиток террейна. Проход 1 «sketch-to-render» разрешает дорисовать деталь, проход 2
«precise-object-edit» снимает бортик и «коврик» по краю ромба.
Кладёт в `<sheets>\<набор>\tiles\`: `tile_<кадр>_t<n>_1hd.png`, `_2flat.png`, `_cut.png`,
и лист `tiles_<кадр>.png`.

| параметр | умолчание | что делает |
|---|---|---|
| `--set` | — (обязателен) | имя набора, например `DESERT.PCK` |
| `--sheets` | `art/TERRAIN` | папка листов |
| `--frame` | первый из `hints.json` | кадры через запятую: `1` или `0,1,7` |
| `--tries` | `1` | сколько раз нарисовать каждый кадр |
| `--seed` | `1234` | зерно; попытка `t` идёт с `seed + t*7919` |
| `--steps` | `40` | шагов |
| `--cfg` | `4.0` | **расходится с разбором 2.1** (там 1.0): ставить `--cfg 1.0`, если не нужен негатив |
| `--mp` | `2.0` | мегапикселей на проход |
| `--zoom` | `24` | во сколько раз увеличить клетку на входе |
| `--scale` | `4` | масштаб пака для готовой клетки |
| `--no-flat` | выкл | только первый проход |
| `--no-hint` | выкл | не дописывать подсказку кадра |
| `--model` / `--offload` | — / `model` | как у `gen_hd.py` |

```powershell
tools\hdart\.venv-qwen21\Scripts\python.exe tools\hdart\gen_tile.py `
    --sheets art/TERRAIN --set DESERT.PCK --frame 1 --tries 2
```

## gen_fire.py — огонь

Отдельный скрипт, потому что у огня нет ромба: ни прохода «плоскость», ни обрезки по альфе
оригинала. Кладёт в `<sheets>\<набор>\fire\`: `fire_<кадр>_t<n>_1hd.png`, `_cut.png`,
`fire_sheet_t<n>.png` и `fire_loop_t<n>.gif` — **петля и есть приёмка**, отдельный кадр ничего не говорит.

| параметр | умолчание | что делает |
|---|---|---|
| `--set` | `SMOKE.PCK` | набор |
| `--frame` | `0,1,2,3` | кадры петли через запятую |
| `--tries` | `1` | сколько раз нарисовать всю петлю |
| `--seed` | `1234` | одно зерно на всю петлю; попытка `t` идёт с `seed + t*7919` |
| `--steps` | `40` | шагов |
| `--cfg` | `1.0` | без направляющей |
| `--mp` | `2.0` | мегапикселей на проход |
| `--zoom` | `24` | увеличение кадра на входе |
| `--scale` | `4` | масштаб пака |
| `--grow` | `3` | на сколько исходных пикселей пламя может выйти за габарит оригинала |
| `--soft` | `48` | порог снятия подложки: меньше — мягче край |
| `--panel` | `90,90,96` | цвет подложки на входе |
| `--alpha` | `unpanel` | `unpanel` — снять подложку арифметикой; `keep` — модель вернула RGBA |
| `--gif-ms` | `125` | длительность кадра в гифе |
| `--pass2` | выкл | второй проход: добить фон и мусор |
| `--no-phase` | выкл | не дописывать номер фазы в промпт |

```powershell
tools\hdart\.venv-qwen21\Scripts\python.exe tools\hdart\gen_fire.py `
    --set SMOKE.PCK --frame 0,1,2,3 --tries 2
tools\hdart\.venv-qwen21\Scripts\python.exe tools\hdart\gen_fire.py `
    --set SMOKE.PCK --frame 4,5,6,7 --tries 2
```

## tile_forge.py fit — ковка пака из нарисованного

Художник отвечает за красоту, геометрию навязывает кузница. Номер кадра берётся из имени файла
только в явной форме: `45.png`, `frame_45.png`, `45_что-угодно.png`.
Пишет `<mod>\hd\<pack-path>\<набор>\<N>.png` и отчёт `forge\<набор>\` (лист + `forge.tsv`).

| параметр | умолчание | что делает |
|---|---|---|
| `--set` | — (обязателен) | набор |
| `--in` | — (обязателен) | папка с нарисованными плитками |
| `--sheets` | `art/TERRAIN` | папка листов |
| `--mod` | — | куда писать пак; пусто — только отчёт |
| `--pack-path` | `TERRAIN` | подпапка пака; для не-террейна пусто |
| `--scale` | `0` | масштаб пака; 0 — как в `layout.json` |
| `--rim` | подбор | доля обрезки тёмного ободка |
| `--max-inset` | `0.20` | предел обрезки периметра |
| `--kind` | `auto` | `auto` \| `floor` \| `object`; auto берёт тип из MCD |
| `--alpha` | `drawn` | `drawn` \| `original` \| `both` |
| `--grow` | `1` | расширение габарита |
| `--flatten` | `auto` | деление на собственное размытие против перепада яркости |
| `--report` / `--preview` | `forge` / `6` | папка отчёта, сколько клеток на лист |
| `--list-missing` | выкл | назвать кадры, которых в папке нет |

```powershell
py -3 tools\hdart\tile_forge.py fit --sheets art/TERRAIN --set DESERT.PCK `
    --in gpt_desert\return --mod "Пиратки\Dioxine_XPiratez\user\mods\hd"
```

## build_pack.py — нарезка целого листа

Когда нарисован ЛИСТ целиком (выход `gen_hd.py`), а не отдельные плитки.
Лист должен быть в раскладке `layout.json` и в её масштабе.

| параметр | умолчание | что делает |
|---|---|---|
| `--sheets` / `--set` / `--hd` / `--mod` | — (обязательны) | листы, набор, нарисованный лист, куда писать |
| `--pack-path` | пусто | `TERRAIN` для террейна, пусто для остальных |
| `--alpha` | `original` | `original` \| `painted` \| `both` |
| `--feather` | `1.5` | мягкость силуэта предметов (HD-пиксели) |
| `--floor-under` | `1.0` | сколько своего пола подложить под предмет |
| `--grow` | `0` | расширить покрытие оригинала перед растушёвкой |
| `--frames` | все | только эти номера |
| `--color-match` | `0.8` | насколько вернуть средний тон и разброс к оригиналу |
| `--chroma-lock` | `1.0` | удержание цветности |
| `--variants` | `auto` | писать ли `<N>.v<n>.png` |
| `--variant-tone` | `1.0` | сколько перекраски варианта оставить |
| `--no-preview` | выкл | не делать `variants_field.png` |

## optimize_hd.py — сжатие пака

Три шага: убрать лишний альфа-канал, при возможности перевести в палитру с проверкой по PSNR,
пережать без потерь (oxipng, если стоит `pyoxipng`). Размеры, имена и `.pal.txt` не трогает.
Повторный запуск безопасен.

| параметр | умолчание | что делает |
|---|---|---|
| `--mod` | — (обязателен) | папка мода; обходится её подпапка `hd\` |
| `--mode` | `palette` | `palette` \| `lossless` (без квантования) |
| `--min-psnr` | `34` | ниже — кадр остаётся полноцветным |
| `--only` | — | только эти папки под `hd\`, через запятую: `--only TERRAIN\DESERT.PCK` |
| `--skip` | — | пропустить эти |
| `--jobs` | по ядрам | сколько картинок разом |
| `--level` | `1` | усилие oxipng 0–6; 1 в пределах ~1% от 3 и много быстрее |
| `--dry-run` | выкл | только замер, ничего не пишет |

```powershell
tools\hdart\.venv\Scripts\python.exe tools\hdart\optimize_hd.py `
    --mod "Пиратки\Dioxine_XPiratez\user\mods\hd" --only SMOKE.PCK
```

**Гнать на машине с паком.** При передаче через мост палитровый PNG перекодируется в RGBA и
весь выигрыш теряется. Порядок всегда: сначала файлы легли в мод, потом сжатие на месте.

## Куда движок смотрит

Читает `HdSprites::loadPack`, ничего в рулсет писать не надо:

| что | путь |
|---|---|
| обычный набор | `hd\<ИМЯ НАБОРА>\<кадр>.png` — например `hd\SMOKE.PCK\0.png` |
| террейн | `hd\TERRAIN\<ИМЯ>.PCK\<кадр>.png` |
| интерфейс | `hd\UI\<имя файла>.png` |
| вариант кадра | `<кадр>.v<n>.png` рядом |
| пак одним файлом | `hd\<набор>\pack.hdp` |
| «взрослое» дерево | `hd_18+\...` — перекрывает обычное пофайлово |

Размер кадра: либо ровно `база * k`, либо любая целая кратность базы (32×40 → 128×160 и т.п.).

**`.v<n>` значит разное в разных путях рисования** — это ловушка:

| где | что такое вариант 1 |
|---|---|
| огонь на клетке (кадры 0–3 `SMOKE.PCK`) | промежуточный кадр: на нечётном полутакте берётся он, огонь идёт вдвое чаще |
| попадание по юниту (кадры 4+ `SMOKE.PCK`, `HIT.PCK`) | **кровь**, а не второй вариант пламени |
| пол террейна | вариант клетки, выбираемый узором по карте |

| набор | чем рисовали | куда легло | итог |
|---|---|---|---|
| `DESERT.PCK`, 46 кадров | GPT в чате, входы из `gpt_desert\` | `gpt_desert\return` → `tile_forge fit` → мод `hd` | полы с ровным песком (#0) модель заменила на крупные волны — на карте решётка по стыкам; предметные кадры (#1, #8) вышли хорошо |
| `SMOKE.PCK` 0–3, огонь на клетке | `gen_fire.py --tries 2` | `hd\SMOKE.PCK\0–3.png` + `.v1` | t2 оказался другим костром, а не промежуточной фазой; `.v1` сняли, оставили четвёрку |
| `SMOKE.PCK` 4–7, попадания | тот же, кадры 4–7 | `hd\SMOKE.PCK\4–7.png` | однородная четвёрка, петля читается; порядок переставлен на `4 → 6 → 5 → 7` |

## Грабли, которые уже стоили времени

1. **2.1 возвращает фиолетовый фон, а не прозрачный.** Ждать RGBA от модели нельзя, подложку
   снимаем арифметикой при сборке.
2. **Полупрозрачную кайму нельзя переводить в RGB как есть.** После обратного смешивания с
   фиолетовым край зеленеет. У огня спасает правило `R ≥ G ≥ B` — оно верно всегда и гасит
   и зелёную кайму, и фиолетовую.
3. **Зерно — на всю петлю, а не на кадр.** Разные зёрна дают не фазы одного огня, а разные огни.
   Между попытками (`--tries`) зерно меняется намеренно, внутри петли — нет.
4. **`gen_tile.py` и `gen_fire.py` не передают `output_resolution`.** Его выставляет только
   `gen_hd.py` (`--qwen21-res 2048`), а оба наших скрипта строят свой `Namespace` без него —
   значит конвейер берёт умолчание diffusers 1024, ровно тот случай, где открыт баг #14824 с гало.
   Тёмный ободок вокруг пламени в кадрах 4–7 похож именно на это. Правка на одну строку в
   `run_pass` обоих скриптов — **ещё не сделана**.
5. **`--cfg` у `gen_tile.py` по умолчанию 4.0**, хотя разбор 2.1 говорит 1.0. Ставить руками.
6. **Мод собран не из того листа, на который смотришь.** `painted_x4.png` в папке листа — это
   отдельный прогон локального художника; в паке может лежать совсем другое. Сверять с
   установленными PNG, а не с листом.
7. **Через мост файлы перекодируются.** Сжимать только на машине с паком.
