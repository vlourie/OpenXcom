## Увеличенные кадры: измерения и выбор

Стенд X-Piratez + HD-моды, цепочка «оборона базы → глобус → бой → глобус → бой → глобус → оборона базы», в каждом
бою два конца хода. Один и тот же exe диагностической копии с переключателем прежнего пути, масштаб 4 — по четыре
прогона каждого варианта.

| Что | Значение |
|---|---|
| Создано увеличенных кадров (масштаб 4) | 8458 в первом бою (15 наборов, 128 МБ), 11 406 после трёх боёв (27 наборов, 201 МБ) |
| Реально нарисовано | 214 из 11 406 на повторе боя (HANDOB 31 из 3104, FLOOROB 5 из 1394) — 2–3 % |
| Создано и не использовано | 97–98 % |
| Время одного кадра | около 10 мкс |
| Суммарная подготовка | 81–88 мс первый бой, 114–123 мс за три боя; каждый новый бой +11…18 мс |
| Повторное использование между боями | полное: повтор боя — 0 новых наборов; новый бой добавляет 5–7 наборов |

Память процесса (прежний путь → по первому обращению), МиБ:

Время кадра в бою (масштаб 4, прежний → новый): среднее 0,35–0,73 → 0,37–0,72 мс; p95 2,3–3,3 → 2,3–3,2 мс;
p99 3,6–7,6 → 3,6–7,7 мс; кадров дольше 33 мс за бой 4–41 → 5–42 (в пределах разброса между прогонами).
Первый показ: кадр загрузки 198–760 → 180–556 мс, следующий за ним 28–230 → 29–194 мс. Микрофризов нет: кадр
заполняется около 10 мкс, а за бой заполняется несколько сотен кадров.

Сравнение вариантов:

- **А. Освобождать после боя.** Глобус −128…201 МиБ, бой без изменений; следующий бой заново создаёт наборы
  (+80–120 мс) и заново регистрирует HD-паки (ключ пака — адрес пикселей кадра). Неиспользуемые кадры создаются
  по-прежнему.
- **Б. По первому обращению (выбран).** Память меньше и в бою, и на глобусе, подготовка боя быстрее на 70–110 мс,
  время кадра то же. Жизненный цикл наборов не тронут: освобождение по-прежнему только при смене масштаба, парковка
  транзакционной загрузки переставляет те же указатели. Нового кэша нет — тот же `Mod::_hdSets`.
- **В. Нужные при подготовке, остальные лениво.** Не нужен: кадр стоит 10 мкс, выигрывать предсозданием нечего,
  а список «нужных» пришлось бы вычислять.

Проверки: кадры без анимации боя (масштабы 1–4, режимы HD 0–2, зум, F11, конец хода, три боя) — 74 устойчивых кадра
из 78 совпали побайтно с прежним путём, 4 неустойчивых (полоса панели после F11, расходится и между двумя прогонами
прежнего пути) совпали с одним из них. Масштаб 1 путь не затрагивает (увеличенных наборов нет). На рабочей сборке:
журнал запуска и загрузок совпал, откаты и годные загрузки со сменой масштаба 4↔1, 3↔1 и палитровые бои 2→2, 2→4 —
PASS (единичное расхождение кадра 1→3 в первом прогоне при трёх повторах не воспроизвелось: анимация карты).

Остаток: кадры, к которым бой обратился, живут до смены масштаба (после трёх боёв память глобуса ниже на 195–205 МиБ из 201 МБ наборов, то есть остаются единицы МиБ).

## Распаковка PNG: +8 МиБ в меню

Занятая память кучи в меню одинакова с распаковкой в потоках и без неё: 240 МБ занято, 172 МБ живых объектов C++.
Разница целиком в свободной, но закреплённой за кучей памяти: 30–33 против 22–24 МБ. Это память аллокатора,
доступная для повторного использования, не удерживаемые буферы; освобождать нечего. Временный бюджет: распакованные
кадры набора живут до конца его применения и читаются порциями; отдельно этот бюджет не замерялся, на пик запуска
(он приходится на этап правил) не влияет. Большие HD-паки этим путём не идут: их кадры читаются по обращению.
