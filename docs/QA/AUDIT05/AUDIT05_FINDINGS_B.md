## AUD05-001 — чтение за концом двоичных данных клеток (`totalTiles` не сверяется с размером `binTiles`)

1. **Где:** `src/Savegame/SavedBattleGame.cpp`, `SavedBattleGame::load`, строки 206–229.
2. **SHA:** `ffbec78ec`.
3. **Фрагмент:**
   ```cpp
   std::vector<char> binTiles = reader["binTiles"].readValBase64();
   Uint8* ptr = (Uint8*)binTiles.data();
   Uint8* dataEnd = ptr + totalTiles * serKey.totalBytes;
   while (ptr < dataEnd) { int index = unserializeInt(&ptr, serKey.index); … }
   ```
4. **Первопричина:** конец данных считается из двух чисел сейва (`totalTiles`, `tileTotalBytesPer`), а настоящий размер
   буфера `binTiles.size()` в расчёте не участвует. Размеры полей (`tileIndexSize` и др.) тоже берутся из сейва как есть;
   при `tileTotalBytesPer` меньше `tileIndexSize` шаг `ptr += totalBytes - index` уходит в беззнаковое переполнение.
5. **Условия:** сейв боя, в котором `totalTiles × tileTotalBytesPer` больше длины `binTiles`.
6. **Последствия:** чтение чужой памяти кучи; прочитанное становится номерами клеток и объектов → дальше запись по
   случайному номеру клетки (AUD05-002). В выпуске — падение или молча испорченная карта.
7. **Происхождение:** OpenXcom (`SavedBattleGame.cpp:166` в `4a4bae5fa`), перенесено в OXCE без изменений.
8. **Воспроизведение:** `py -3.13 docs/QA/AUDIT05/evidence/B/save_corrupt_battle_test.py run total_tiles_x16`
   (в сейве `totalTiles: 3279` заменено на `52464`).
9. **Факт:** ASan `heap-buffer-overflow READ of size 4`, 0 байт за областью 75 417 байт; стек
   `unserializeInt (SerializationHelper.cpp:53) ← SavedBattleGame::load (:225) ← SavedGame::load (:775) ← LoadGameState::think (:169)`.
10. **Ожидание:** окно «не удалось загрузить», игра продолжает работать.
11. **Исправление:** перед циклом проверить `totalBytes >= index + обязательные поля` и
    `totalTiles * totalBytes <= binTiles.size()`; иначе `throw Exception("Invalid tile data")`.
12. **Риск для механики:** нет — исправные сейвы проходят проверку без изменения поведения.
13. **Регресс-тест:** случай `total_tiles_x16` должен дать REJECTED, `control` — LOADED.
14. **Приоритет:** P2. **Доказанность:** подтверждено санитайзером.
15. **Upstream:** да — OpenXcom и OXCE.
16. **Сырые результаты:** `evidence/B/runs/20261118_223943_17516/total_tiles_x16.*`.

## AUD05-002 — номер клетки из сейва не проверяется: запись за пределы массива клеток

1. **Где:** `src/Savegame/SavedBattleGame.cpp`, `SavedBattleGame::load`, строки 225–227.
2. **SHA:** `ffbec78ec`.
3. **Фрагмент:**
   ```cpp
   int index = unserializeInt(&ptr, serKey.index);
   assert(index >= 0 && index < _mapsize_x * _mapsize_z * _mapsize_y);
   _tiles[index].loadBinary(ptr, serKey);
   ```
4. **Первопричина:** единственная проверка — `assert`, а выпуск собирается с `-DNDEBUG`.
5. **Условия:** сейв боя с номером клетки вне `0 … ширина×длина×высота − 1`.
6. **Последствия:** `Tile::loadBinary` **пишет** около 20 байт по адресу `_tiles.data() + index × sizeof(Tile)` —
   управляемая содержимым файла запись в память. Для далёкого номера — падение; для близкого — тихая порча кучи.
   Это единственная находка этапа, где файл сейва управляет **записью**; сейвы игроки присылают друг другу и нам.
7. **Происхождение:** OpenXcom, перенесено в OXCE.
8. **Воспроизведение:** `… save_corrupt_battle_test.py run tile_index_out` (первый номер клетки заменён на `0x7fffffff`).
9. **Факт:** `A fatal error has occurred: Segmentation fault.` в `openxcom.log` сразу после команды загрузки; игра остаётся висеть на окне отчёта о падении. Отчёта ASan нет: исключение раньше перехватил собственный обработчик игры, поэтому стека с именами функций нет — место указано по коду.
10. **Ожидание:** окно «не удалось загрузить».
11. **Исправление:** заменить `assert` на проверку с `throw Exception`.
12. **Риск для механики:** нет.
13. **Регресс-тест:** случай `tile_index_out` → REJECTED.
14. **Приоритет:** P1 (запись в память по данным из файла). **Доказанность:** подтверждено воспроизведением (место — по исходному коду).
15. **Upstream:** да.
16. **Сырые результаты:** `evidence/B/runs/20261118_223943_17516/tile_index_out.*`.

## AUD05-003 — номер набора карты из сейва не проверяется

1. **Где:** `src/Savegame/SavedBattleGame.cpp`, `SavedBattleGame::loadMapResources`, строка 529.
2. **SHA:** `ffbec78ec`.
3. **Фрагмент:**
   ```cpp
   if (mdID != -1 && mdsID != -1)
       _tiles[i].setMapData(_mapDataSets[mdsID]->getObject(mdID), mdID, mdsID, tp);
   ```
4. **Первопричина:** `mdID` проверяет `MapDataSet::getObject` (бросает `Exception`), а `mdsID` идёт в `operator[]`
   без проверки. Отрицательные значения, кроме −1, тоже проходят.
5. **Условия:** сейв, где номер набора у клетки не меньше длины списка `mapdatasets` (ручная правка; сейв, в котором
   список наборов короче, чем был при записи).
6. **Последствия:** чтение указателя за концом вектора и вызов метода по нему — падение.
7. **Происхождение:** OpenXcom (`:370` в `4a4bae5fa`).
8. **Воспроизведение:** `… save_corrupt_battle_test.py run mapdataset_id_out`.
9. **Факт:** ASan `heap-buffer-overflow READ of size 8`, 272 байта за областью 240 байт (список из 30 наборов); стек `SavedBattleGame::loadMapResources (:529) ← LoadGameState::think (:191)`.
10. **Ожидание:** окно «не удалось загрузить».

1. **Где:** `src/Menu/LoadGameState.cpp`, `error`, строка 242 (`delete save`) → `SavedGame::~SavedGame` (`SavedGame.cpp:269`)
   → `SavedBattleGame::~SavedBattleGame` (`SavedBattleGame.cpp:101-104`) → `MapDataSet::unloadData` (`MapDataSet.cpp:268-280`).
2. **SHA:** `ffbec78ec`.
3. **Фрагмент:**
   ```cpp
   SavedBattleGame::~SavedBattleGame()
   {
       for (auto* mds : _mapDataSets)
           mds->unloadData();          // наборы принадлежат Mod и общие для всех боёв
   ```
4. **Первопричина:** наборы карты (`MapDataSet`) — общие объекты мода, а выгружает их деструктор **любого**
   `SavedBattleGame`, в списке которого они есть. Недогруженный сейв `s` успевает занести в свой список те же наборы
   (`load`, строки 186–191), что использует идущий бой. Когда загрузка отклоняется, `delete s` выгружает их, и клетки
   идущего боя остаются с указателями на удалённые `MapData`.
5. **Условия:** игрок **в бою** открывает загрузку и выбирает сейв боя, который ломается после чтения списка наборов
   (обрезанный файл, битый юнит или предмет, сейв другой версии мода) и у которого хотя бы один набор карты общий с
   идущим боем (`BLANKS` есть почти везде). Появляется окно «не удалось загрузить» — и игрок возвращается в свой бой.
6. **Последствия:** обращение к освобождённой памяти на первом же кадре анимации карты; в выпуске — падение или
   мусор вместо карты. Несохранённый ход потерян. Отказ, который выглядит безопасным, убивает идущую игру.
7. **Происхождение:** OpenXcom (`SavedBattleGame.cpp:78`, `LoadGameState.cpp:218` в `4a4bae5fa`).
8. **Воспроизведение:** `py -3.13 docs/QA/AUDIT05/evidence/B/save_corrupt_battle_test.py run truncated_half` —
   тест сначала сам грузит `control` (на стенде идёт бой), затем на том же стенде грузит обрезанный сейв и закрывает
   окно ошибки. В прогоне-доказательстве перед этим стоял ещё `selected_unit_text` (тоже отклонён, игра жива).
9. **Факт:** ASan `heap-use-after-free READ of size 8`, 0 байт внутри освобождённой области 192 байта.
   Обращение: `MapData::getDataset (MapData.cpp:52) ← Tile::updateSprite (Tile.cpp:774) ← Tile::animate (:727) ←
   Map::animate (Map.cpp:3065) ← BattlescapeState::animate (:2836) ← BattlescapeState::think (:1105)`.
   Освобождение: `MapDataSet::unloadData (MapDataSet.cpp:274) ← ~SavedBattleGame (:103) ← ~SavedGame (:269) ←
   LoadGameState::error (:242) ← LoadGameState::think (:216)`.
10. **Ожидание:** после окна ошибки идущий бой продолжается как ни в чём не бывало.
11. **Исправление (варианты):** (а) счётчик использований в `MapDataSet` (`loadData` / `unloadData` парами);
    (б) `SavedBattleGame` выгружает наборы, только если сам их загружал (флаг, выставляемый в `loadMapResources` и
    генераторе); (в) в `LoadGameState::error`, если идёт бой, после `delete save` заново вызвать
    `loadMapResources` для идущего боя. Вариант (б) самый узкий.
12. **Риск для механики:** нет. Проверить расход памяти: наборы не должны остаться загруженными после боя.
13. **Регресс-тест:** последовательность `control` → `truncated_half` → Enter: игра жива, отчётов ASan нет.
14. **Приоритет:** P1 — достижимо игроком без ручной правки файлов, портит идущую игру. **Доказанность:** подтверждено санитайзером.
15. **Upstream:** да — OpenXcom и OXCE; сильный кандидат на отчёт.
