## G1. Зависимости глубже включений (19.11.2026)

Считает `tools/arch_g.py` и `tools/arch_g_up.py` по описи этапа A (`inventory/includes.tsv`, 7 299 рёбер, 989 файлов).
Модуль — пара `X.h` + `X.cpp`. Таблицы: `inventory/arch_dirs.tsv`, `arch_upward.tsv`, `arch_scc.tsv`,
`arch_modules.tsv`. Это разбор включений, а не языка: зависимость через предварительное объявление без включения
сюда не попадает, то есть настоящая связность не меньше показанной.

### Слоёв по факту нет

Этап A записал «циклов включений не найдено». На уровне модулей это не так: **461 модуль из 524 входит в одну
группу взаимных зависимостей** (346 809 строк из 397 535, 87 %): Engine 79, Battlescape 74, Basescape 70, Mod 60,
Menu 48, Geoscape 48, Savegame 39, Ufopaedia 24, Interface 19. Других групп нет. Причина унаследована от OpenXcom:
`Game` знает `Mod`, `SavedGame` и экраны; `State` знает `Game`; правила знают сейв; сейв знает бой.

Узлы: `Mod` — 289 входящих и 104 исходящих связи, `Options` 269, `Game` 252, `Text` 227, `TextButton` 197,
`State` 183, `SavedGame` 173. Больше всего исходящих: `GeoscapeState` 120, `Mod` 104, `BattlescapeState` 87, `Map` 63.

Следствия, а не дефекты:
- правка заголовка узла пересобирает почти всё (это видно и по времени сборки);
- класс из группы нельзя собрать в тест без остальных — поэтому тесты уровня функции в `tests/` покрывают только
  листья, а остальное проверяется стендом на живой игре;
- расплетать группу — переписывать движок; в рамках проекта («механику не трогаем», минимальный диф) не предлагается.

### 2. Adlib — ограниченное чтение, без переписывания

Указатель чтения дорожки теперь идёт вместе с концом данных (`adl_gv_music_start/end`): каждое чтение команды —
через `ADL_READ` (за границей дорожка заканчивается), числа переменной длины — с проверкой конца, разделы заголовка —
через `ADL_ROOM`. Проверено по списку задания: границы дорожек и длины команд (выше); переходы и вложенные вызовы —
номер подпоследовательности сверяется с их числом; индексы — нота вне таблиц (108) и сэмпл вне числа сэмплов не
играются, хор только 1..16; завершение — метка `track_over`; бесконечное исполнение — бюджет команд без задержки
равен длине дорожки, не больше 16 перезапусков за тик; время жизни — буфер принадлежит `AdlibMusic` до его
деструктора, который сначала останавливает проигрывание. Полное переписывание не потребовалось.

`tests/adlib` (сам проигрыватель и синтезатор игры, без игры): звук 3000 тиков каждой из 22 дорожек `ADLIB.CAT` и
3 дорожек `AINTRO.CAT` оригинала старым и новым проигрывателем — хэши PCM совпали на всех 25; ни одна новая
проверка на них не срабатывает (сборка со счётчиками). 19 повреждённых дорожек: новый — без отчётов на всех,
старый — отчёты ASan/UBSan на 15. Случайные повреждения (4 зерна по 200 дорожек на каждый файл): новый чист,
старый — чтение за буфером. В X-Piratez музыка не Adlib — в игре путь не исполнялся.

### 6. Трассировка — `src/Engine/CrashTrace.cpp`, `tests/crashtrace`, `tools/crash_symbolize.py`

Что было (опытом, не чтением): на главном потоке старая трасса работала; авария в рабочем потоке и целочисленное
деление на ноль убивали процесс без записи (`signal()` действует на главный поток); обработчик звал `malloc`, журнал
и `SymInitialize`; у кадров не было смещений.

Что стало: фильтр необработанных исключений процесса (любой поток) пишет запись в журнал и в stderr одной `WriteFile`
из статического буфера: код, адрес обращения, поток, кадры `exe+0xRVA`. В фильтре нет кучи, замков, потоков вывода
и символизатора — только разворачиватель системы (`RtlLookupFunctionEntry`, `RtlVirtualUnwind`). Имена находит потом
`tools/crash_symbolize.py` по таблице экспорта того же exe. Обычное исключение: `Exception` запоминает до 20 адресов
места броска (`CaptureStackBackTrace`, 0,18 мкс на бросок с 4 кадрами), имена берутся только если оно стало роковым.
Новых зависимостей нет (`dbghelp` уже линковался).

`tests/crashtrace/run.py`: PASS — исключение с именами кадров; авария на главном и на втором потоке, деление на ноль,
переполнение стека: код выхода 1, одна запись в файле и в stderr, имя виноватой функции находится символизатором.
Авария внутри уведомления игрока: запись первой аварии цела, процесс завершает система своим кодом (не 1).
Не проверено: авария в самой игре (намеренно не устраивалась); 32 бита и не Windows — прежний путь.
