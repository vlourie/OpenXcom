## 4. Остатки рецензии HD

### 4.1. `HdUi::_smooth` (рецензент: 001) — воспроизведено

**Механизм.** В одном кэше `_smooth` под ключом «указатель поверхности» лежат записи двух разных видов:
«ответ, какая HD-картинка стоит за этой поверхностью» (`cache(surface, pixelHash, …, art, artX, artY)`) и «готовый
кадр картинки» (`prepared()` → `cache(art->baseSurface, …, frame)` с `art = nullptr`). Если на экран рисуется **сама
поверхность мода** (та же, что `art->baseSurface`), вторая запись затирает первую: в следующем кадре ответа «это
картинка» уже нет.

**Воспроизведение.** `evidence/HD/smooth_collision_test.py`, прогон `smooth_20261119_092817_16692`. Диагностическая
сборка из копии исходников HEAD во временной папке: верхний экран рисует поверхность мода `BIG_REALM_OF_WIZARDRY`
(у неё есть HD-картинка) через `Surface::hdMirror`, `HdUi::drawSurface` пишет в лог, какой дорогой она нарисована.

| Случай | Кадры 1…12 |
|---|---|
| окно 1920×1080 (k интерфейса 4), режим 2, сама поверхность мода | картинка, затем 11 раз **сглаженная классика** |
| то же, через копию поверхности (обычный путь игры) — контроль | картинка все 12 раз |
| то же, режим 1, сама поверхность | картинка, затем 11 раз сглаженная классика |
| окно 960×540 (k интерфейса 3), сама поверхность / копия | 1 + 11 / 12 картинок |
| окно 480×270 (k = 1) | путь не исполняется: HD-слоя интерфейса нет |

Масштаб интерфейса задаёт размер окна, а не `oxceHdScale` (он — масштаб мира); поэтому «k = 1» и «k = 4» проверены
окном. Оба режима HD, повторное использование одной поверхности (12 кадров подряд) — проверены. **Поздняя
регистрация** картинки и смена палитры отдельным случаем не проверялись.

**Достижимость в игре сегодня.** Живого вызова, где на экран уходит сама `baseSurface`, чтением не найдено:
экраны рисуют копии (`kept`, `back`, `alt`) и свои поверхности. То есть сейчас это мина под будущий код, а не
видимый дефект. Приоритет P3.

**Варианты исправления (не вносились, нужен выбор):**

- **А — раздельные кэши (полноценное).** Готовые кадры картинок — в свою карту со своим ключом
  (`art`, k, палитра) и своим вытеснением под общий бюджет памяти; `_smooth` остаётся только для ответов по
  поверхностям. Коллизия невозможна по построению. Объём: `HdUi.cpp/.h`, около 60–80 строк; проверка k = 1
  IDENTICAL и k = 4 по правилу 3, плюс этот тест → 12 картинок из 12.
- **Б — минимальное.** `prepared()` кладёт запись с тем же `art`, что и ответ (не `nullptr`). Три строки, но два
  вида записей по-прежнему делят ключ: ошибка такого же рода возможна при следующей правке.

Рекомендация — А.

### 4.2. `HdTurn`: 8-битные исходные спрайты (рецензент: 011)

`HdTurn.cpp`: ключ кэша — `src.getBuffer()`. Объект `HdTurn` создаётся в `Map.cpp:1888` только при повёрнутой камере
и удаляется вместе с `Map` (`Map.cpp:592`). Его источники — кадры частей клеток из наборов местности мода
(`Map.cpp:2097–2164`, `MapCell.cpp:179–180`, `HdTurnGroups.cpp:162`); наборы принадлежат моду и живут дольше `Map`.
По коду висячего указателя и устаревшего ключа нет. **Запуском не проверялось** (нужен бой с поворотом камеры под
ASan) — UNVERIFIED в части запуска.

### 4.3. `exitNow`: `probeLogFlush` без замка (рецензент: 010) — остаток AUD04-008

`CrossPlatform.cpp:1790–1805`: после ста неудачных `try_lock` `probeLogFlush()` вызывается без замка. Вызов
`exitNow` один — `Game.cpp:868`, под `AiProbe::fast()`, то есть только в сборке стенда ИИ; **в выпуске путь
недостижим**. Следом идёт `fflush(nullptr)`, так что безусловный сброс журнала избыточен. Предложение (после
согласования): звать `probeLogFlush()` только при взятом замке (`owns_lock()`). P4.

### 4.4. Три ошибки видеокарты — варианты восстановления

Сейчас (`HdGpuWorld.cpp:900, 1325`): счётчик ошибок только растёт, на третьей мир до конца процесса рисует
процессор. Политика **не менялась**. Варианты:

- **A — как есть.** Просто и безопасно; после трёх случайных сбоев за долгую игру видеокарта не вернётся до перезапуска.
- **B — прощение по времени.** Счётчик сбрасывается после N минут (или кадров) без ошибок. Случайные сбои не
  копятся; постоянный сбой всё равно отключает карту за три кадра подряд.
- **C — сброс по событию.** Счётчик сбрасывается при пересоздании контекста (смена разрешения или режима экрана) и
  в начале нового боя. Естественные точки, где причина сбоя могла исчезнуть.
- **D — вручную.** После отключения опция в меню HD (или её повторное включение) возвращает карту; игрок решает сам.

B и C сочетаются. Рекомендация — C + D: без таймеров, поведение объяснимо игроку.
