## 3. `fd85989c7`, `02a05ca68`: надёжность записи (`writeFile(..., durable)`)

(Часть `02a05ca68`, не пункт форума.)

* **Файл:строка (HEAD):** `src/Engine/CrossPlatform.cpp:1075` (`flushFileToDisk`), `:1102-1121` (`writeFile`), вызов
  `src/Savegame/SavedGame.cpp:1054`; поток записи через `.bak`: `src/Menu/SaveGameState.cpp:~205` (`save(backup)` -> `moveFile`).
* **Причина:** `SDL_RWclose` игнорировал ошибку отложенной записи; перед заменой прошлого сейва файл не сбрасывался на диск.
* **Что сделано:** ошибка `SDL_RWclose` = отказ записи; для сейва после закрытия файла `FlushFileBuffers` (Windows) / `fsync` (прочие);
  отказ сброса = исключение `Failed to save`.
* **Проверено как:** чтение кода. Сейв пишется в `<имя>.bak`, затем `moveFile` на настоящее имя, так что отказ сброса оставляет прежний сейв
  нетронутым (замена не выполнится) — поведение безопасное. Время сброса видно в столбце `flush` `bench.tsv` (около 2 мс на 1,6 МБ).
* **Классификация:** исправлено верно (устойчивость), побочное: строже, чем upstream.
* **Статус проверки:** чтение кода; замеры времени исполнены (`bench.tsv`). Отказ сброса не вызывался. **Тег/HEAD:** оба.
* **Риски:** на файловых системах, где `FlushFileBuffers`/`fsync` возвращает ошибку при целом файле (сетевая шара, облачная папка, Wine), сейв
  теперь не сохранится, хотя раньше сохранялся. На медленном носителе автосейв каждого хода ждёт сброса. Для пользовательской папки
  по умолчанию — не проявляется.
* **Нужен ли тест:** желательно: сохранение на носитель с ошибкой сброса (подмена `flushFileToDisk` в стенде) -> окно ошибки, прежний сейв цел.
