## 3. fa9deca80 — div/mod INT_MIN на -1 (B1), miniz без невыровненных чтений (C)

### 3a. Скрипты div/mod
- HEAD: `src/Engine/Script.cpp:127-137` (`divInt_h`, `modInt_h`), `:309-310` (IMPL). Upstream `Script.cpp:263-264`.

- Сделано: при `b == -1` div даёт `0u - (unsigned)a` (то есть `-a` по модулю 2^32, INT_MIN→INT_MIN), mod даёт 0. Остальные значения прежние. Это совпадает с математикой для `a % -1 == 0`, `a / -1 == -a`; для INT_MIN результат INT_MIN — то, что получил бы процессор, не падая.
- Вывод скриптов: для всех входов, где раньше не было падения, результат тот же (деление на любое b != -1 не менялось; для b == -1 значения `-a` и 0 — совпадают с `idiv`). Новое поведение появляется только на входе, где раньше игра падала.
- Остаточное в скриптах (не закрыто): `RetError` при нулевом делителе — прежнее; `mulDiv_h`/`mulAddMod_h` считают в int64 — переполнения нет (|a*b| <= 2^62).
- Доказательство: `evidence/F/divtrap.c` (падение), `evidence/F/script_arith.cpp`, `ROOT_CAUSES.md` строка 681; моя проверка выше (div/mod не входят в cmp.cpp, но формулы тривиальны). Классификация: исправлено верно. Статус: исполнено (evidence/F) + чтение. Тег/HEAD: да/да.
