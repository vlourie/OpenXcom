Hi Dioxine! I ran the whole Piratez ruleset through a checker that loads it the same way OXCE does (same file order, same merge rules). It found a few spots where the engine silently drops or ignores what you wrote. No crashes, just stuff that doesn't do what it looks like it does. Line numbers are from the current release.

1) Piratez_Factions.rul:9633, AUX_XARQUID_GRAPPLE: `damageAlter:` appears twice. OXCE takes the FIRST key, which is empty, so the whole block is ignored (RandomType, ToHealth 0.4, ToTime 1.5, etc.).
Wrong:
    damageAlter:
    damageAlter:
      RandomType: 2
      ...
Fix: delete the empty line:
    damageAlter:
      RandomType: 2
      ...

2) Other duplicate keys (the engine uses the first one, the second is dead):
- Piratez.rul, STR_STAFF_OF_BURNING_SOULS (items, ~58480 and ~58493): `power: 16` and then `power: 18`. The game uses 16. Which one did you mean? Delete the other.
- Piratez.rul:1281/1288, STR_EYE_OF_HORUS (facilities): `placeSound: 309` and then `placeSound: 305`. The game uses 309.
- Piratez_Resources.rul:13277, BIG_CAPTAIN_YESGRAY_NOGOLD:
    fileSingle: Resources/Pedia/Captain_GrayNoGold.png
    fileSingle: Resources/Pedia/UPed_Unavailable.gif   <- dead line, delete

3) `despawnEvenIfTargeted: true` is placed in alienDeployments, but only alienMissions read it, so there it does nothing. In 11 cases the matching mission doesn't have it, so the flag isn't active at all:
STR_LOC_THULE_BOSSBATTLE, NECROPOLIS, CITY_OF_THE_DEAD, CITY_OF_THE_DEAD_SCOUTING, EMANSION_MAG, FOUNTAIN_OF_YOUTH, FOUNTAIN_OF_YOUTH_G, GATE_OF_FEAR, DOOMED_CRYPT, EUROSYNDICATE_ELIMINATION, STYX_BLACK_TOWER_OUTSIDE
Wrong (Piratez_Factions.rul:61496):
  alienDeployments:
    - type: STR_LOC_THULE_BOSSBATTLE
      duration: [24, 24]
      despawnEvenIfTargeted: true
Fix: move it to the mission with the same name (Factions:34416):
  alienMissions:
    - type: STR_LOC_THULE_BOSSBATTLE
      objective: 3
      despawnEvenIfTargeted: true
The other 5 (CATACOMBS_BUTCHER, CATACOMBS_BUTCHER_ENTRY, HALLS_OF_FEAR, NIGHTOSHPHERE_DELOREAN, NIGHTOSHPHERE_HARVEST) already have it on the mission, so the copy in the deployment is just dead weight.

4) Piratez_Events.rul:11482 and 11492: `interruptResearch` is in eventScripts (STR_NINJAS_ESCALATION, STR_NINJAS_AT_BAY), but eventScripts don't read it. Only events and alienMissions do.
Wrong:
  eventScripts:
    - type: STR_NINJAS_AT_BAY
      ...
      interruptResearch: STR_NINJA_ESCALATION_6
Fix: move it into the event itself:
  events:
    - name: STR_NINJAS_AT_BAY
      interruptResearch: STR_NINJA_ESCALATION_6
(same for STR_NINJAS_ESCALATION / STR_NINJA_ESCALATION_4)

5) Piratez.rul:79547, craft STR_CAVES_DROP_ENTRY: `revealedFloors: [3]` sits on the craft, and crafts don't read it. It belongs on the map blocks:
Wrong:
    refuelRate: 9999
    revealedFloors: [3]
    battlescapeTerrainData:
Fix:
    battlescapeTerrainData:
      mapBlocks:
        - name: ...
          revealedFloors: [3]

6) Broken names in startingConditions (Piratez_Globals.rul), allowedArmors. These are item names, not armor names, so the entry matches nothing:

- STR_STARCON_GAL_PARTY, allowedCraft (line 4975): `- STR_DELIVERATOR`. No craft has that name. Leftover or renamed?
