## 1. Как наш слой находит контент

- Номер тайла базы: `hdTileIndex = (spriteEnabled ? spriteFacility : spriteShape) + n`. Файл `<N>.png`.
  Сначала ищется номер g, затем g − смещение мастера.
- Постройка рисуется в HD, только если картинка есть у всех её тайлов (isHdFacility). Иначе вся постройка
  остаётся классической. Сцены, толпа и огни рисуются только на HD-постройках. Роли для живой базы берутся
  из рулсета (HdBaseLife.h).
- Огни кораблей в ангаре: номер равен skinSprite + 33, файл `<N>.lights.txt` (HdCraftLights.h).
- Интерфейс ищет по имени картинки, размеру и содержимому (HdUiArt.h). Поэтому у интерфейса подмены нет,
  а у баз есть.
- Голоса задаются чистым рулсетом (voiceSets, soldiers, units) в `hd_voices_*.rul`.
- Пак Piratez `hd\BASEBITS.PCK`:
  - 4888 файлов, 24,3 МБ;
  - 228 тайлов (png + anim + scene), 70 файлов `.lights.txt`;
  - покрыты все 115 построек Piratez.

## 5. Предложения (решает Vitali)

1. **Не снимать `master: piratez` с `hd`**, пока HdBase не проверяет содержимое кадра.
2. **Страховка в HdBase.** Записывать хэш классического кадра в `<N>.anim.txt` и сверять его при первой отрисовке,
   как в HdUiArt. Это правка движка, k = 1 она не задевает; пак Piratez придётся один раз пересчитать.
3. **Отдельный мод для каждой игры:** `hd_<игра>` с master нужной игры и нумерацией её мастера. Движок это уже
   поддерживает.
4. **Порядок по цене:** Mars-com, XCHR, XCF, потом 40k и ROSIGMA, TWoTS — когда будут данные TFTD.
5. **Голоса:** моды `hd_voices_<игра>_<язык>` на готовом конвейере. Сначала игры, где бойцы немые.

## Границы

- Рулсеты слиты упрощённо: побеждает последний тип, `delete` убирает. Патчи `!add` и mcdPatches не учитывались.
- TFTD не установлен, поэтому выводы по пикселям TWoTS ненадёжны.
- Стиль построек оценивался по именам и по несовпадению кадров. Сами картинки глазами не смотрели.
