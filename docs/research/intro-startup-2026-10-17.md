# Интро при запуске через лаунчер — разведка 2026-10-17

## Вывод

Общая причина пропуска интро находится в движке: `src/Menu/StartState.cpp:201` считает первый старт только по изменению master-мода. Лаунчер заранее передаёт `-master piratez`; master уже равен piratez до создания StartState, поэтому после загрузки он не меняется и интро не ставится в стек. Это воспроизводится логикой независимо от musicVolume. Нулевая музыка объясняет отсутствие озвучки уже запущенного интро, но не отсутствие самого интро у пользователей лаунчера.

Минимальное исправление условия:

```cpp
bool intro = (!Options::reload || _oldMaster != Options::getActiveMaster() || playIntroAfterReload) && Options::playIntro;
```

`Options::reload` уже надёжно различает запуск процесса и перезагрузку ресурсов. Дополнительное поле или новый сохраняемый параметр не нужны. Рулсеты, озвучку, громкость и порядок вопросов менять не требуется.

## Доказательство по цепочке вызовов

1. `portal/src/Xp.Launcher.Core/Builds.cs:322–330`, LaunchArgs: если EngineMaster указан, в команду добавляются `-master` и его значение. `portal/src/Xp.Launcher/MainWindow.cs:1130–1132` передаёт эти аргументы GameProcess.Start; `portal/src/Xp.Launcher.Core/GameProcess.cs:39` заполняет ProcessStartInfo.ArgumentList.
2. `src/main.cpp:120–129`: Options::init выполняется до new Game и new StartState.
3. `src/Engine/Options.cpp:904`, loadArgs: ветка `master` на строках 775–777 сразу присваивает `_masterMod` из аргумента. Считывание options.cfg не обнуляет эту переменную.
4. `src/Engine/Game.cpp:79` явно устанавливает `Options::reload = false` в конструкторе игры.
5. `src/Menu/StartState.cpp:71` запоминает `_oldMaster = Options::getActiveMaster()`, который уже равен piratez.
6. `src/Menu/StartState.cpp:351–352`: load вызывает Options::updateMods; `src/Engine/Options.cpp:1127` вызывает refreshMods.
7. `src/Engine/Options.cpp:954–956` обнуляет `_masterMod` только при reload. На обычном старте `_masterMod` остаётся piratez; ветка 1045–1047 выбирает этот мастер, ветка 1115 сохраняет то же значение.
8. `src/Menu/StartState.cpp:201` получает false для сравнения master и false для playIntroAfterReload (начальное значение на строке 50); при любом playIntro интро не показывается.

При старте без -master глобальная строка сначала пустая: обычное обнаружение master при updateMods меняет её, поэтому старое условие случайно работало. Зависимость от аргумента запуска — ошибка определения первого старта.

## Почему сохраняются перезагрузки и вопросы

- `StartState.cpp:224–226` сбрасывает Options::reload только после вычисления intro и постановки следующих экранов. Новая проверка читает актуальное значение.
- `OptionsBaseState.cpp:228–230` отправляет в StartState при reload из меню. ModListState выставляет reload при изменении набора модов, OptionsAudioState — при смене формата звука, OptionsHdState — при смене графики, OptionsAdvancedState — при выключении lazy loading. При неизменном master новая ветка !reload для них ложна: интро не повторяется.
- При смене master сравнение _oldMaster с новым master продолжает разрешать интро, как раньше. В refreshMods reload обнуляет _masterMod, после чего выбирается активный master из mods.
- `AdultChoiceState.cpp:142–146` при смене версии арта уничтожает стек, устанавливает reload и передаёт _introPending в playIntroAfterReload. Новое условие сохраняет эту ветку; StartState.cpp:202 потребляет флаг один раз.
- StartState.cpp:203–221 сначала кладёт CutsceneState, затем экран языка, либо предупреждение, либо выбор арта. LanguageChoiceState.cpp:135–142 и GentleChoiceState.cpp:110–113 передают introPending дальше без запуска повторного интро.
- `CutsceneState.cpp:55–65` выбирает языковой вариант в init, то есть уже после выбора языка. Этот порядок менять нельзя.
- `AdultChoiceState.cpp:60–62` сохраняет проверку наличия строк (R-036); добавление интро не должно её обходить.

| Reload выбора арта с ожидающим интро | 1 | 0 | 1 | 1 | Интро один раз |

| Любой reload с playIntro=false | 1 | любой | любой | 0 | Интро нет |

Проверка должна исполнять само изменяемое C++-условие или небольшой реальный код выбора, а не независимо переписанную формулу Python: иначе откат StartState.cpp не сломает тест. Контрольный опыт: прежнее условие проваливает первый и третий сценарии. Для интеграционной приёмки — отдельный чистый -cfg и обычный профиль, вопросы до интро; язык интро соответствует выбранному языку; отсутствие `not found in` в логе. До выпуска подтвердить путь свежего exe и включение его в релиз (R-087); после коммита проверить `git show --stat` и `git status --short src` (R-108).
