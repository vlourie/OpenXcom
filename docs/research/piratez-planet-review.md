# Разбор Piratez_Planet.rul (X-Piratez)

Файл: `Пиратки/Dioxine_XPiratez/user/mods/Piratez/Ruleset/Piratez_Planet.rul`, 30 997 строк.
Файл прочитан скриптами, а не глазами. Рулсеты Пираток слиты так же, как их сливает движок (`tools/rul_map.py`, итог в `.index/mod/Piratez/rul/`). Карты, маршруты и наборы тайлов читались с диска в том порядке слоёв, в каком их ищет игра: `UFO` → `standard/xcom1` → `user/mods/Piratez`, имя без учёта регистра.
Проверки повторяют то, что делает движок:
- `MapBlock::load`, `RuleTerrain::getMapData` (`src/Mod/MapBlock.cpp`, `src/Mod/RuleTerrain.cpp`);
- `BattlescapeGenerator::loadMAP` / `loadRMP` / `addLine` / `fillArea` (`src/Battlescape/BattlescapeGenerator.cpp:2082`, `:2356`, `:4355`, `:3170`);
- `MapScript::getNextBlock` (`src/Mod/MapScript.cpp`);
- `RuleRegion::insideRegion`, `RuleCountry`, `Texture::getRandomTerrain` (`src/Mod/`);
- выбор места миссии в `AlienMission::spawnUfo` (около 195) и посадка (около 895), `spawnMissionSite` (`src/Savegame/AlienMission.cpp`).

**Файл не правился**: установка Пираток только читается. Все исправления ниже — предложения автору.

Как движок это читает — без этого главную находку не понять:
- Номер тайла в MAP — это номер записи MCD **сквозь все** `mapDataSets` террейна по порядку. Номер за концом суммы движок **молча** превращает в BLANKS 0, то есть в пустую клетку (`RuleTerrain::getMapData`). Ни ошибки, ни строки в логе.
- Остальные ошибки карт громкие: размер MAP не совпал с рулсетом, блок не кратен 10, предмет за блоком, труп на карте — исключение при загрузке боя. Узел RMP за блоком отбрасывается со строкой в логе.
- `addLine` без блока 10×10 нужной группы (2, 3, 4) и `fillArea`, которому нечем заполнить, роняют генерацию («Map failed to fully generate»).

## Косяки

### 1. EMANSION_MAG: не хватает набора SPACEVOID — «пустота» особняка становится пустой клеткой

- Террейн: `Piratez_Planet.rul:16287`. Им играется миссия STR_LOC_EMANSION_MAG (`Piratez_Factions.rul:36025`, деплоймент `:85243`), мапскрипт `EMANSION_MAG` (`Piratez_Mapscripts.rul:2866`).
- `mapDataSets`: BLANKS, COMMERCE_MAG, XB3BITZ1_MAG, MANSIONFURNITURE_MAG, URBITS, MANSIONGARDEN_MAG, MANSIONFLOOR_MAG, MANSIONBITS, XCOMEXIT — вместе **250 записей MCD, номера 0–249**.
- 21 блок ставит пол с номерами **250** (уровень 0) и **251** (уровень 1): EMANS00B (по 154 клетки каждого), EMANS06_SPAWN1, EMANS_VOID00, EMANS_VOID20, EMANS_VOID_WE00–07, EMANS_VOID_NS00–07, EMANS_VOID_XX00.
- Номера 250 и 251 ровно ложатся на `SPACEVOID.mcd`: 2 записи без кадров и без LOFT, `TU_Walk 255`, броня 255 — невидимый непроходимый пол «пустоты». Тот же набор последним стоит в ORBIT_S1B (`:29948`).
- Без него движок ставит на эти клетки BLANKS 0 — пустую клетку. EMANS_VOID_WE/NS/XX — блоки групп линий, мапскрипт кладёт их `addLine direction: both`, то есть пустота режет **каждую** карту миссии крестом.
- Что видит игрок, по коду: на уровне 0 вместо непроходимой пустоты — проходимая чёрная земля, на уровне 1 — дыра без пола. **В бою не проверено.**
- Исправление: дописать `- SPACEVOID` **в конец** `mapDataSets` EMANSION_MAG (в конец, чтобы номера 250/251 попали на него).
- У обычного EMANSION (`:15335`) 9 общих с ним блоков, но номеров больше 249 в них нет — там всё в порядке.

## Чего НЕ выяснил

- Ничего не проверено в бою. Что именно видно на месте пустоты EMANSION_MAG (проходимая земля или дыра), надо смотреть в игре: миссия STR_LOC_EMANSION_MAG, дамп Ctrl+F8.
- Команды мапскриптов с `terrain: globeTerrain` / `baseTerrain` проверены только на то, что группы есть у **своего** террейна: какой террейн придёт с глобуса, зависит от точки.
- Мапскрипты не прогонялись симуляцией целиком: проверено, что каждая команда найдёт хоть один блок, но не то, что `fillArea` при любом раскладе заполнит карту до конца.
- Файлы русского патча сверены только по размеру и номерам тайлов, не по содержанию (см. заметку выше).
