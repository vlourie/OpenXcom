# OXCE 8.7.1: что изменилось и чем это грозит нам

Проверено 2026-09-20 на пробном слиянии `upstream/oxce-plus` (441cae1b0, 19.09.2026)
в нашу ветку `hd-render` (833caf8d5). Проба собиралась и запускалась в отдельном
рабочем дереве, репозиторий не трогали.

## Объём обновления

Десять коммитов, 37 файлов, +298/-232. Ни одного файла графического слоя:
`src/Engine/Hd*`, `src/Interface/*`, палитры и блиты не затронуты вовсе.
Требование «k = 1 даёт IDENTICAL» обновление затронуть не может.

| Коммит | Суть |
|---|---|
| 441cae1b0 | версия 8.7.1 |
| 6ef16e182 | перевод OXCE (в том числе `bin/common/Language/OXCE/pl.yml`) |
| 3e35368af | проверка бонусов бойца при загрузке рулсетов |
| ecd85c6c9, 27af01897, 035fa6e71 | проверка триггеров исследований, три части |
| d30feb54f, 7866e89a8 | убран устаревший `isResearched(std::string)` |
| f1fe1bfba | чистка |
| 0e07b06fd | бросок больше не упирается в `maxRange` оружия |

Единственная правка, которую видно в игре, — последняя: `BattlescapeGame::primaryAction`
перестал отвечать «вне дальности» на **бросок** (`BA_THROW`). Остальное — перевод имён
в указатели на правила и проверка этих имён при загрузке.

## Слияние с нашей веткой

Пробное слияние: конфликт **один** — `src/version.h`, строка `OPENXCOM_VERSION_GIT`
(наша подпись против их даты). Десять файлов правились с обеих сторон и слились сами:
`Mod.cpp/.h`, `SavedGame.cpp`, `Soldier.cpp`, `BattlescapeGame.cpp`, `GeoscapeState.cpp`,
`PurchaseState.cpp`, `SoldierTransformationState.cpp`, `TechTreeViewerState.cpp`.

Сборка слитого дерева: 428 целей, **0 ошибок**, новых предупреждений в наших файлах нет.
То есть удалённый `isResearched(std::string)` в нашем коде нигде не вызывается.

## Чем это грозит: X-Piratez перестаёт загружаться

Главное. С 8.7.1 имена исследований в `requires:` проверяются при загрузке, и ссылка
на несуществующую тему — **фатальная ошибка**, а не молчание:

```
[ERROR] During linking rulesets of crafts:
Error processing 'STR_RED_BARON' in crafts: Research STR_RED_BARON not found
```

Игра остаётся на экране загрузки. Проверено на установке Пираток (X-Piratez v.o1.1.1,
`user/mods` как на рабочей машине, мастер `piratez`).

Чтобы узнать не первую дыру, а все, проверка была временно ослаблена (запись в лог
вместо исключения). Тогда мод догрузился до главного меню, а в логе оказалось ровно
**три** битые ссылки — все в самих Пиратках, все на несуществующие темы исследований:

| Ссылка | Где |
|---|---|
| `STR_RED_BARON` | `Piratez.rul:77638`, раздел `crafts`, поле `requires` |
| `STR_OFFERING_TO_PURPLE_BLOOM_CPAL` | `Piratez.rul:236622`, статья ХабароПедии |
| `STR_LIVING_QUARTERS_ADVANCED_LARGE_DAMAGED` | `Piratez.rul:222909`, статья ХабароПедии |

Это давние опечатки мода: темы не существует, значит условие не выполнялось и раньше —
корабль не покупался, статьи не открывались. 8.7.0 это проглатывал, 8.7.1 — нет.

Ванильный UFO на том же движке грузится начисто: ни одной битой ссылки, ни одной ошибки.

## Что делать

1. **Само слияние безопасно** — конфликт один, сборка чистая, графики не касается.
2. **Обновлять игру, в которую играешь, пока нельзя**: без правки мода 8.7.1 её не запустит.
   Ждём обновления X-Piratez от Dioxine либо несём в форке свою заплатку.
3. Заплатка, если ждать не хочется: несуществующую тему не считать ошибкой, а привязывать
   к скрытой теме, которую невозможно исследовать, и писать строку в лог. Тогда поведение
   останется ровно таким же, как в 8.7.0 (условие никогда не выполняется), а список дыр
   будет виден. Просто выбрасывать ссылку нельзя: условие исчезнет, и корабль станет
   доступен — это уже правка механики.
4. При слиянии затрагивается `bin/common/Language/OXCE/pl.yml` — значит три шага святого
   правила (R-003): предупредить, перенести в установку Пираток, сказать про вторую машину.

## Как это проверялось

```
git fetch upstream                      # ветка разработки OXCE - oxce-plus, не master
git worktree add <scratch>/try871 HEAD
git merge upstream/oxce-plus            # конфликт только в version.h
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release .. && ninja
openxcom.exe -data <Пиратки> -user <scratch>/user871 -master piratez   # SDL_VIDEODRIVER=dummy
```

Мод в пробной папке подключён ссылками на установку Пираток, сама установка не менялась.
Ссылки удобнее делать не через `mklink` (на именах без пробелов cmd отвечает
«Invalid switch»), а через `New-Item -ItemType Junction`.
