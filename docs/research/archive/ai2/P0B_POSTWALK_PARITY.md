# P0-B. PLAYER-BOT POST-WALK PARITY

Фаза 0 AI 2.0 — сделать стенд честным. Категория: **A. HARNESS BUG**.
Стенд ведёт сторону игрока через AIModule, а конец ходьбы исполняет по правилам живого игрока.
OXCE 8.7.1 здесь ни при чём. Основа — P0-A (`OXCE_AI_PANIC_TURN_FIX=1`, база k76t).

## 1. Штатный поток (OXCE 8.7.1)

`UnitWalkBState::postPathProcedures()` (`UnitWalkBState.cpp:478`) вызывается в двух местах:
- путь пройден до конца (`:416`, следующего шага нет);
- юнит стоит, а на остановке замечен новый враг (`:276-280`). Перед вызовом `setHiding(false)`.

Остановки посреди пути `postPathProcedures` не зовут ни у одной стороны: они идут через `cancelCurentMove` (`abortPath` и `popState`). Это:
- «замечен» после шага (`:242`);
- реакция (`:250`);
- «замечен при повороте» (`:444`, там тоже `setHiding(false)`);
- резерв ОВ и прочие обрывы (`:315-383`).

Тело `postPathProcedures`:

| шаг | условие | что делает |
|---|---|---|
| `_action.clearTU()` | всегда | |
| ветка AI | `getFaction() != FACTION_PLAYER` (`:481`) | все шаги ниже |
| finalAction | `_action.finalAction` | `dontReselect()` — юнит больше не выбирается в этом ходу |
| рывок | `getCharging() != 0` | направление на цель; если `validMeleeRange` — `BattleAction BA_HIT` (оружие `getUtilityWeapon(BT_MELEE)`), `setCharging(0)`, `statePushBack(MeleeAttackBState)` |
| укрытие | иначе, если `isHiding()` | направление = текущее + 4, `setHiding(false)`, `dontReselect()` |
| поворот | направление не −1 | `lookAt` и `turn()` до конца, FOV на каждом шаге поворота |
| ветка игрока | иначе, если флаг паники ложен | `clearTimeUnits()` |
| конец | всегда | свет, `calculateFOV`, `popState()` (если не падает) |

Где AIModule задаёт эти поля:
- `finalAction` — отход (`AIModule.cpp:759`) и засада (`:830`);
- `setHiding(true)` — отход (`:765`);
- `setCharging` — ближний бой (`:3316`, `:3363`);
- `finalFacing` — `:264`, `:801`, `:828`, `:1786`, `:3120`, `:3825`.

Где AIModule снимает эти поля:
- `handleAI` гасит `finalAction` у ходьб к предмету и к оружию бота (`BattlescapeGame.cpp:2797`, `:3171`);
- на первом действии юнита за ход (`_AIActionCounter == 1`) зовёт `setHiding(false)`.

Возврат в `AIModule::think()` для обоих случаев один:
- `popState` переходит к следующему состоянию (удар, если поставлен);
- следующий `handleAI` видит `!reselectAllowed()` и переходит к следующему юниту (`BattlescapeGame.cpp:386`).

Остальные проверки стороны в `UnitWalkBState` к решению не относятся и не менялись:
- камера (`:192`);
- `setVisible(false)` у не-игрока (`:221`);
- `cancel()` обрывает путь только на ходу игрока (`:471`);
- скорость ходьбы.

## 2. Где бот стенда расходится

Ветка AI закрыта условием `getFaction() != FACTION_PLAYER`. Юниты бота — фракция игрока. Поэтому всё, что AIModule бота решил на конец ходьбы, молча отбрасывается:
- `finalAction` не делает юнит невыбираемым. После отхода `handleAI` снова зовёт `think()`, и юнит действует дальше, пока не кончатся ОВ или счётчик действий;
- `finalFacing` не применяется — юнит стоит, как пришёл;
- рывок, кончившийся в пределах удара, не бьёт. `getCharging()` остаётся выставленным;
- укрытие не разворачивает юнит спиной к угрозе. `isHiding()` остаётся true до первого действия следующего хода.

После P0-A ветка игрока для бота почти пуста: флаг паники true, `clearTimeUnits()` не срабатывает.

Рядом есть ещё одно место, но в P0-B не тронуто: в `popState` (`BattlescapeGame.cpp:1385-1440`) сброс счётчика действий AI идёт только у не-игрока. Это P0-C.

`MeleeAttackBState::init` (`:129`) у юнита AI-стороны берёт цель `ai->getTarget()`, у бота — юнита на клетке цели. Для рывка это одно и то же: цель = позиция `getCharging()`.

## 3. Минимальная правка

Флаг стенда `OXCE_AI_POSTWALK_FIX` (по умолчанию 0), сборка build-ai75:

```cpp
const bool aiBranch = _unit->getFaction() != FACTION_PLAYER
	|| AiProbe::postWalkAi(_parent->getSave(), _unit, _parent->getPanicHandled());
...
if (aiBranch)
{ ...тело ветки AI без изменений... }
else if (!_parent->getPanicHandled())
{ _unit->clearTimeUnits(); }
```

`postWalkAi` = флаг включён И `botTurn(save)` (`OXCE_AI_BOT`, сторона игрока) И юнит фракции игрока И флаг паники true.
- Живой игрок не попадает в ветку AI никогда: без `OXCE_AI_BOT` `botTurn` ложен, в сборке без `OXCE_AI_DEV` функция — заглушка `false`.
- Ходьба паникующего бойца (флаг паники ложен) остаётся в ветке игрока с `clearTimeUnits()`, как у человека и как в P0-A.
- Вложенные условия ветки AI не тронуты: порядок рывок → укрытие → `finalFacing`, проверка `validMeleeRange`, поворот до конца.

Счётчики — `AiProbe::postWalkBegin/End` вокруг ветки и `postWalkMelee` в `MeleeAttackBState::init` после `spendTU`. Они только читают, RNG и состояние не трогают:
- строка `[AIPOSTWALK]` на каждую ходьбу с запросом;
- итог `[AIPOSTWALK] result` по бою.

| счётчик | запрошено | исполнено |
|---|---|---|
| fa | `finalAction` решения | юнит стал невыбираемым |
| turn | нужное направление не −1 и не текущее (включая укрытие и рывок) | направление после = нужному |
| melee | рывок кончился в пределах удара | `push` — удар поставлен, `begun` — удар потратил ОВ |
| hide | укрытие без рывка | `isHiding()` снят и юнит развернулся на +4 |

## 4. Результаты прицельных боёв

Сборка build-ai75 (exe sha256 `43176d00…`), данные `4feca4ac…`, окружение V4 плюс `OXCE_AI_PANIC_TURN_FIX=1`.
15 боёв из когорты k76t, каждый в двух плечах (`OXCE_AI_POSTWALK_FIX` 0 и 1). Чётные шли на рабочей машине, нечётные на сервере.

Как отбирали: по источникам решений бота в k76t (`escape`, `melee`, `patrol`, `firepoint`; засады у бота нет). Состав:
- 7 боёв с отходом;
- 4 с рывком;
- 2 коротких;
- 2 тихих, в том числе отрицательный контроль.

Разбор — `pw_ana.py` (блокнот сессии). Сравниваются строки AIREC, AIEXEC, AIAFTER, AIMEDI и AISTUNRES без поля cfg.

### 4.6. Замечено, но не тронуто

- **carefulGuard после разворота конца ходьбы.** Слой стенда `OXCE_AI_CAREFUL` (`BattlescapeGame::carefulGuard`) раз в ход поворачивает закончившего юнита к ближайшему видимому врагу. В ON он перекрыл исполненный разворот:
  - укрытие — 706 из 1003;
  - `finalFacing` — 42 из 883;
  - рывок — 58 из 288 (`pw_guard.py`).

  У штатного AI-юнита такого слоя нет. Это отдельный слой стенда, а не post-walk. Решение — за специалистом: оставить как поведение бота или выключать после укрытия.
- Сброс счётчика действий AI в `popState` только у не-игрока — P0-C.
- 110 цепочек ответного ближнего боя не исследовались. A*, отход, `_knownEnemies`, гранаты, угроза ближнего боя, отряд — не тронуты.
