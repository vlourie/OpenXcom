[b]3. Left-hand shield skips the right-hand shield[/b] (line 4598)

The fix splits YSCRIPT_ENERGY_SHIELDS_HIT_ITEM into two scripts: one for the left hand, one for the right. Now, when the left shield lets a damage type through ("return power part side;"), only the left-hand script ends, and the right-hand one still runs.
Nothing inside the left or right block changes. You only replace one comment line, the one just before "unit.getRightHandWeapon shieldItem;".

Find (it's in the file only once):
[code]          # Now do it for a right hand shield[/code]
Replace with:
[code]          return power part side;

      - new: YSCRIPT_ENERGY_SHIELDS_HIT_ITEM_RIGHT
        offset: 1.5
        code: |
          var ptre BattleItem shieldItem;
          var ptr RuleItem shieldRule;
          var int shieldCapacity;
          var int shieldNeedsPriming;
          var int shieldTimer;
          var int shieldType;
          var int shieldResistCoeff;
          var int shieldHp;
          var int temp;

          # Now do it for a right hand shield[/code]

Why this works:
- Several hitUnit scripts run one after another, and each one gets the power left over by the previous one. So the left shield reduces the hit first, then the right shield gets what's left, exactly as before.
- Offset 1.5 puts the new script between the item shields (offset 1) and the armor shields (offset 2). The engine accepts fractional offsets; it multiplies them by 100.
- The "- new:" line must line up with "- new: YSCRIPT_ENERGY_SHIELDS_HIT_ITEM" above it (6 spaces). "offset:" and "code:" get 8 spaces, and the code gets 10 spaces.

[b]8. Cydonia remote control: the overcharge shield penalty wears off[/b] (line 3507)

Overcharge (YSCRIPT_CYDONIA_REMOTE_CONTROL) drops the turret's shield to 750 / 6 = 125. But YSCRIPT_ENERGY_SHIELDS_SET_ARMOR regenerates it by 75 per turn, up to the armor's full 750. After a few turns an overcharged turret is back at full shields and still keeps its tripled TU and reactions.
YSCRIPT_DEPOWERED_SHIELDS already holds shields at 0 while a turret is powered off (status 1). The fix makes the same script also keep them at no more than 125 while the turret is overcharged (status 3). It runs every turn after the regeneration (offset 22 vs 2), so the shield still regenerates, just never above 125.

Find (in YSCRIPT_DEPOWERED_SHIELDS, only once in the file):
[code]          if eq powerStatus 1;
            unit.setTag Tag.UNIT_ENERGY_SHIELD_HP 0;
          end;
          return;[/code]
Replace with:
[code]          if eq powerStatus 1;
            unit.setTag Tag.UNIT_ENERGY_SHIELD_HP 0;
          end;

          # Overcharged (status 3): shields stay capped at 125 = 750 / 6,
          # the value YSCRIPT_CYDONIA_REMOTE_CONTROL sets on overcharge
          if eq powerStatus 3;
            var int shieldHp;
            unit.getTag shieldHp Tag.UNIT_ENERGY_SHIELD_HP;
            limit_upper shieldHp 125;
            unit.setTag Tag.UNIT_ENERGY_SHIELD_HP shieldHp;
          end;
          return;[/code]

The two "#" comment lines need the same 10 spaces as "if". If a comment line starts further left than the code, it ends the "code: |" block: the game then fails to load Yankes_Scripts.rul ("Rapidyaml ERROR: parse error") and disables X-Piratez completely. If in doubt, just delete the comment lines.

If you change the 750 in YSCRIPT_CYDONIA_REMOTE_CONTROL ("var int defaultShields 750;"), change the 125 here to match. If instead the penalty is [i]meant[/i] to wear off, just skip this one.
