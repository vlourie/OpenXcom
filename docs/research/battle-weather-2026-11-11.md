# Погода в бою: что можно сделать и где

Разбор 2026-11-11. Четыре разведчика (Sonnet, только чтение): движок, карты Пираток, видимость и механика,
приёмы других игр. Ничего не правилось. Ключевые места кода сверены грепом.

## Главное

- **Погода делается только картинкой и звуком** — в HD-слое (режимы 1/2), под опцией. Тогда механика,
  сейвы, ИИ и `k = 1` IDENTICAL не задеты.
- **Тип погоды выбирается по карте без записи в сейв**: в сейве уже есть `enviroEffectsType`,
  `flattenedMapTerrainNames` (имя terrain на каждый блок 10×10), `depth`, `globalshade`, `missionType`
  (`SavedBattleGame.cpp:157-177`). Из них биом и сид погоды восстанавливаются детерминированно после загрузки.
- **«Меньше видно» — пелена по расстоянию от своих солдат** (Vitali 11.11, §3а): механика видимости не меняется,
  замеченный враг под пеленой остаётся силуэтом.

## 1. Где встраивать (движок)

Проход: `Map::draw` (Map.cpp:1353) → `drawTerrain` (:5118) → `Canvas32::flush` полосами через `HdWorkers`
(HdCanvas.cpp:1525-1547). Попиксельная работа — только новой командой холста, не циклом в кадре.

| Слой | Куда | Образец |
|---|---|---|
| налёт на полу (мокро, лужи, снег, песок) | цикл тайлов, сразу после следов `hdSteps` (Map.cpp:~5671): после пола и AO, до стен и юнитов | `hdSteps`, AO пола `hdFloorAo` (:5635) |
| частицы на экран (капли, снег, песок, листья) | конец `drawTerrain`, после вспышек `HdFx::running` (:6986-7000), до `unlock` (:7002); HUD рисуется позже | `HdSmoke::puffs`, `HdFire::tongues` — чистая функция (x, y, z, время) без RNG; `VAPOR_SOFT` для снежинок |
| перекати-поле, брызги у земли | тайловая стадия (сортировка по глубине) | спрайт-клип по тайлам пола |
| общий тон кадра (пасмурно, мгла, охра бури, молния) | новая команда `Cmd::TONE` по образцу `FLASH` (HdCanvas.h:320, `doFlash`) | GPU-путь `HdGpuCanvas` знает только свои команды: либо ветка в шейдере, либо откат на CPU |
| блеск мокрого пола | тон тайла в `hdTintOf` / `updateHdLight` (Map.cpp:1714/1757) | освещение 9 узлов `HdLight` |

Условия рисования:
- **Крыша**: готового API нет. Маска «над (x, y, z) есть пол или объект выше» по образцу
  `TileEngine::calculateSunShading` (TileEngine.cpp:941-960), кэш с пересчётом при разрушении (TileEngine.cpp:3419,
  подпись как `hiddenSignature`). Под крышей нет ни капель, ни налёта.
- Налёт — только на `isDiscovered(O_FLOOR)`, `!hasNoFloor`; погоды нет при `getDepth() > 0`, `hdVacuum()`, `hdOrbitalMap`.
- Уровни: цикл уже режет по `camera->getViewLevel()` (Map.cpp:5383-5391); экранные частицы маскировать крышами видимой зоны.
- **Время**: `SDL_GetTicks()`, как у `HdFx`; случайность — хэш (индекс частицы, сид погоды, цикл), как `HdFx::hitHash`.
  `RNG::` игры не трогать никогда. В `Map::think` (Map.cpp:1308-1318) поднимать `_redraw`, пока погода идёт.
- **Опции**: `Options.inc.h` рядом с `oxceHdFx` (:338) / `oxceHdBloodSteps` (:353), регистрация Options.cpp:555-589,
  экран `OptionsHdState.cpp`. Предлагаю: `oxceHdWeather` (вкл/выкл), `oxceHdWeatherPower` (1-5),
  `oxceHdWeatherGround` (налёт). Строки — в `bin/common/Language/OXCE` (исключение святого правила, шаг 2 обязателен).

Цена (оценка разведчика, не замер — R-091): 300-1000 частиц спрайтами `blitFrame` на 2560×1440 — терпимо; дождь
дешевле сделать 2-3 тайлящимися буферами штрихов с прокруткой по ветру (одно наложение на слой); налёт — не больше
одного готового кадра на видимый тайл; маски крыш и луж — раз на изменение карты. Замер до и после — обязателен.

## 3. Видимость и честность

- Видимость — одно место: `getVisibleDistanceMaxHelper` и `TileEngine::visible` (TileEngine.cpp:1735, 1871);
  ИИ ходит через них же (AIModule.cpp:466, 2998…). Глобальные `maxViewDistance` / `maxDarknessToSeeUnits` —
  на всю игру, ключей на миссию или terrain нет.
- **Механическая погода** — минимум 6-10 мест C++, новое поле в сейве (старые = «ясно»), прогон стенда ИИ. Без
  кода можно только через подмену брони (`armorTransformations`) или скрипт `VisibilityUnit` — оба меняют баланс.
  Это правило 2: только по решению Vitali.
- **Визуальная погода честна, если**: (а) не скрывает клетку или юнита, видимых движку; (б) мгла — в «воздухе»,
  юниты в поле зрения рисуются без маски; (в) порог контраста у силуэтов; (г) молния — украшение, `shade` не меняется;
  (д) опция выключения. Иначе игрок видит меньше, чем ИИ, — это против контракта честности.

## 3а. Решение Vitali 11.11: только картинка

Vitali: «она режет только визуал, механика игры не меняется — если идёт ливень, становится меньше видно; в будущем можно
модифицировать усталость». Ответы: сила «умеренно», по ходам усиливается и стихает, ясно ~50 % (сильная непогода ~10 %).
Набросок механической модели (множитель дальности / «дым в воздухе») снят — он есть в истории этого файла.

- **Пелена по расстоянию** от ближайшего своего солдата (не от камеры): до порога — чисто, дальше густеет до полной мглы
  за 2-3 клетки. Пороги: дождь, снегопад ~17; ливень, гроза, шторм ~14; метель ~11; туман ~10; вьюга, песчаная буря ~8;
  морось, редкие снежинки, ветер, перекати-поле — без пелены. Ночью порог тот же, пелена темнее.
- Механика не задета: `TileEngine::visible`, FOV, сейв, ИИ — как в OXCE. Пелена — маска по клеткам раз на ход
  (и при шаге солдата), рисуется готовой командой холста под `HdWorkers`.
- **Замеченный враг** движку виден и в HUD (красные кнопки), поэтому под пеленой он остаётся силуэтом — насколько
  проступает, решается на странице.
- Сила — функция (сид, номер хода): буря налетает и стихает, пороги плавают в пределах вида.
- Тип и сид — из сейва без записи (см. «Главное»); ясно ~50 %, остальное по таблице биома.
- Позже, отдельным решением: усталость в дождь и снег (механика, правило 2).

Память +30…90 МБ (кадры смерча и вихрей ×4). Откуда цена: пока погода идёт, карта перерисовывается 30 раз в секунду

больше трети времени); смена шага пишется в лог («HD weather: moves every N ms»). Перемер тем же скриптом:

## 4. Следы на полу — без ромбов

Правило 12 и R-039: налёт **не ромбом на тайл**. Маска — шум в мировых координатах, тайл только разрешает
(«пол, открытое небо, обнаружен»). Край пятна идёт по шуму, а не по границе клетки. Порог по шуму растёт с ходами
(снег копится, лужи растут, песок наметает у стен с градиентом от стены). Следы шагов в снегу — через готовые `hdSteps`.

## 5. Звук

`ambience` / `ambienceRandom` есть только у RuleTerrain (RuleTerrain.cpp:96-102), играет `BattlescapeState.cpp:921`,
`seedless`. Звук погоды можно пустить отдельным HD-каналом без записи в сейв. Нужны файлы с понятной лицензией.

## 6. Что из других игр берём (подробнее — отчёт разведчика, в основном общее знание, не проверено по источникам)

RimWorld: вес погоды на биом и снег только на открытой земле. Project Zomboid: лужи растут с силой дождя,
снег копится. Дождь: 2-3 слоя штрихов с параллаксом (дальние тусклее и медленнее), брызги на высоте пола тайла.
Снег: синус с фазой по id. Метель и буря: тайлящийся шум с несоизмеримыми периодами плюс тон кадра. Против
повторов узора — blue noise для расстановки. Модов погоды для OXCE поиск не нашёл (форум руками не проверен).

## 7. Предлагаемый порядок

1. **Страница-артефакт** (правило 13): кадры боя Пираток «оригинал / сейчас / с погодой» по 2-3 варианта на вид
   (дождь трёх сил, снег и метель, песчаная буря, налёт на полу) — Vitali отмечает и жмёт «Готово».
2. `HdWeather.{h,cpp}`: выбор биома и сида, частицы, маска крыш; опция; замер на hdbench; Ctrl+F8 при k = 1 — IDENTICAL.
3. Налёт на полу и тон кадра (`Cmd::TONE`).
4. Перекати-поле, листья, молния — спрайты через страницу.
5. Звук — когда будут файлы.
6. Усталость в дождь и снег — механика, только по отдельному решению.
