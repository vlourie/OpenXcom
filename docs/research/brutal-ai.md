# Разведка: Brutal-OXCE (Brutal AI)

**Дата:** 2026-09-19
**Задача:** понять, что авторы Brutal AI изменили в OXCE, и чего это стоит для нашей ветки ИИ.
**Вывод одной строкой:** форк даёт готовый рантайм-переключатель ИИ, честный режим без читерства и автобой обеими сторонами — три вещи, которые я закладывал как отдельную работу. Оценка «месяц вечеров до арены» сокращается примерно вдвое.

## 3. Архитектура: как устроено переключение

`AIModule::think()` (строка 430) делает общую подготовку, а затем:

```cpp
if (_unit->isBrutal())
{
    brutalThink(action);
    return;
}
// дальше — оригинальный код OXCE, без изменений
```

`brutalThink()` начинается на строке 3189; весь файл теперь 7289 строк. В `AIModule.h` добавлено **~80 новых методов** — не конфиг-константы, а полноценная подсистема:

- **оценка позиции:** `getCoverValue`, `highestCoverInRange`, `isPositionVisibleToEnemy`, `getPeakPosition` (непрямое подглядывание из-за угла);
- **свой слой пути:** `_allPathFindingNodes`, `tuCostToReachPosition`, `furthestToGoTowards`, `closestToGoTowards`, `isPathToPositionSave`, `getReachableBy`;
- **выбор атаки по ожидаемому урону:** `brutalScoreFiringMode`, `brutalExtendedFireModeChoice`, `damagePotential`, `maxExtenderRangeWith`;
- **не стрелять по своим:** `projectileMayHarmFriends`, `brutalExplosiveEfficacy`, `inRangeOfAnyFriend`;
- **работа по неизвестным целям:** `blindFire`, `getNewTileIDToLookForEnemy`, `scoreVisibleTiles`, `getClosestSpawnTileId` (идут к точке высадки игрока);
- **гранаты и предметы:** `brutalGrenadeAction`, `grenadeRiddingUrgency`, `tryToPickUpGrenade`, `improveItemization`, `getItemPickUpScore`;
- **психология боя:** `shouldAvoidMeleeRange`, `wantToRun`, `getUnitPower`, `IsEnemyExposedEnough`, `setWantToEndTurn`.

Правки в `TileEngine.cpp` — это в основном **фундамент под это всё**, а не смена механики: `visibleTilesFrom`, `calculateTilesInFOV`, `hasTileSight`, плюс кэш видимости (`setVisibilityCache` / `getVisibilityCache` / `resetVisibilityCache`). То есть авторы упёрлись ровно в ту же стену, что и мы упрёмся: ИИ, который честно считает видимость для сотен клеток, тормозит, и нужен кэш.

## 4. Три находки, которые меняют план

### 4.1. Переключатель ИИ уже есть, и он **поюнитный**

```cpp
bool BattleUnit::isBrutal() const
{
    if (getFaction() == FACTION_HOSTILE)      brutal = Options::brutalAI;
    else if (getFaction() == FACTION_NEUTRAL) brutal = Options::brutalCivilians;
    else if (getFaction() == FACTION_PLAYER)  brutal = isAIControlled();
    if (_unitRules && _unitRules->isBrutal())    brutal = true;   // из рулсета
    if (_unitRules && _unitRules->isNotBrutal()) brutal = false;
    return brutal;
}
```

Опции `brutalAI` и `brutalCivilians` дают `0 = ванильный OXCE`, `1 = Brutal AI`, `2 = Seek & Destroy`. Плюс рулсет может форсировать режим **на конкретный тип юнита**.

Это ровно тот «сменный ИИ-бэкенд», который я закладывал как 1–2 недели работы. Он уже написан, причём с более тонкой гранулярностью, чем я предлагал: можно сравнивать не только «сторона А против стороны Б», но и «секториды на ванили против секторидов на Brutal» в одном бою.

### 4.2. Читерство — явная настройка, и по умолчанию его нет

```
aiCheatMode (по умолчанию 0):
  -1  без squadsight
   0  без читерства
   1  ИИ видит позиции твоих юнитов на миникарте
   2  ИИ всегда видит твои юниты
```

Причём:

```cpp
int BattleUnit::aiCheatMode()
{
    if (getFaction() != FACTION_HOSTILE) return 0;  // игрок и мирные — всегда честно
    return Options::aiCheatMode;
}
```

Это снимает мой главный вопрос из прошлого захода: сравнение будет честным, достаточно держать `aiCheatMode = 0`. Отдельно стоит отметить `updateTurnsSinceSeenByClue` — ИИ (и игрок по Alt) умеет вычислять клетку, откуда прилетел выстрел, не видя стрелявшего. Это не читерство, это вывод из наблюдаемого, но при замерах учитывать.

### 4.3. Автобой: ИИ умеет играть **за игрока**

Опция `autoCombat` передаёт управление отрядом игрока тому же ИИ (`isAIControlled()`), с настройками по типам юнитов и хоткеем Ctrl+A. В `BattlescapeGame.cpp` под это уже разведён цикл ходов, включая крайние случаи (юнит погиб от реакционки во время автоплея — строка 230).

**Это и есть недостающий «скриптовый бот-игрок».** Я писал, что его придётся сочинять с нуля; сочинять не надо. Более того, сторона игрока в автобою не читерит по определению (см. выше), значит асимметрия информации в арене контролируется полностью.

## 5. Чего по-прежнему нет

**Headless-режима нет.** Ни флага командной строки, ни запуска боя без окна — `main.cpp` и `CrossPlatform.cpp` в этой части не тронуты, CI собирает обычный бинарник под SDL. Автобой крутится внутри живого `BattlescapeState` с анимациями и таймерами.

То есть арену всё равно строим мы, но задача сузилась: не «написать ИИ для обеих сторон и цикл боя», а **«снять UI-обвязку с уже работающего автобоя»** — отвязать от `Screen`, выключить анимации и ожидания, добавить генерацию боя по seed и машинный вывод результата. Это самая рискованная часть по-прежнему, но объём меньше раза в два.

## 6. Риск: форк меняет механику по умолчанию

Для нас, с правилом «ничего не трогаем в механике», это существенно. Realistic Accuracy отключён по умолчанию (`battleRealisticAccuracy = false`) — хорошо. Но вот что **включено** из коробки:

| Опция | Дефолт | Что делает |
|---|---|---|
| `shootingSpreadMode` | **1** | разброс равномерный по направлениям, не как в оригинале |
| `ignoreDelay` | **true** | алиены применяют взрывчатку с 1-го хода (в ванили — с 3-го) |
| `allowPreprime` | **true** | ИИ заранее ставит таймер на гранаты |
| `avoidMines` | **true** | ИИ не наступает на прокси-гранаты |
| `preprimeGrenades` | **1** | автовзвод дымовых в экипировке |
| `updateTurnsSinceSeenByClue` | **true** | точное отслеживание источника выстрела |
| `brutalAI` | **1** | Brutal AI включён |

Плюс форк **переименовал** существующую опцию OXCE `oxceUniformShootingSpread` в `shootingSpreadMode` и удалил `aggressiveRetaliation` из OXC-набора. При заимствовании это надо ловить отдельно, иначе поедут сейвы и конфиги.

Вывод: заимствовать можно, но «включить и забыть» нельзя. В арене все эти флаги фиксируем явно, в игровой сборке — приводим к ванильным значениям, иначе `IDENTICAL` и любые замеры сравнивать не с чем.

## 8. Обновлённая оценка

| Этап | Было | Стало | Почему |
|---|---|---|---|
| Разбор дифа | 1–3 вечера | **сделано** | — |
| Сменный ИИ-бэкенд | 1–2 недели | **~0** | `brutalAI` + `isBrutal()` уже есть |
| Бот-игрок для замеров | не оценивал | **~0** | `autoCombat` уже есть |
| Headless-арена | 2–4 недели | **1–2 недели** | остаётся снять UI с рабочего автобоя |
| Турнир + статистика | 2–3 вечера | 2–3 вечера | — |
| Приведение механики к ванили | не учитывал | **3–5 вечеров** | семь флагов + переименования |

Итого порядка **двух недель вечеров** до состояния «ночью гоняется несколько тысяч боёв, утром таблица», вместо месяца.

## 9. Что делать дальше

1. **Собрать Brutal как есть** и поиграть пару боёв с `aiCheatMode = 0`. Дешевле всего понять, насколько он вообще лучше, до того как вкладываться.
2. **Замерить время хода.** `aiPeformance` существует не просто так: Brutal перебирает достижимые клетки с оценкой укрытия — на больших картах Пираток это может оказаться неприемлемо медленно даже для игры, не говоря об арене на тысячи боёв.
3. **Решить стратегию заимствования.** Либо мерж ветки Brutal в отдельный бранч нашего форка (он на той же базе 8.7.0 — реально), либо перенос только `AIModule` + необходимого куска `TileEngine`. Второе чище, но `brutalThink` тянет за собой кэш видимости и поюнитные флаги.
4. **Только потом** — headless и арена.

Отдельно: ИИ-ветку держать **параллельно HD-слою**, не смешивая. У нас уже один фронт слияния с MeridianOXC; Brutal — второй, и трогает он `TileEngine` и `BattleUnit`, то есть не те файлы, что HD, но общий `BattlescapeGame`.
