## Рамки — четыре направления

Эскизы процедурные, без модели, на настоящем кадре меню: `frames_sheet.png` (целиком + угол 1:1),
полноразмерные `frame_1..4_*.png`.

| № | Рамка | К какой панели боя |
|---|---|---|
| 1 | латунная накладка с заклёпками, тонкая линия цвета экрана внутри | латунь (пиратская) |
| 2 | кованое железо, угловые пластины на четырёх болтах | железо |
| 3 | корабельный HUD: срезанные углы, скобы, засечки, свечение в цвет экрана | космос |
| 4 | серебро с чернью: светлый ободок, гравированная полоса, розетки | серебро |

Как сделать в движке (одно решение на все четыре):

- **Рамка из картинок, 9 кусков**: `hd/UI/frame_<материал>/corner.png`, `edge_h.png`, `edge_v.png`
  (+ необязательные `mid_top.png` — герб/засечка посередине верхней кромки). Углы ставятся как есть,
  кромки тайлятся, толщина = `inset` окна × k. Цвет экрана — только тонкая внутренняя линия и
  свечение (из рампы), сам материал своего цвета. Стиль выбирается той же опцией, что и панель боя,
  чтобы геоскейп и бой были из одного металла.
- Рисуется в `drawPanelFrame` стилем 4+, куски кладутся в кэш собранной рамки по ключу
  (материал, w, h, k, цвет рампы) — окно не перестраивается каждый кадр (R-009).
- Режим 0 и `oxceHdUiSkin` 1–3 не меняются → IDENTICAL сохраняется.
- Тень рамки на картинку внутри (затемнение 10–15 px у кромки) — уже в эскизах; она же помогает
  читать подписи поверх фона.
- Кнопки следом: та же латунь/железо для `drawButton`, гранями в тон рамки.

Куски рамки — генерацией по эскизу выбранного материала (Qwen-Image, плоский вид спереди, без
перспективы), доводка asset-smith: бесшовность кромки, альфа, 4 размера k.

## Решение Vitali (20.10, второй заход): картинки по темам экрана, как в лаунчере

Не перерисовка старых `BACKxx`, а новые сцены по теме экрана (как фоны мастера лаунчера,
`gen_promo.py`): Qwen-Image-2.1 с нуля, свет и металл панели боя, под текстом — прозрачность,
а текст не должен расплываться.

### Темы (пилот — первые шесть)

`tools/hdart/gen_screens.py` (`THEMES`, `SCREENS`): исследования (лаборатория в трюме), производство
(мастерская), бойцы (кубрик), рынок (чёрный рынок в пещере), ангар, мостик (перехват). После выбора
стиля — остальные: тренировки, мемориал, оружейная (снаряжение), склад и перевозки, погоня за НЛО,
оборона базы, итоги боя, стройка, меню и настройки (каюта капитана). Педия — своя, не трогаем.

Почему по экрану, а не по `BACKxx`: `Back_Main` Пираток стоит на 22 экранах от настроек до
дебрифинга — одна картинка не может быть темой их всех.

### Обработка под текст (эскиз — `art/_review/ui_screens/mock_*`)

Проверено на настоящих экранах Пираток: снятых с пустым фоном (временный мод `ui_blackbg` в папке
модов scratch, установка не тронута) — окно залито ровным цветом экрана F, по нему текст игры
отделяется точно и кладётся на новую картинку.

1. картинка вписывается в окно (cover), а не в экран 320×200 — у каждого окна свой кадр;
2. тон: «мягкий дуотон» — 65 % в рампе экрана (тёмный → F → светлый F) + 35 % своего цвета; свет
   картинки кончается заметно ниже света букв (×0,72);
3. виньетка и тень рамки по краю;
4. **матовое стекло под текстом**: там, где лежат подписи (с запасом), картинка размыта и
   притемнена — сюжет виден по краям и в просветах, буквы стоят на спокойном тёмном;
5. **мягкий тёмный ореол у каждой буквы** (2 px) — край знака не тонет в рисунке, текст остаётся
   резким TTF, сам не размывается;
6. рамка — металл панели боя, тонкая линия цвета экрана внутри.

### Как встанет в движок (после выбора, отдельной правкой через editq)

- `State::setWindowBackground(window, s)` — единственная точка, где экран называет себя (129 вызовов):
  окно запоминает имя экрана `s`, классика не меняется.
- HD-зеркало окна ищет картинку темы по таблице в моде (`hd/UI/screens/screens.txt`: тема → экраны,
  картинки `hd/UI/screens/<тема>.png`) — состав тем правится без сборки.
- Тон по рампе — во время рисования, по палитре окна: одна картинка служит экранам разного цвета.
- Стекло под текстом — по прямоугольникам текстов окна с прошлого кадра (экраны статичны);
  обработанная картинка в кэше по ключу (тема, w, h, k, палитра, набор прямоугольников), R-009.
- Ореол букв — в `drawTtfString` для текста на картинке (сейчас там обводка, R-399).
- Рамка из 9 кусков по материалу `oxceHdBattleHudColor` (латунь, космос, серебро, железо, бронза).
- Режим 0 и экраны без картинки темы — как сейчас → IDENTICAL.

### Движок

| где | что |
|---|---|
| `State::setWindowBackground` | окно запоминает имя экрана (`Window::setInterfaceName`) |
| `src/Engine/HdScreens.*` | таблица тем, подготовка картинки, стекло под текстом, металлическая рамка |
| `Window::draw` (ветка скина HD) | есть тема — картинка темы во внутренний прямоугольник рамки, иначе как было |
| `HdUiDraw::drawTtfLine` | строки текста на картинке окна записываются (прямоугольники для стекла) |
| `HdUi::noteBackdrop` | картинка окна — «занятая» подложка: текст на ней с обводкой и ореолом (R-399) |
| `HdBattleHud::metalShade` | рампа металла панели боя (графит без цвета панели → латунь) для рамки |

- Таблица — `hd/UI/screens/screens.txt` мода hd: `картинка.png = id экранов…` (id — `interfaces` рулсетов,
  у ванили и Пираток одни). Пишет `gen_screens.py install`, движок читает при загрузке HD-интерфейса.
- Картинка: cover во внутренний прямоугольник окна при k, цвета ×0,7 насыщенности, свет ×0,72,
  тень рамки по краю и виньетка; матовая копия — три прохода box-размытия радиусом k, ×0,6.
- Стекло: прямоугольники строк прошлого кадра (+2 px, размытие маски), смесь резкой и матовой
  копий собирается **один раз на набор строк** (хеш) и дальше копируется строками (`shadeRows`).
  Кэш картинок — до 144 МБ (три плоскости на окно), LRU.
- Рамка: поле высот (полоса, скруглённые углы, фаска, заклёпки через 14 базовых px на толстой
  рамке), свет и тон по `metalShade`, шлифовка, тонкая линия цвета экрана внутри. 4 полосы в кэше;
  у всплывающих окон, пока они растут, — прежняя векторная рамка.
- Включено: HD-интерфейс со скином, k ≥ 2, опция `oxceHdPictures` («Картинки HD»). При k = 1 и в
  режиме 0 HdUi не работает → кадр классики не меняется.
