# Живой стенд для проверок: одна загрузка — сколько угодно кадров

26.10, задача от Vitali: «САМАЯ ГЛАВНАЯ».

## Проблема

Сейчас `tools/game_hidden.py` делает так: запуск игры, загрузка модов и сейва (60–90 с, на загруженной машине до 330 с), цепочка щелчков, один кадр, выход. Каждый экран и каждое положение опции — новый запуск. Финальный прогон пачки на 20 экранов — 30–60 минут ожидания.

## Решение

Игра под переменной `OXCE_HD_CONTROL=<папка>` не выходит после кадра, а ждёт команды из файла.

- Загрузка — один раз на сборку.
- Каждая следующая проверка стоит секунды: щелчки, клавиши, кадр, переключение опции, другой сейв без перезагрузки модов.
- Клиент `tools/hdbench.py` держит игру живой между вызовами (агент или командир зовёт его много раз подряд).
- Без переменной код не исполняется: путь игрока и режим 0 не меняются, механика не трогается.

## Движок (src/Engine/Game.cpp, рядом с OXCE_HD_DUMP, ~стр. 443–670)

Каждые 100 мс (по `SDL_GetTicks`) игра проверяет `<папка>/cmd.txt`.
- Если файл есть: переименовать его в `cmd.<n>.run` (n по порядку), строки встают в очередь команд.
- Команды исполняются по одной за кадр; `wait` занимает время.
- В конце пачки игра пишет `<папка>/done.<n>`. В нём по строке на команду: `ok`, `err <текст>` или результат (`state`), последняя строка `end`. Запись — во временный файл и переименование, клиент не должен прочитать полфайла.

### Команды (по строке, `#` — комментарий)

| команда | что делает |
|---|---|
| `click x,y` / `rclick x,y` / `mclick x,y` | щелчок в пикселях базового экрана, как `OXCE_HD_CLICK` (тот же `toDisplay`) |
| `hover x,y` | только движение мыши |
| `wheel up x,y` / `wheel down x,y` | колесо (с `ctrl` — как `u`/`d` у OXCE_HD_CLICK) |
| `key N` / `key ctrl+N` | клавиша SDL, как `OXCE_HD_KEY` (`key ctrl+289` — полный дамп боя Ctrl+F8) |
| `type текст` | ввод текста, как `OXCE_HD_TYPE` |
| `wait ms` | пауза, кадры идут (анимации, загрузка) |
| `shot <файл.png>` | `_screen->requestHdTestDump(файл)`; `done` пишется только после записи файла |
| `set ключ=значение` | любая опция из `Options::getOptionInfo()` (через `OptionInfo::load` из YAML-узла `{ключ: значение}`), затем `_screen->resetDisplay(false)`; особые: `k=n` (`setWorldScale`), `oxceHdUi=n` |
| `reinit` | `init()` верхнего состояния (экран перечитывает опции) |
| `state` | в ответ — имя класса верхнего состояния (`typeid`, без префикса) и, в бою, сторона хода |
| `load <имя.sav>` | загрузка сейва из папки пользователя тем же путём, что `ListLoadState` (без перезагрузки модов) |
| `open geoscape\|base\|battle\|load` | тот же переход, что `MainMenuState` по `what` |
| `quit` | выход |

Ошибка команды не останавливает игру: `err ...` в done, дальше следующая.

## Клиент `tools/hdbench.py` (python 3.13, без зависимостей кроме ai_probe)

- `start --name A [--exe ...] [--save ...] [--set k=v;...] [--user ...]` — запуск через `ai_probe.Hidden` (скрытый стол, SDL dummy, как `game_hidden.py`; общие куски вынести, а не копировать). Ждёт, пока игра ответит на `state` (готова). Пишет `scratchpad/hdbench/<A>/pid`.
- `run --name A "click 10,20; wait 500; shot E:/.../x.png"` или `--file script.txt` — кладёт `cmd.txt`, ждёт `done.<n>` (тайм-аут по сумме `wait` + 60 с), печатает результат, код 1 при `err`.
- `stop --name A` — `quit`, ожидание выхода, иначе снять процесс (свой, по pid).
- `list` — живые стенды.
- Несколько стендов сразу (эталонный exe и новый) — по имени.
- Справка в начале файла; пример финального прогона экрана в одну команду.

## Проверка (Definition of Done)

1. Сборка; `hdtest_compare` режим 0 при k=1 и k=4 IDENTICAL против `scratchpad/xp291b_before.exe` на стрим.sav. Дамп — `game_hidden` как раньше и через стенд одной сессией: заодно доказательство, что стенд даёт тот же кадр.
2. Замер: один запуск стенда, 10 кадров разных экранов геоскейпа и базы (NoCodexCatZ.sav). Записать время до первого кадра и время каждого следующего. Ожидание: первый — как сейчас, следующие — секунды.
3. В одной сессии: `set` опции и `reinit` — кадр меняется без перезапуска (например `oxceHdWoundedRed`).
4. Без `OXCE_HD_CONTROL` поведение прежнее (`game_hidden` работает как раньше).

Затем строка в docs/handbook/render.md: проверка экранов — через `hdbench.py`; `game_hidden.py` — для одиночного кадра.

## Сделано (26.10)

Движок: `src/Engine/HdControl.cpp/.h` (команды, ответ `done.<n>`), два вызова в `Game::run` (после событий и при нарисованном кадре), `MainMenuState::hdStart` (цепочка `OXCE_HD_START` вынесена в функцию — её же зовёт `open`; без переменной поведение прежнее). Клиент `tools/hdbench.py` (`start|run|stop|list|log`), общие куски вынесены в `tools/hidden_game.py` (его же зовёт `game_hidden.py`). Отличия от наброска выше:

- щелчок идёт в два кадра: движение мыши сейчас, кнопка — на следующем нарисованном кадре (как у человека);
- команда `shot` сама выжидает 3 нарисованных кадра после ввода;
- добавлена `waitstate <Класс> [мс]` — ждать окно, которое игра открывает по своему таймеру (после загрузки `NoCodexCatZ.sav` окно перехвата приходит через 1–3 с после «готов», и их два: R-488);
- `state` отвечает `state <верх> stack=<А>><Б>...` и в бою `side=<сторона> turn=<ход>`; `key` понимает ещё `esc|enter|tab|space|fN`, `ctrl+|shift+|alt+`;
- `set k=N` меняет масштаб мира (слой кадра), а `oxceHdScale` (масштаб карты боя) на лету не меняется — он читается при загрузке боя; для k=4 карты — свой стенд с `--set oxceHdScale=4`.

Проверка (сборка 26.10 после выпуска 2026.10.26, 1920x1080, машина свободна):

1. Режим 0, `стрим.sav`, эталон `scratchpad/xp291b_before.exe` против новой сборки через `game_hidden`: k=1 — map и frame IDENTICAL, k=4 — map и frame IDENTICAL; контрольный опыт (k=1 против k=4 без `--scale`) — DIFFERENT. Через стенд: k=1 map и frame IDENTICAL с эталоном; k=4 map IDENTICAL, frame IDENTICAL на 2 из 4 дампов одной сессии — у остальных 219 и 781 пиксель в рамке кнопки конца хода (x=570..617, y=998..1023): свечение кнопки пульсирует по часам, два дампа стенда друг с другом в секундном интервале различаются тем же пятном (R-489). Файлы — `scratchpad/hdbench_dod/`.
2. Замер, один запуск стенда, `NoCodexCatZ.sav` (`scratchpad/hdbench_measure.py`): запуск игры до готовности 23,4 с (с первым щелчком — 23,6 с по часам вызова), первый кадр (окно перехвата дождалось и снято) — 23,4 + 2,2 = 25,6 с. Следующие девять кадров (перехват, геоскейп, графики, хабаропедия, настройки, база, экран базы и т.д.): 5,85 (после ЕСТЬ: пауза 5,5 с из-за наезда камеры, R-450), 0,58, 1,05, 0,64, 1,04, 0,64, 1,04, 1,10, 0,85 с; сумма девяти 12,8 с, из них явных пауз 10,3 с, на сами команды и снимки — 0,3 с на кадр. 10 разных кадров. 3. В одной сессии `set oxceHdWoundedRed=false/true; reinit; shot` на `стрим.sav`: кадры различаются на 384 пикселя в рамке раненого бойца (x=1012..1040, y=372..408); `set oxceHdUi=0/1` — кадры различаются на 282 тысячи пикселей. Перезапуска нет, 17 команд за 2,7 с.
