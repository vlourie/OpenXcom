# Ревью производительности HD-слоя (только чтение, 05.10)

Правило R-091: ни одной цифры ускорения ниже нет. Цифры "было" взяты только из уже снятых замеров
(docs/PERF.md, docs/research/units-perf-baseline.md). Всё остальное - "ожидаемо дорого, потому что".
Занятые файлы (protected_status.txt) - только tools/ и docs/ (DECISIONS, RAKES и др.); docs/PERF.md и src/ в списке
нет - ни одна находка не задевает занятые файлы.

Как мерить всё ниже: OXCE_HD_FRAMELOG=файл (столбцы record_us, units_us, script_us, smooth_us/n, toned_us/n,
flush_us, strip_max_us, cmds, pack_fr/pack_ms, ui_ms, flip_us), строки "HD perf" и "HD interface: N ms/frame" в
openxcom.log, drawMs/flipMs из дампа Ctrl+F8, tools/hdtest_compare.py --max-slowdown 1.25, серия как в
units-perf-baseline.md (тишина машины R-196, снятый троттлинг R-199, 3 повтора, видимый против видимого для хвоста).

## Топ по ожидаемому эффекту

### 1. Первое появление ассета: затенение, перекраска скриптом и декод пака в одном потоке записи (R-009)
- src/Engine/HdCanvas.cpp:2077-2154 tonedFor - промах считает копию кадра попиксельно на главном потоке во время
  записи команд. Замер уже есть: первый кадр боя 1500-2626 промахов, toned 67-91 мс, рисование 72-88 мс; новый юнит
  в кадре 315-753 промаха, 13-32 мс (units-perf-baseline.md п.4). Это единственные настоящие рывки рисования.
- src/Engine/HdCanvas.cpp:738-913 blitScripted, промах _smoothScripted - перекраска 128x160 HD-пикселей с float и
  поиском соседа 3x3 на главном потоке; при мигании попадания или щите промах на каждой фазе.
- src/Engine/HdSprites.cpp:395-421 find -> load (декод PNG) на главном потоке при первом обращении; preload
  (HdSprites.cpp:540) зовётся только из src/Mod/MapDataSet.cpp:260 - террейн. Юниты, HANDOB, FLOOROB - лениво в кадре.
- Правка: двухфазная запись - tonedFor и перекраска на промахе только заводят запись кэша и задание, Canvas32::flush
  перед полосами делает pool.run по списку заданий (записи в unordered_map и deque - адреса стабильны). Плюс прогрев
  из docs/HD_UNITS.md раздел 9 (кода прогрева в src нет - grep warm/prewarm пусто).
- IDENTICAL: нет риска - режим 0 в tonedFor и паки не заходит; в режимах 1-2 та же арифметика на пиксель.
- Мерить: toned_us/toned_n, script_us/smooth_n, pack_ms на первом кадре боя и при появлении юнита; приёмка прогрева -
  ноль pack_fr/toned_n/smooth_n в кадре для прогретого набора (ТЗ раздела 9).

### 2. HdFx: кадры клипа эффекта декодируются из PNG на главном потоке в момент выстрела или взрыва - и журнал этого не видит
- src/Engine/HdFx.cpp:470-492 - каждый кадр клипа при первом показе: HdSprites::loadPng + resample, один поток, посреди
  анимации. loadPng зовётся напрямую, мимо HdSprites::load, поэтому pack_fr/pack_ms журнала кадров этот декод НЕ
  считают - рывок первого выстрела каждого типа невидим для нынешней разметки.
- Правка: при первом обращении к клипу читать байты всех кадров и декодировать на HdWorkers (как HdSprites::preload),
  либо прогрев клипов оружия на карте; в любом случае считать это время в takeLoadStats.
- IDENTICAL: нет риска - HdFx только при режиме не NEAREST.
- Мерить: сначала добавить счётчик (иначе мерить нечем), затем draw_us кадра выстрела (OXCE_HD_DUMP_FX).

### 3. HD-интерфейс хэширует каждую поверхность целиком каждый кадр побайтовым FNV в одном потоке
- src/Engine/HdUiArt.cpp:71-84 hashPixels - FNV-1a по байту: цепочка умножения на каждый байт, без векторизации.
- src/Engine/HdUi.cpp:602 - drawSurface хэширует каждую поверхность, блитнутую на экран, каждый кадр (k>=2), только
  чтобы найти тот же кэш; HdUi.cpp:744 drawSurfaceWorld хэширует _hdEarth глобуса каждый кадр, хотя Globe.cpp:2187
  сам знает _hdEarthDirty; HdUi.cpp:819 drawSurfaceFit - то же.
- Почему дорого: цена пропорциональна площади всех зеркал кадра (фон экрана, панели, битмап-тексты, глобус в
  масштабе s), а работа - ожидание задержки умножения; на статичном экране это ожидаемо основная часть ui_ms.
- Правка: хэш по 8 байт за шаг (FNV по Uint64 или multiply-xorshift) - одна функция, art->hash и поиск считаются
  ею же, на диск хэши не пишутся (grep hashPixels - только HdUiArt и HdUi). Для _hdEarth - ключ по счётчику
  перерисовки вместо хэша содержимого.
- IDENTICAL: нет риска - хэш только ключ кэша; при k=1 wantHash ложь (HdUi.cpp:601), хэш не считается вовсе.
- Мерить: "HD interface: N ms/frame" и ui_ms на геоскейпе (вращение и покой), в базе, в педии; до и после.

### 4. Запись карты на главном потоке: выделение на каждый тайл и пересчёт света, который меняется раз в действие
- src/Battlescape/Map.cpp:2063 std::vector<int> pixelMaskArray(4*k*k) - выделение кучи на КАЖДЫЙ видимый тайл
  каждого перерисованного кадра (внутри цикла тайлов); содержимое зависит только от k.
- src/Battlescape/Map.cpp:811-848 updateHdLight - на каждый тайл 8 getTile и до 9 вызовов hdTintOf (Map.cpp:768) с
  float по 4 слоям света; оттенок соседа считается до 9 раз за кадр, а меняется при изменении освещения.
  Тень кэширована (_hdShadeCache), оттенок нет.
- Почему важно: record_us - главный поток; база p99 2,9 мс скрыто и 5,2 видимо, в видимом прогоне 13 кадров с
  record_us 15-24 мс без перекрасок и паков - причина открыта (units-perf-baseline.md, Видимый прогон п.3).
- Правка: pixelMask - член Map, перестраивается при смене _k; оттенок - кэш на индекс тайла рядом с _hdShadeCache
  (тот же сброс в Map::draw).
- IDENTICAL: нет риска - маска та же; HD-свет только при режиме не NEAREST (Map.cpp:624).
- Мерить: record_us p50/p99 на бомбардировщике 201 и станции, m0k4 и m2k4.

### 5. Вывод кадра: полная копия world в screen одним потоком
- src/Engine/Screen.cpp:225-232 - при размере окна равном миру (2560x1440 у Vitali) SDL_BlitSurface копирует
  14,7 МБ одним потоком каждый кадр; flip p50 1,6 мс скрыто, 2,57 мс видимо (база 03.10).
- Правка: при SW-поверхностях одного формата - построчный memcpy на HdWorkers (как Canvas32::copyTo), иначе прежний путь.
- IDENTICAL: нет риска - побайтная копия.
- Прямо: SDL_Flip (вывод окна SDL 1.2 при useOpenGL false) - узкое место движка и SDL, не мода; вокруг него мод не
  переписывать.
- Мерить: flip_us только видимый против видимого (dummy занижает, units-perf-baseline.md п.2).
