# Темы по экранам (XP-000484, вариант Г, Vitali 04.11)

Цель: у каждого экрана своя тема кнопок, рамок и текста. Дочерний экран берёт тему родителя, пока ему не задали свою.
Настройки лежат в читаемом файле. Механику не трогаем. Без настроек каждый кадр побайтно прежний.

## Что уже есть (проверено по коду 04.11)

- Тема окон читается из опций в момент рисования: `oxceHdWindowTheme`, `oxceHdWindowThemeColor`, `oxceHdWinKeyHue/Sat/Val`,
  `oxceHdButtonFace/Shape/Gloss`, `oxceHdButtonInkTone/Hue/Light/Sat`, `oxceHdUiSkin`. Читатели: `HdBattleHud.cpp`, `HdUiDraw.cpp`,
  окна настроек. Кэши рамок и кнопок уже различают тему по ключу (`HdScreens.cpp:477`, `HdUi.cpp:803`, `HdBattleHud.cpp:2320`).
- Кадр собирается одним циклом: `Game.cpp:635-640`, `(*i)->blit()` для каждого состояния стопки. `HdWorkers::run` вызывается
  внутри рисования; этап 1 обязан подтвердить, что после `blit` никто не читает тему отложенно (комментарий `HdBattleHud.cpp:290`).
- Экран знает свою категорию: `State::setInterface("...")`. Категорий в коде 111, в рулсетах Пираток 147; `parent` есть только у 9.
  Своего дерева там нет, его задаём сами.
- Без `setInterface` живут 47 файлов состояний, из них около 25 с окном (инвентарь, медкомплект, брифинг, меню действий и другие);
  остальные - служебные `*BState`, у них своего окна нет.
- Одну категорию делят разные экраны: `geoscape` - 8 файлов, `optionsMenu` - 10.
- `winCustom.version` растёт при каждой пересборке рампы. Два своих цвета в одной стопке давали бы новый ключ кэша каждый кадр.

## Схема

**Подмена опций на время `blit` одного состояния.** Перед `(*i)->blit()` движок кладёт в перечисленные опции значения темы этого
экрана, после `blit` возвращает прежние (RAII). Читатели не меняются. Нет настроек для экрана - нет ни одной записи в опции и кадр
прежний: это и есть гарантия IDENTICAL. Опции панели боя (`oxceHdBattleHudColor`, `oxceHdCustom*`) в подмену не входят, панель
настраивается как сейчас (XP-000479).

**Экран.** `State::_hdScreen`: ставится в `setInterface` и `setWindowBackground`, может быть уточнён явным вызовом
`setHdScreen("имя")` там, где категорию делят разные экраны или её нет. Состояние без экрана берёт экран состояния под ним в стопке.

**Дерево.** Таблица в коде, `src/Engine/HdScreenThemes.cpp`: экран -> родитель. Верх: `all` (общие опции) -> группы `menu`, `geoscape`,
`basescape`, `battlescape`, `messages`, `landing`. Экран из чужого мода, которого нет в таблице, - прямо под `all`.

**Разрешение темы.** Каждый параметр берётся отдельно: свой, иначе у родителя и выше, у `all` - текущая опция. Результат кэшируется
и пересчитывается только при изменении файла, настроек или опций верхнего уровня.

**Ключ кэша.** Для своего цвета вместо `winCustom.version` - упакованные оттенок, насыщенность, яркость (`0x50000000 + h<<14 | s<<7 | v`).
Два одинаковых цвета на разных экранах делят один кэш, а чередование экранов не даёт промахов.

**Файл.** `hd_screen_themes.yml` в папке настроек игрока, рядом с `options.cfg`. Только то, что игрок задал:

```yaml
# Темы экранов OXCE-HD. Что не указано, берётся у родителя.
screens:
  basescape: { color: 7 }
  researchMenu: { color: 10, hue: 200, sat: 40, val: 70, face: 2, textHue: 45, textSat: 60 }
```

Файл нет или он битый: тем нет, игра работает, в лог одна строка. Файл читается только при старте и при выходе из окна настроек.

**Текст.** `textHue`, `textSat` - новая подмена цвета надписей: оттенок и насыщенность меняются, яркость каждой точки надписи остаётся.
Обычные надписи сейчас красятся палитрой (`HdUiDraw.cpp:1958`), поэтому это отдельный этап с замером.

## Этапы

1. **Движок без меню.** `_hdScreen`, таблица верхнего уровня, файл, подмена, ключ кэша. Приёмка: без файла IDENTICAL при `k = 1` и
   `k = 4`; с файлом меняется только названный экран; экран над экраном с разными своими цветами - без роста промахов кэша.
2. **Меню.** Настройки HD -> «Темы экранов»: дерево, у строки своя тема или «как родитель», выбор через существующие окна цвета и
   рельефа, сброс. Строки ru и en в `bin/common/Language/OXCE`, копия в установку Пираток.
3. **Цвет текста.** Подмена цвета надписей, замер, настройка в меню.
4. **Все экраны.** Полная таблица и явные `setHdScreen` для окон без категории и для общих категорий, имена всех экранов на двух языках.

## Что не входит

- Отдельная программа настроек: игрок назвал её как вариант, вкладка меню и читаемый файл задачу закрывают.
- Фоновые картинки окон остаются: это арт, а не тема.

## Проверки каждого этапа

Режим 0 при `k = 1` и `k = 4`, `oxceHdUi` 0 и 2: `hdtest_compare.py` против exe предыдущего выпуска. По R-536 сверка не только одной
темы: минимум три цвета и свой. Замер кадра до и после окна с кнопками (R-091). Всё невидимо, через `hdbench`.
