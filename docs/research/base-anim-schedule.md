# Анимация построек базы: неподвижная картинка и вспышки по расписанию

Дата: 2026-09-27. Статус: **сделано** (Vitali: «делай как ты думаешь, я посмотрю»).

Итог реализации, где он разошёлся с проектом ниже:

- вспышка в **одну** петлю (3,2 с, `loops: 1`): база 6×6 — не больше 36 клеток, а не 60, но
  вспышка меняет в среднем 64 % клетки, и обрезка экономит меньше, чем ожидалось;
- замер пака: 228 клеток, в среднем 0,75 МБ на клетку (было 1 МБ), стартовая база Пираток —
  320 картинок за 13 мс, 12 МБ из 64;
- постоянные эффекты: `ripple`, `bubbles` и `sway` (колыхание растений); луч радара — вспышкой;
- дамп стартовой базы: при выключенной анимации постройки чистые; при включённой в один момент
  вспыхивает одна постройка (ангар), остальные совпадают с неподвижной картинкой;
- для проверки добавлен вход `OXCE_HD_START=base` (новая игра и экран стартовой базы);
- формат пака закреплён тестом `tools/test_base_pack.py`, грабли R-104;
- старый пак целиком в `art/_backup/basebits_before_schedule/{repo,piratez}`.

## 1. Что сломано и почему

**Жалоба.** Если выключить «Анимацию построек базы», картинка застывает посреди
анимации: часть огней погашена, по полу казино рассыпаны точки, над складом дым, у кузни
искры. Выключение и повторное включение HD-мода этого не исправляет.

**Причина — в паке, а не в опции.** В паке просто нет неподвижной картинки.

- `tools/hdart/gen_base_anim.py`, функция `write`: фаза 0 петли пишется в `<N>.png`,
  фазы 1..15 — в `<N>.v1..v15.png`. Чистая постройка без эффектов (`Facility.rgb`) на
  диск не попадает никогда.
- Движок при выключенной анимации берёт фазу 0 (`BaseView::drawHd`:
  `facilityPhase = Options::oxceHdBaseAnim ? _animPhase : 0`). То есть показывает
  «стоп-кадр» петли в момент t = 0: с эффектами в том состоянии, в каком они были в эту
  долю секунды.
- Выключить HD-мод и вернуть его — это тот же пак и та же фаза 0. «Обычная» картинка
  есть только у классического слоя, то есть когда HD-мода нет вообще.

**Замер** (скрипт сравнивает фазу 0 с чистой постройкой, 114 построек с эффектами):
у половины построек фаза 0 отличается от чистой больше чем на 4 % пикселей. Хуже всех:

| постройка | доля изменённых пикселей | эффекты |
|---|---|---|
| STR_BURROW | 53 % | flicker, tint |
| STR_DISRUPTOR_SHROUD | 45 % | blink, pulse, sparks |
| STR_SUMMONING_CIRCLE | 45 % | sparks, sweep, tint |
| STR_RED_TOWER | 43 % | breathe, pulse |
| STR_GENERAL_STORES_DAMAGED | 42 % | smoke, sparks, tint |
| STR_CASINO | 25 % | band, blink, pulse, sweep |
| STR_HANGAR | 21 % | blink — посадочные огни погашены |

Лист «чистая | фаза 0»: [../assets/base-anim-still-vs-phase0.png](../assets/base-anim-still-vs-phase0.png).

«Картинка некачественная» — отдельная беда, её этот план не лечит. HD-постройки базы — это
классический спрайт, увеличенный Scale2x до x4, поэтому пиксельные ступеньки видны
(RED_TOWER на листе). Перерисовывать базу моделью — отдельная задача.

## 2. Что хотим

1. Анимация выключена — постройка **чистая**, как нарисована, без эффектов.
2. Анимация включена:
   - **постоянные** эффекты (вода в бассейнах и онсэне, пузыри хеллерия, рябь в
     резервуарах) идут всё время;
   - **остальные** (огни, дым, искры, лучи радаров, бегущие полосы) — **вспышкой**: раз
     в 30, 45 или 60 секунд постройка «оживает» на несколько секунд и снова стоит.
3. Постройки не вспыхивают все разом — у каждой свой сдвиг.
4. Механика не трогается (правило 2): никакого `RNG` игры, только часы экрана.

## 3. Формат пака

Остаётся папка `hd/BASEBITS.PCK/`, меняются имена фаз. Номер `<N>` — как сейчас
(`hdTileIndex`, номер мастер-мода без сдвига).

| файл | что это | у кого есть |
|---|---|---|
| `<N>.png` | **неподвижная чистая картинка** | у всех |
| `<N>.v1.png` … `<N>.v16.png` | постоянная петля: только постоянные эффекты, 16 фаз по 200 мс | только у построек с водой и подобным |
| `<N>.b1.png` … `<N>.bM.png` | вспышка: постоянные + периодические эффекты, с нарастанием и затуханием | только у построек с периодическими эффектами |
| `<N>.anim.txt` | одна строка: `every 45` — период вспышки в секундах | у тех, у кого есть вспышка |

Почему `.png` теперь отдельно от петли: неподвижная картинка нужна и при выключенной
анимации, и между вспышками. Если бы она оставалась фазой 0 петли, между вспышками
вода стояла бы, а в петле был бы рывок.

**Совместимость.** Старый пак (`.png` + `.v1..v15`, без `.anim.txt` и без `.b*`)
движок читает как сейчас: `.png` — фаза 0 петли. Признак нового формата — наличие
`<N>.anim.txt` или файлов `.b*`; тогда `.png` в петлю не входит.

## 4. Генератор (`tools/hdart/gen_base_anim.py`, `base_anims.yml`)

**Разметка в yml.** Два новых ключа, оба необязательные:

```yaml
STR_ONSEN:
  every: 60                 # период вспышки, секунд (30 / 45 / 60)
  effects:
    - {fx: ripple, ...}     # вода - постоянная сама по себе (см. ниже)
    - {fx: pulse, ..., always: true}   # этот огонь тоже горит всё время
```

- У эффекта `always: true | false`. По умолчанию постоянные — `ripple` и `bubbles`
  (вода, пузыри); всё остальное — вспышка. Если нужно, чтобы маяк на вышке мигал всё время,
  ему пишут `always: true`.
- У постройки `every:`. Если не задан — берётся по категории, чтобы база не мигала в
  такт: 30 с — производство и мастерские (кузня, принтер, лаборатории), 45 с — связь,
  радары, защита, 60 с — жильё, склады, ангары. Таблица категорий — в шапке yml.
- `STR_HELLERIUM_PLANT` (свой генератор `gen_base_bubbles.py`) — целиком постоянная
  петля; генератору нужна та же правка: чистая `.png` отдельно, петля в `.v1..v16`.

**Что пишет.**

1. `<N>.png` — `Facility.rgb`, без единого эффекта.
2. Если есть постоянные эффекты — 16 фаз петли из них одних → `.v1..v16`.
3. Если есть периодические — вспышка длиной `M = 16 · loops` фаз (по умолчанию `loops: 2`,
   6,4 с): кадр = петля (или чистая) + `e(p)` · (полный кадр − петля), где огибающая
   `e(p)` нарастает за первые 3 фазы и гаснет за последние 3. Первый и последний кадр
   вспышки совпадают с петлёй — входа и выхода не видно. Фаза петли внутри вспышки
   идёт тем же счётом (`p mod 16`), поэтому вода во время вспышки не дёргается.
4. `<N>.anim.txt` — `every <сек>`.
5. Старые файлы клетки перед записью удаляются (`<N>.v*.png`, `<N>.b*.png`), иначе
   от прежней 16-фазной петли останется хвост, а движок считает фазы до первой дыры.

**Превью** (`--preview`) — три GIF на постройку: чистая, постоянная петля, одна вспышка
с секундой покоя до и после. В мод — только после выбора Vitali (правило «арт — сначала
показать»).

## 5. Движок

Всё в двух файлах: `src/Engine/HdBase.*` и `src/Basescape/BaseView.cpp`.

**HdBase.** В `Tile` три списка вместо одного: `still` (`.png`), `loop` (`.v*`),
`burst` (`.b*`) плюс `every` (мс) из `.anim.txt`. Разбор имён в `scan()` — тот же, что
для `.v`, плюс буква `b`. Новый вызов вместо `frame(index, phase, ...)`:

```cpp
/// Картинка клетки в момент `ms` (часы экрана) для постройки со сдвигом `offset`.
const HdFrame *frameAt(int index, Uint32 ms, Uint32 offset, bool animate, int scale, int w, int h);
```

Выбор кадра:

```
если !animate                       -> still
t = ms + offset
если есть burst и (t mod every) < M*200  -> burst[(t mod every) / 200]
иначе если есть loop                 -> loop[(t / 200) mod 16]
иначе                                -> still
```

`every` округляется вниз до кратного 3,2 с (16 фаз), чтобы начало вспышки всегда
совпадало с фазой 0 петли — тогда вода внутри вспышки продолжается без скачка.

**Сдвиг постройки.** `offset` — хэш координат постройки на базе (`x*7 + y*31`, как у
огней кораблей, `craft.seed`), умноженный на шаг 3,2 с и взятый по модулю `every`.
Все клетки большой постройки берут один `offset` — вспыхивают вместе. Часы —
`SDL_GetTicks()`, никакого `RNG::generate`: сейв и ход игры не видят анимацию вообще.

**BaseView.**

- `drawHd` вызывает `frameAt` с `SDL_GetTicks()` и `offset` постройки; `_animPhase` для
  построек больше не нужен (у кораблей остаётся как есть).
- `blink`: `_redraw = true` только если на базе есть постоянная петля или хоть одна
  постройка сейчас во вспышке (или вспышка только что кончилась — нужно вернуть
  неподвижную). Сейчас база перерисовывается каждые 200 мс всегда, когда в паке есть
  анимация; после правки спокойная база не перерисовывается вовсе. Это выигрыш, а не
  расход (R-009).
- `preload`: при выключенной анимации — только `.png`, как сейчас. При включённой — `.png`
  и петля сразу, вспышку — тоже сразу (иначе первая вспышка каждой постройки даст
  подвисание на чтении PNG).

**Память** (бюджет HdBase 64 МБ). Сейчас: 16 фаз на клетку. Будет: 1 + (16, если есть
вода) + 32 (вспышка в 2 петли). Для типичной базы из ~60 клеток по 64 КБ при x4 это
~60 × 33 × 64 КБ ≈ 125 МБ — **в бюджет не влезет**, LRU начнёт выбрасывать фазы и читать
их заново во время вспышки. Два выхода, выбрать один:

- вспышка в одну петлю (`loops: 1`, 3,2 с) — ~60 × 17 × 64 КБ ≈ 65 МБ, на грани;
- **(рекомендую)** хранить вспышку не целиком, а прямоугольником, где она отличается от
  петли/неподвижной (`<N>.b<k>.png` + `<N>.b.rect.txt`), и рисовать её поверх `.png`.
  Огни и искры занимают 5–25 % клетки — память падает в 4–10 раз, вспышка может быть
  длиннее. Генератору это одна обрезка по маске отличий.

Точные числа — замером (`HD base: preloaded ... MB of 64 MB` в логе), а не прикидкой
(R-091).

**Опция.** `oxceHdBaseAnim` остаётся вкл/выкл. Можно (шаг 3, по желанию) добавить
`oxceHdBaseAnimEvery`: «как в паке / 30 / 45 / 60 / всегда» — множитель к `every`,
чтобы игрок мог сделать базу спокойнее или живее без перегенерации.

## 6. Порядок работ

| шаг | что | проверка |
|---|---|---|
| 1 | Генератор: чистая `.png`, петля `.v1..v16` только из постоянных эффектов, вспышка `.b*`, `.anim.txt`, `every`/`always` в yml; то же в `gen_base_bubbles.py` | превью-GIF: чистая / петля / вспышка — Vitali выбирает |
| 2 | HdBase + BaseView: `frameAt`, три списка, старый формат читается по-старому | дамп Ctrl+F8 на базе: анимация выкл → клетки побайтно равны чистой `.png`; вкл → через `every` секунд вспышка |
| 3 | Перегенерация 298 клеток в обе копии мода hd (репозиторий и установка Пираток, R-087) | сверка списков файлов в обеих копиях; лог `HD base: ... tiles` |
| 4 | Опция частоты (по желанию) | экран настроек без сырых `STR_` (R-078) |

Приёмка движка: режим 0 при k = 1 и k = 4 даёт IDENTICAL (база в HD-слое при k = 1 не
рисуется вовсе, `drawHd` выходит при `k < 2`), `drawMs` на базе не хуже прежнего —
ожидаю лучше, потому что спокойная база перестаёт перерисовываться.

## 7. Чего НЕ выяснил

- Какие постройки Vitali считает «водой» кроме `ripple`/`bubbles`: `sway` (колыхание
  растений) и `sweep` (луч радара) можно отнести и к постоянным. Сейчас в плане — вспышка.
- Категории 30/45/60 с для 114 построек предложены по смыслу, список не согласован.
- Есть ли у кораблей в ангарах HD-картинки с фазами (`craft.index` через `HdBase::frame`
  с `_animPhase`): в текущем паке файлов `.v*` у кадров 1288–1293 нет, но если появятся,
  у них будет та же беда с фазой 0.
