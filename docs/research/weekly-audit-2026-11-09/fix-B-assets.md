# Пакет Б аудита 09.11: HD-арт без невидимого цвета

Скрипт: `tools/hdart/strip_hidden_rgb.py` (Pillow 12.1.1, numpy 2.4.4). Не трогает видимые пиксели: RGB обнуляется только там, где альфа = 0;
PNG пересохраняется `optimize=True, compress_level=9`, режим RGBA прежний. Файлы другого режима (палитра, RGB) пропускаются; если новый файл
не меньше старого, он не пишется. Запись: временный файл рядом + `os.replace`; с `--verify` новые байты перечитываются ДО подмены
(альфа побайтно та же, RGB при альфе > 0 побайтно тот же), при расхождении файл остаётся прежним и идёт в отчёт.

## Педия: доказательство по коду и решение

Загрузчик всех путей HD-картинок один — `HdSprites::decodePng` (`src/Engine/HdSprites.cpp:1188`): `lodepng::decode(..., LCT_RGBA, 8)`;
его зовут `HdUiArt.cpp:506` (карточки/куклы hd/UI), `HdBase.cpp:580`, `HdSprites.cpp:296` и `loadPng`. `Mod.cpp:3409` читает у картинки
только размер (`pngSize`, заголовок) и `.pal.txt`. lodepng при приведении RGB → RGBA ставит альфу 255 и не меняет RGB (в файле нет tRNS),
то есть кадр в памяти для RGB-файла и для RGBA-файла с альфой 255 побайтно один. Код движка цвет-тип нигде не проверяет
(grep `colortype` вне lodepng: только кодировщики). Ещё довод: в `hd/UI` уже лежат RGB-карточки (в выборке 70 из 200) — игра читает их так же.

**Вывод: RGB для непрозрачных карточек безопасен для движка** (`--cards`, проверка `verify` для них — равенство всего RGBA).
Но не применено: полный сухой прогон — 1 841 файл, 1 870,6 → 1 665,6 МиБ (**−205 МиБ, −11,0 %**; записали бы 1 137, непрозрачных нет у 105,
уже RGB 583, палитра 16). Именно это и делал выпуск 2026.11.02-2 и был откатан в 11.03 (`7a2b14606`: «прежние байты у не перерисованных
картинок педии… обновление ~0,4 ГБ вместо 1,5») — причина отката трафик (докачка ~1,5 ГиБ одной волной), а не корректность. Решать ведущей
сессии/Vitali: имеет смысл только в одной волне с куклами/террейном (они и так перекачиваются).
