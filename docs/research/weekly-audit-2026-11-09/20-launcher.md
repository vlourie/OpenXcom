## Безопасность: что проверено по пунктам задания

### Цепочка доверия
- **Манифест и блобы.** `Updater`, `LauncherRelease.FetchAsync`, `Installer`: манифест проверяется ключами `prod` из `portal/keys/release-keys.txt`. Ключ `dev` в Release не принимается: `Config.cs:134-135` и `Installer.cs:138` под `#if ALLOW_DEV_KEYS`, а сборка Release без `prod`-ключа останавливается целью `RequireProdKey` (`Xp.Launcher.csproj` ~:43). Блобы сверяются по размеру и sha256 в `RepoClient.DownloadFileAsync`; откат указателя отсекает `LastSequence`.
- **Пакеты `tar.br`.** `portal/src/Xp.Launcher.Core/PackReader.cs:23-31`: принимаются только обычные файлы с именем-sha256 (`Hashing.IsSha256Hex(e.Name)`), размер сверяется с подписанным манифестом до записи, хэш — после записи (`TrustException`). Путь на диске строится из sha, не из имени в архиве, так что обход пути невозможен. Ссылки и каталоги внутри пака отвергаются.
- **Пак «сайта по требованию»** (`LazyPacks`, 8100d20b5): его хэш приходит от сайта, но каждый блоб внутри сверяется с подписанным манифестом (комментарий к `LazyPackFor` в `Updater.cs`) — подмена пака не даёт подмены файла.
- **Самообновление.** `SelfUpdate.PrepareAsync` -> `LauncherRelease.FetchAsync` проверяет каждый файл по подписанному манифесту; `Apply` передаёт в Bootstrapper пары `--file/--sha`, и тот перепроверяет копию перед `File.Move` (`Xp.Bootstrapper/Program.cs`, цикл подмены в `Run`: `Hashing.FileSha256(dst + ".xp-new") != want`). Это закрывает пункт 11 прошлого аудита. Остаётся допуск для старых лаунчеров: без `--sha` Bootstrapper работает «unchecked»; для текущей цепочки не опасно, допуск можно убрать через несколько версий.
- **Lua-моды с сайта.** Отдельного пути «скачать мод с сайта» в лаунчере нет: моды каталога едут в подписанном выпуске игры в `user/mods/cm-<id>/` (проверка `ManifestValidator.cs:111-120`: `CatalogFolderPrefix`, `SafePath.IsValid`, отзыв и поставка одной папки одновременно запрещены). `InstallPolicy.WhyProtected` не даёт выпуску писать в `user/` кроме `user/mods/<мод>/`. Лаунчер Lua не исполняет (`LuaMods.cs:19-20`), включает мод только записью в options.cfg. Выход за папку при распаковке отсекается `SafePath.Resolve`; симлинки в авторских модах режет `LuaSubmit.Walk` (`ReparsePoint` -> ошибка `path_link`).
- **Отправка Lua-мода автором** (`LuaSubmit.cs`): `Pack` собирает zip только из списка проверенных файлов; движок для проверки запускается как `game.exe -modcheck <папка> <отчёт>` с лимитом 120 с через `ArgumentList` (без склейки строки), код мода не выполняется.

### Headless, TalkHook, задания
- **Headless** (`Headless.cs`): `--game`, `--repo`, `--channel`, `--profiles` — локальные ключи, ничего не исполняют из данных; `--repo` меняет адрес, но подпись проверяется встроенными ключами. Опасных команд нет (см. #9 о токене и о лишних инструментах).
- **TalkHook** (`TalkHook.cs`): слушает только пока игрок в комнате или назначает кнопку; ничего не записывает и не логирует, кроме сравнения с выбранной клавишей; всегда зовёт `CallNextHookEx`. Портов и процессов не открывает. Для антивирусов это поведение клавиатурного шпиона (глобальный `WH_KEYBOARD_LL`) — полезно помнить при отправках в Defender/Kaspersky. Проблема — только в потоке (#3).
- **Задания проверки** (`ReviewTasks.cs`): лаунчер ничего не запускает по заданию и не передаёт его игре; скачивает только файлы пакета, имена на диске = sha256 (путь из пакета диском не становится), хэш проверяется при записи и при каждом чтении (`PutFile`, `ReadFile`), лимит 200 МБ на пакет, потоковое чтение с обрывом. Данные ответа (`ReviewAnswer.Build`) — только то, что человек тронул: правки строк, вердикты, заметки, без путей и сведений о машине. Единственное замечание — редирект и порт (#2).
- **Протокол xpiratez://** (`UrlProtocol.cs:48`): `"exe" "%1"` в кавычках; `VoiceLink.Parse` принимает только `xpiratez://voice/<id>`, буквы, цифры и дефис до 32 знаков; ссылка лишь выбирает комнату в списке и не входит в неё (`VoicePage.cs` ~:626 -> `OpenChannelAsync(pick, join: false)`).
- **Процессы:** `Process.Start` используется в 6 местах — Bootstrapper (аргументы от самого лаунчера через `ArgumentList`), `GameProcess.Start` (аргументы из локального builds.json), `-modcheck`, `OpenUrl` (#8). Строк из данных сайта в командную строку нигде не подставляется.
- **TLS:** переопределения проверки сертификатов нет (grep по `ServerCertificateCustomValidationCallback`, `DangerousAcceptAnyServerCertificateValidator`, `RemoteCertificateValidation` по `portal/src` -> 0 совпадений в коде лаунчера).
- **Секреты:** в коде и конфигурации токенов/ключей бота нет; публичные ключи подписи в `portal/keys/release-keys.txt` (`dev` и `prod`), закрытые `*.key` в `portal/.gitignore`. В журналы токен не пишется (grep по `log.*Token`). Адрес LiveKit из ответа сайта передаётся в SDK без проверки схемы (`VoiceSession.cs:676`) — доверие к своему сайту, замечанием не вынесено.

### Что внутри 36,8 МБ exe

- Lua-справочник `Xp.Launcher.Core/Docs/lua_api.*` = 310 131 Б встроен в Core, а значит и в Bootstrapper (`EmbeddedResource`; тримминг ресурсы не режет): установщик, который качает каждый новичок, несёт 0,3 МБ документации к Lua.

### Что можно убрать (по убыванию выгоды игрокам)

1. **Голос по запросу** (#5 б): -25,4 МБ (31 %) на установке и самообновлении у тех, кто голосом не пользуется. До голоса набор весил 36,8 МиБ (size-audit 26.10), с голосом 77,0 МиБ. Цена 8-12 ч, меняет модель установки.
2. **Пак «с нуля» для установки** (#5 а): 80,7 МБ -> около 20 МБ у нового игрока (оценка по замеру 27.10: 76,9 -> 15,0). 5-8 ч. Не меняет состав файлов.
3. **Настройки Ilc** (#6): 3,5-5,5 МБ из exe, то есть и из каждого пака обновления (оценка; нужна пробная сборка). 1-2 ч. Самая дешёвая правка в списке.
4. **Картинки героя и установки**: 2,24 МБ jpg в каждом exe. Можно оставить в exe одну `hero_*` и по минимуму `setup_*`, остальные грузить файлами из выпуска (подписанными). Выигрыш 0,5-1,0 МБ на каждое обновление лаунчера, цена 3-4 ч; приоритет после п. 1-3.
5. **Lua-документация только в лаунчер**: убрать `Docs/*` из Bootstrapper (перенос `EmbeddedResource` в Xp.Launcher): -0,3 МБ на каждом установщике. 0,5 ч.
6. **Одинаковые паки лаунчера** (#11): серверная экономия около 410 МиБ (оценка).
7. **Дельта вместо цельного exe** не предлагаю: NativeAOT-код сдвигается целиком, дельта даст мало; не проверено.

Размер обновления лаунчера (замерено): пак 0.5.0/0.5.1/0.5.2 -> 0.5.3 = 16 038 886 Б при 43 795 968 Б сырых (exe + bootstrap; Skia, HarfBuzz, livekit, sodium, xpaudio не меняются и берутся из папки: `reuseFrom: AppDir`).
