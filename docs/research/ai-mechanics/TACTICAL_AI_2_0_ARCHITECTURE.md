## 0. Коротко

- **Слабость штатного ИИ — уровень стороны, а не формулы.** Знание у стороны общее, а решает каждый юнит сам, по своему
  броску режима. Общего плана, приказа и проверки исполнения в движке нет.
- **Четыре уровня — один модуль «командир хода стороны»:**
  - A — анализатор обстановки;
  - B — командир: задача стороны;
  - C — планировщик отряда: роли;
  - D — исполнитель: приказ и проверка на каждой активации юнита.
- **Где живёт:**
  - план строится в начале хода врага и пересчитывается только при значимом событии;
  - приказ подменяет решение юнита **после** его собственного `think()`. Поэтому решение D0 всегда есть как запасное, а
    поток ГСЧ до первой подмены совпадает с D0;
  - результат каждого действия читается, когда очередь состояний этого юнита опустела.
- **Честность:** только то, что сторона знает по правилам: `turnsSinceSpotted`, место и направление из памяти стороны
  (`getAiSeen`), тип юнита и броня по рулсету. Здоровье, ОВ, мораль и порог реакции бойцов игрока не читаются.
- **Безопасность:**
  - выключенный командир побайтно повторяет D0;
  - любая непройденная проверка возвращает решение D0;
  - в плане нет ГСЧ;
  - бюджет считается числом операций, а не временем, чтобы не ломать детерминизм.
- **Первая тактика — STRIKE-V0.** Сосредоточенный удар по известной цели силами тех, кто законно может по ней
  стрелять со своей клетки, но по своему броску режима не атакует. Почему именно она — в документе сценариев, §6.

## 1. Почему штатный ИИ не действует организованно

Все числа — из уже сыгранных боёв. Набор — 24 сценария × 2 сида, D0, если не сказано иное.

| что мешает | данные | источник |
|---|---|---|
| **Решает юнит, а не сторона.** Знание общее (`getTurnsSinceSpottedByFaction`), но действует по нему только тот, кому так выпал режим | после контакта 63 % решений — патруль; разведчик идёт к случайному узлу карты (`getPatrolNode`, `compliantNodes[RNG]`) | COMMANDER-DESIGN §2 |
| **Законный выстрел не делается.** Юнит со своей клетки может стрелять по известной пехотинке, по которой могут стрелять ещё двое, но за весь ход не атакует никого | 746 из 1937 юнит-ходов (38,5 %). Первый режим хода: побег 273, патруль 235, бой 161, засада 77 | `cm/tai2/focus2_scpa_D.txt` |
| **Режим — бросок кубика с инерцией.** ESCAPE, выпавший на ходу 1, держится, пока нет причины его пересчитать | лидер 1000057 в M3 s1: выстрел с оценкой 337 был в его вариантах, сделал 4 шага побега и ни одной атаки | TACTICAL_BATTLE_EXPERIMENT_M3_RESULT §1 |
| **В бой приходят по одному** | 36 % павших врагов ни разу не атаковали; 40 % погибли без союзника в 5 клетках; 416 — сразу после патрульной ходьбы; 496 — в собственный ход, от реакции бойцов | COMMANDER-DESIGN §2 |
| **Оружие часто не пробивает броню** | из 3333 атакующих юнит-ходов урон бойцу игрока нанесли 554 (17 %); 514 выстрелов без прямого урона, полезная альтернатива — в 2,1 % | `cm/tai2/useful_scpa_D.txt`, AI_ACTION_SELECTION_RESULT |
| **Нет исполнения нескольких юнитов** | юниты ходят по очереди; не больше двух активаций по два действия; очереди намерений нет, есть только очередь анимаций текущего действия | SIDE_TURN_ACTION_SCHEDULER_DESIGN §1 |
| **Реакционный огонь на стороне игрока** | реагирует тот, чей счёт `реакция × ОВ / макс. ОВ` не меньше счёта действующего. Прикрытие врага не выстрелило ни разу из 36 | SIDE_TURN_SCHEDULER_STAGE3_RESULT |

Главный вывод для архитектуры: **добавить ещё юнитов в бой мало.** Это уже пробовали: B24 HUNT, STAGE_RALLY, CE, TD
APPROACH. Пришедшие в основном стреляют без урона. Командир должен распоряжаться **законными и действенными** действиями
и проверять каждое после исполнения.

## 3. Схема четырёх уровней

```
SavedBattleGame::endTurn → ход врага
 └─ первая активация хода (T3, AiProbe::passStartNote)
     A  Situation::build      силы стороны, контакты по честному знанию, матрица «кто чем кого может»
     B  Commander::choose     задачи стороны на этот ход (в V0 — только STRIKE)
     C  Squad::assign         роли и приказы с предусловиями
 └─ каждая активация юнита (handleAI)
     unit->think(&action)     решение D0 — всегда считается первым
     D  Executor::onDecision  есть приказ и все проверки прошли → действие приказа; иначе действие D0
     … состояния: ходьба / выстрел / реакция игрока / взрывы …
 └─ popState: очередь юнита опустела
     D  Executor::onResult    что вышло: урон, гибель, реакция, ОВ → журнал
     A  Situation::update     значимое событие → пометить устаревшие строки матрицы
     B/C коррекция             цель выбыла / цель развернулась / стрелок ранен → переназначить или отпустить к D0
 └─ BattlescapeGame::endTurn (T5): план стёрт; на следующем ходу врага строится заново
```

Почему подмена идёт **после** `think()`, а не вместо него:
- поток ГСЧ и всё внутреннее состояние AIModule до первой подмены такие же, как в D0. Значит, A/B сравнение честное;
- решение D0 всегда под рукой как запасное;
- закрытые эксперименты STAGE 2 и COUNTERFIRE уже проверили эту точку на нашем дереве.

Где код (план реализации, сейчас не пишется):
- новый модуль `Battlescape/AiCommand.{h,cpp}` по шаблону `AiProbe`: в выпуске заглушки, на стенде флаг окружения;
- состояние хода — член `BattlescapeGame`, как `_AISecondMove`, сбрасывается в T5;
- три вызова: T3 (построить), `handleAI` после `think` (подменить), `popState` при `noActionsPending` (результат);
- выбор очерёдности (T1) — только если задаче нужна последовательность. STRIKE-V0 её не трогает.

## 4. Уровень A — анализатор обстановки

### 4.1 Что он собирает

| блок | содержимое | откуда |
|---|---|---|
| свои силы | юнит, клетка, направление, ОВ, здоровье, мораль, режим ИИ, оружие и патроны в руках, встроенное оружие, размер, `sniper`, `spotter`, `aggression`, `intelligence`, Leeroy | свои юниты — знание стороны о себе |
| контакты | юнит игрока, `since = turnsSinceSpotted`, место и направление из `getAiSeen`, тип (пехота или техника по размеру и броне), броня по рулсету по сторонам | память стороны |
| достоверность | `since == 0` — видим в этом ходу, направление свежее; `since ≤ интеллект юнита` — место из памяти, направление старое; иначе контакт этому юниту неизвестен | правило движка |
| матрица действенности | для пары «свой юнит × контакт»: лучший режим прямого огня с текущей клетки, ожидаемый урон по `fireModeEffect`, ОВ, линия огня | правила плюс штатная проверка линии огня |
| опасные направления | для каждого контакта с `since == 0` — сектор обзора по известному направлению и дальность обзора (в Пиратках 40) | направление из памяти стороны |
| задача миссии | тип миссии из рулсета: оборона базы — разрушение модулей; террор — гражданские; иначе — уничтожение | рулсет миссии |

Укрытия и пути считаются **по требованию задачи**, а не для всей карты. STRIKE-V0 их не использует.

### 4.2 Граница знания

| можно | нельзя |
|---|---|
| свои юниты целиком | здоровье, ОВ, оглушение, мораль, раны бойцов игрока |
| `turnsSinceSpotted` по своей стороне | позиции юнитов, которых сторона не видела или забыла (`since > интеллект`) |
| место и направление из `getAiSeen` | текущая клетка и направление вместо запомненных |
| тип юнита и броня по рулсету (видно по спрайту) | `seenby`, то есть кто из игроков видит врага |
| линия огня и стоимость — штатные проверки движка, как у D0 | запас реакции и счёт реакции бойцов игрока |
| `isCheating()` после `cheatTurn` — правило движка | карта видимости игрока |

Каждый приказ пишет в журнал поля знания, которыми пользовался (`[TACFAIR]`). Тест проверяет, что среди них нет полей
из правого столбца.

### 4.3 Когда пересчитывать

- **Полностью** — один раз в начале хода врага.
- **Частично** — только при значимом событии:
  - юнит выбыл (свой или чужой);
  - сторона заметила новый контакт;
  - контакт развернулся после реакции;
  - свой юнит сдвинулся или потратил ОВ.

  Пересчитываются только строки матрицы этого юнита или столбец этого контакта.
- **Кэш** — ключ «клетка стрелка, место цели, направление цели, оружие, ОВ». Линия огня из той же клетки в ту же клетку
  за ход не пересчитывается: за ход врага бойцы не ходят.

## 5. Уровень B — командир

Задача выбирается на ход стороны для контакта или группы контактов. Одновременно не больше одной задачи на контакт.
Юнит участвует не больше чем в одной задаче. Остальные ходят как D0.

| задача | условия выбора | ожидаемая польза | силы | ограничения | отмена | завершение | статус |
|---|---|---|---|---|---|---|---|
| **STRIKE** (сосредоточенный удар) | известный контакт E, по которому ≥ 2 своих имеют с текущей клетки законный выстрел с ожидаемым уроном ≥ 0,5 HP | больше выстрелов с уроном по одной цели, выше шанс вывести её из строя в этом ходу | 2+ «способных» | только прямой огонь; только юниты, не выбравшие свою атаку | E выбыл, забыт или стал недосягаем | ход кончился или у способных нет ОВ | **первая, V0** |
| FLANK (по слабой стороне) | контакт, чью лобовую броню оружие не пробивает, а бортовую или кормовую пробивает; есть достижимая за ход клетка с этой стороной и ОВ на выстрел | урон там, где с фронта его нет | специалист по тяжёлой цели | путь под реакцией | после реакции цель развернулась, сторона закрыта | выстрел сделан | после STRIKE; данных мало (сценарии §4) |
| WITHDRAW (отход из-под непробиваемого) | способных против контакта 0, свой юнит в его известном секторе | меньше своих потерь от реакции | любые | **не запрещать полезные атаки** | появилась действенная атака | юнит вне сектора | по выжившим потерям игрока не сдвигает (§1, P0/P1) |
| HOLD (держать) | задача миссии требует места (оборона базы, объект) | цель миссии | охрана | ожидание только при перспективе удара | — | — | движок уже частично делает (охрана) |
| REGROUP | силы рассыпаны, способных у контакта < 2, а в 1 ход набирается ≥ 2 | следующий ход — STRIKE | — | **не сбор в точке**: только если удар на следующем ходу законен | контакт забыт | — | закрыт как STAGE_RALLY, нужен новый довод |
| AMBUSH | известное направление движения игрока | первый выстрел на своём ходу | — | реакция из засады не проходит по счёту (§1) | — | — | блокирован правилом реакции |
| BREACH | контакт за стеной, линии огня нет ни из одной досягаемой клетки, есть оружие с уроном по клеткам | открыть линию огня | взрывчатка или тяжёлое оружие | только броня клетки по рулсету | — | клетка разрушена | вне обороны базы кода нет |
| SEARCH | контакт забыт, задача миссии — уничтожение | вернуть контакт | разведчики | не гнать одиночек под реакцию | — | контакт найден | движок частично делает (патруль) |
| ATTACK (общий натиск) | несколько STRIKE подряд за несколько ходов | — | — | **не самоубийственный штурм**: в каждом ходу только законные действенные действия | — | — | надстройка над STRIKE |

Правило против самоубийственного штурма: задача не даёт юниту действия, которого нет в списке законных
действий движка, и не посылает его в атаку без ожидаемого урона по правилам.

## 6. Уровень C — роли

**Механики командования у врага в OXCE нет.**
- Ранг (0 командир, 1 лидер, …) влияет только на узлы появления.
- Мораль стороны врага зависит от числа живых, а не от ранга.
- Потеря морали при гибели — параметр юнита `moraleLossWhenKilled`.

Поэтому «командир» — это модуль, а не юнит. Придумывать бонусы за лидера нельзя.

| роль | чем определяется (по правилам и рулсету) | что делает | в V0 |
|---|---|---|---|
| ударный (STRIKER) | есть законный выстрел по цели задачи с ожидаемым уроном ≥ 0,5 HP по `fireModeEffect` | стреляет по цели задачи | **да** |
| специалист по тяжёлой цели | оружие, которое пробивает броню техники хоть с одной стороны | FLANK | нет |
| стрелок поддержки | `sniper > 0`, оружие с дальним прицельным | стреляет по цели наводчика | нет; штатный `sniperAction` уже есть |
| разведчик | `spotter ≥ 1`, обзор | держит цель видимой для снайперов | нет |
| штурмовик | ближнее оружие, Leeroy | ближний бой при досягаемости | нет |
| прикрытие | остаток ОВ на выстрел реакции | — | **нет**: счёт реакции врага проигрывает (§1) |
| резерв | всё остальное | ход D0 | **да**: все неназначенные |

Перегруппировка в ходе:
- роль пересчитывается при каждом решении юнита;
- погибла цель → ударный переходит на следующую цель задачи или отпускается к D0;
- ранен ниже 2/3 HP → отпускается к D0 (там штатный побег);
- **роль без исполнимого приказа не назначается** — урок TD V1: прикрытие назначено 45 раз, занято 3.

## 7. Уровень D — исполнитель

Главный уровень. Цикл на каждой активации юнита, в `handleAI` после `think()`:

| шаг | что делается | где |
|---|---|---|
| ПЛАН | у юнита есть приказ из C (роль и цель) | состояние хода |
| ПРИКАЗ | собственное решение юнита — не атака (ходьба, патруль, побег без причины, засада, пустое) | после `think()` |
| ПРОВЕРКА | цель жива и в сознании; известна стороне; место и направление по памяти стороны; линия огня из текущей клетки (`canTargetUnit`); ОВ ≥ стоимости; есть патрон; ожидаемый урон ≥ 0,5 HP при **текущем** известном направлении цели; юнит не паникует, HP ≥ 2/3, не цель миссии | `canTargetUnit`, `getActionTUs`, `getAmmoForAction`, `fireModeEffect` |
| ИСПОЛНЕНИЕ | действие D0 заменяется выстрелом приказа; дальше обычная очередь состояний | `handleAI` |
| РЕЗУЛЬТАТ | очередь юнита опустела: урон по цели, выбыла ли она, была ли реакция, сколько стрелок потерял HP, остаток ОВ | `popState`, `noActionsPending` |
| КОРРЕКЦИЯ | цель выбыла — новая цель задачи; цель развернулась — пересчитать сторону брони; стрелок ранен — отпустить; ОВ кончились — `dontReselect` как у D0 | A + C |

Что исполнитель **не** делает:
- не отменяет собственную атаку юнита: ни одной, это правило;
- не ставит «стоять» вместо D0 при провале проверки — возвращается решение D0;
- не выбирает клетку по неполной формуле: в V0 шагов нет;
- не держит юнита в ожидании;
- не тратит ГСЧ.

Защиты:
- не больше 4 приказов на юнит-ход;
- после приказа, который не потратил ОВ, юнит отпускается до конца хода;
- проверка, не прошедшая два раза подряд у одного юнита, снимает его роль.

## 8. Общая модель состояния и приказов

```cpp
struct Contact {            // A: только знание стороны
    int unitId;             // юнит игрока
    int since;              // turnsSinceSpotted для FACTION_HOSTILE
    Position seenPos;       // getAiSeen
    int seenDir;            // getAiSeen; свежий только при since == 0
    bool vehicle;           // размер брони 2 / тип по рулсету
};
struct Capability {         // A: строка матрицы «свой × контакт»
    int shooterId, contactId;
    BattleActionType mode;  // лучший прямой огонь с текущей клетки
    int tuCost; double expDamage; bool lof;
    uint64_t key;           // клетка стрелка, место и направление цели, оружие, ОВ — для кэша
};
enum class TaskKind { Strike /*V0*/, Flank, Withdraw, Hold, Regroup, Ambush, Breach, Search };
struct Task {               // B
    TaskKind kind; int contactId;
    std::vector<int> members;
    int created;            // номер хода; задачи живут один ход (V0)
    enum { Active, Done, Cancelled } state; const char *why;
};
struct Order {              // C → D
    int unitId; int taskIdx; BattleActionType mode; int targetId;
    int issued, executed, cancelled; const char *lastCancel;
};
struct SideTurnPlan {       // всё состояние; живёт ход врага, в сейв не пишется
    int turn; std::vector<Contact> contacts; std::vector<Capability> cap;
    std::vector<Task> tasks; std::map<int, Order> orders; uint32_t opsUsed, opsBudget;
};
```

Журнал: `[TACPLAN]`, `[TACORDER]`, `[TACCHECK]`, `[TACRESULT]`, `[TACCANCEL]`, `[TACFAIR]`, `[TACTIME]`. Каждая
строка самодостаточна, чтобы цепочку «проблема → решение → что исполнилось → польза» можно было собрать из лога.

## 9. Требования

### 9.1 Детерминизм

- В плане нет ГСЧ. Обход — по возрастанию id юнита. Равенство оценок решает меньший id.
- `think()` вызывается всегда, поэтому расход ГСЧ до первой подмены совпадает с D0.
- Бюджет — число операций (проверок линии огня и вызовов `fireModeEffect`), а не миллисекунды. Время зависит от машины,
  а решение от него зависеть не должно.
- Проверка: один бой дважды — побайтно одинаковые журналы.

### 9.2 Сохранение

- План одного хода в сейв не пишется. Сейв посреди хода ИИ и так начинает ход врага заново с сохранёнными ОВ
  (KNOWN-ISSUE-SAVE-MID-AI-TURN). План строится заново из текущего положения, а приказы проверяются по нему же.
- Задачи на несколько ходов (REGROUP, AMBUSH) потребуют записи в `AIModule::save` (`AIModule.cpp:614`) с ключом версии.
  До них V0 сейв не меняет.
- Проверка: сейв в начале хода игрока после хода с приказами → загрузка → бой идёт, падений нет.

### 9.3 Честное знание

- Граница — §4.2. Аудит — `[TACFAIR]` и тест, который ищет запрещённые поля.
- Линия огня считается движком по настоящей карте — так же, как у D0. Это не подсказка, а штатная проверка возможности
  выстрела.

### 9.4 Запасной путь

- Флаг выключен — побайтно D0. Проверка: 48/48 боёв совпадают.
- Флаг включён, а задач нет — решения те же, что у D0.
- Любая непройденная проверка → действие D0. Исчерпан бюджет операций → командир молчит до конца хода.
- Код командира не может отменить атаку, панику, берсерка, цель миссии и действие юнита под контролем игрока.

### 9.5 Производительность

- Только процессор. Видеокарта — только при измеренном узком месте, сейчас его нет.
- Дорогое — линия огня. STRIKE-V0 проверяет её только из текущей клетки стрелка до запомненного места цели, с кэшем на
  ход. Поиска клеток нет.
- Горизонт — один ход стороны.
- Измерено ранее: выбор следующего юнита в Scheduler V1 — 49 мкс; ход стенда — 4,15 с при 24 боях параллельно; проверки
  линии огня в TD V1 подняли L2 с 57 до 83–97 с.
- Своих цифр у STRIKE-V0 пока нет: они будут измерены `[TACTIME]` на функциональном шаге. Допуск — в плане реализации.

## 10. Чего архитектура не повторяет

| запрещено | как устроено здесь |
|---|---|
| сбор в точке | шагов к точке сбора нет; REGROUP только с законным ударом на следующем ходу |
| перестановка порядка без результата | порядок D0 не трогается; T1 — только если задаче нужна последовательность |
| роли без исполнения | роль даётся только вместе с исполнимым сейчас приказом |
| ожидание без перспективы удара | приказа «ждать» в V0 нет |
| «лучшая клетка» по неполной формуле | в V0 клеток нет; позже клетка — только из `findReachable` с проверкой линии огня и стороны брони |
| запрет полезных атак | собственная атака юнита не отменяется никогда |
| T1/T2 (выбор цели по коэффициентам) | атакующих не перенацеливаем; приказ получают только **не атакующие** юниты |

## 11. Побочное (в бэклог, веток не открывать)

- 13 ОВ на сорванное взведение гранаты — из COUNTERFIRE_V0_CLOSED, без изменений.
- 161 юнит-ход в режиме боя с законным выстрелом с места без атаки за ход. Возможно, ход к точке огня обрывается
  обнаружением. Причину не разбирал.
- `fireModeEffect` не оценивает взрывчатку (−1 для `area`). Для BREACH и FLANK с гранатомётами понадобится отдельная
  оценка.
