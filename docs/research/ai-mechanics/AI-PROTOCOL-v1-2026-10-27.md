# Протокол сравнения кандидатов ИИ, версия 1

27.10.2026. Закрепляется **до** проверки следующего кандидата.

Решение Vitali от 27.10:

- HP — основная метрика;
- гибель — показатель безопасности;
- анализ кластеризован по сценариям;
- старые результаты задним числом не переписываются.

Основа — этап 1 (`AUDIT-STAGE-1-BENCHMARK-DESIGN.md`, разделы 9.2, 9.3 и 9.6). Где этот протокол с ним
расходится, главнее этот.

## 1. Что сравнивается

| | |
|---|---|
| плечо A, эталон | стенд, бот штатный, BetterAI-исправления врага включены (`OXCE_AI_OXCE_FIXES=1`, «FX») |
| плечо B, кандидат | A и флаг кандидата; больше ничего не меняется |
| сборка | **одна** DEV-сборка на оба плеча; хэш exe пишется в каждую запись |
| пара | один сценарий, один сид, оба плеча |
| сторона кандидата | **только враг**. Флаг кандидата бота не трогает, это проверяется до боёв (раздел 6, шаг 1) |

Почему эталон FX, а не чистый OXCE: под стендом шесть исправлений включены всегда (`P1-SIDES-REPORT.md`, раздел 7).
Чистый OXCE игрока стенд сейчас не воспроизводит, а FX — воспроизводит. Вопрос «включать ли BetterAI по умолчанию»
(FX против OXCE) — отдельное сравнение, для него нужен П-1.

**Перенос на игрока.** Код решений стенда и выпуска пока не доказан одинаковым (этап 0В). Поэтому кандидат, прошедший
протокол, идёт к игрокам только в общем коде обеих сборок, с проверкой IDENTICAL при выключенном флаге.

## 2. Сценарии и сиды

**Сценарии.** 24 сценария, которые можно сыграть сейчас: средняя и поздняя стадии, M1–M12 и L1–L12 этапа 1.

- Стадии по решению Vitali: средняя 12–47, поздняя 48+.
- Отряды: средняя — PeasGray (мес. 20), RedCatZ (45), стрим (46) по кругу; поздняя — GoldGalZ (60), NoCodexCatZ (62),
  NoCodexManZ (108) по кругу.
- Месяц 108 (NoCodexManZ) входит в оценку и отдельно показывается своим слоем.
- Расы — `P6-RACES.tsv`, M4 — `STR_SECTOID_NONCOM` (`P6-RACES.md`).
- Ранняя стадия (E1–E12) ждёт сейва (П-2) и в версию 1 не входит.

**Сиды:** `2 000 000 + 1000·i + k` (раздел 9.7 этапа 1), одни и те же в обоих плечах.

**Объём** записывается в файл регистрации когорты до первого боя и потом не меняется. По умолчанию — 24 × 20 = 480
пар. Промежуточных просмотров эффекта нет.

## 3. Метрики

| роль | метрика | эффект кандидата | значимая величина |
|---|---|---|---|
| **основная** | `phplost` — HP, потерянные бойцами игрока за бой | B / A − 1 (отношение средних) | **+10%** |
| **безопасность** | `pdead` — погибшие бойцы игрока за бой | B − A | граница ухудшения **−0,05** на бой |
| описательные | исход, ходы, тайм-ауты, убитые враги, атаки врага, время хода врага (медиана, p99), падения | — | — |

Знак: «лучше» — значит враг сильнее. Бойцы теряют больше HP и гибнут не реже.

## 4. Анализ

1. В каждой паре — разность B − A.
2. По каждому сценарию — среднее по сидам.
3. Оценка: стадии с равным весом, внутри стадии сценарии с равным весом. Для HP — отношение взвешенных средних
   B и A.
4. 95% ДИ — двухуровневый бутстрап, стратифицированный по стадии:
   - сценарии внутри стадии берутся с возвращением;
   - сиды внутри сценария берутся с возвращением, пара остаётся парой;
   - 10 000 повторов, квантили 2,5% и 97,5%, зерно закреплено.
5. Для сверки — t по средним сценариев с S − 1 степенями свободы.
6. **По боям не считается никогда.** Сиды как независимые наблюдения дают 17–22% ложных «улучшений»
   (`POWER-CLUSTER-2026-10-27.md`).

Основная гипотеза одна, поэтому ДИ 95% без поправки на две метрики. Гибель — проверка безопасности, а не вторая
гипотеза успеха.

## 5. Как читать итог

Вердикт выносится по первой подходящей строке сверху.

| вердикт | условие |
|---|---|
| **отклонён: безопасность** | ДИ гибели целиком ниже нуля **и** оценка гибели ≤ −0,05 на бой |
| **отклонён: крупная регрессия** | в какой-то группе фракций (раздел 9.3 этапа 1) ДИ целиком ниже нуля **и** оценка ≤ −10% HP или ≤ −0,10 погибшего |
| **вред** | ДИ HP целиком ниже нуля |
| **подтверждённое улучшение** | ДИ HP выше нуля **и** оценка HP ≥ +10% |
| **улучшение есть, меньше значимого** | ДИ HP выше нуля, оценка < +10% |
| **значимой пользы нет** | ДИ HP целиком ниже +10% и не выше нуля |
| **не решено** | всё прочее: ДИ захватывает и ноль, и +10% |

Правила чтения:

- **Отсутствие значимости — не доказательство отсутствия пользы.** «Значимой пользы нет» говорится только тогда,
  когда ДИ исключает +10%. При «не решено» так и пишется, с ДИ.
- При истинном эффекте ровно на пороге строка «подтверждённое улучшение» выпадает примерно в половине случаев. Это
  свойство правила, а не невезение когорты.
- Фракции и стадии описательны: оценка и 95% ДИ по каждой группе, без вывода «подтверждено по группе». Исключение —
  правило крупной регрессии.
- Исключения и сбои — по разделу 9.6 этапа 1. Любое падение в плече B останавливает когорту до разбора.
- Решение о выпуске принимает Vitali по вердикту. Вердикт сам кандидата не включает.

## 6. Порядок для каждого кандидата

1. **Корректность без боёв.**
   - Сборки DEV и релиз собираются.
   - С выключенным флагом код решений прежний: диф показывает только ветки под флагом, в релизе — заглушки.
   - Флаг читается только для врага.
2. **Корректность поведения — малая проверка на станции,** по отдельному разрешению.
   - Короткая серия по сценариям протокола, 1–2 сида.
   - Журнал показывает, что механизм срабатывает там, где должен, и не срабатывает там, где не должен.
   - Нет падений, зависаний и застреваний.
   - С выключенным флагом бои побайтно те же, что у эталона.
3. **Пилот пользы** — до 2 сидов на сценарий, только чтобы поймать грубый вред. Вердиктом не считается.
4. **Когорта** по этому протоколу — только для кандидата, прошедшего шаги 1–3. Объём записывается заранее.

## 7. Старые результаты

Серии до 27.10 (AI 2.0, фаза 3, лучшая клетка, cp1b) остаются со своими выводами и оговорками:

- стенд до П-1;
- эталон не равен врагу игрока;
- fair22 на месяце 60.

По этому протоколу они не пересчитываются и не переименовываются.
