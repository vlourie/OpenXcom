# BetterAI в выпуске игроков: план (22.10.2026)

Решения Vitali 22.10:
- AI3 в выпуске по умолчанию **выключен**;
- во вкладке HD **первой строкой** — «BetterAI ›», по нажатию свой экран;
- первая строка экрана — общий выключатель, пока он выключен, все строки ниже серые;
- внутри две строки: «Исправления OXCE (О1–О14)» (по умолчанию ДА) и «ИИ AI3 (экспериментально)» (по умолчанию НЕТ).

## Опции

| Опция | По умолчанию | Что |
|---|---|---|
| `oxceBetterAi` | false | общий выключатель; выкл — чистый OXCE, как сейчас |
| `oxceBetterAiFixes` | true | О1–О14 (действует только при общем вкл) |
| `oxceBetterAiAi3` | false | механизмы AI3 без честного знания и бота (только при общем вкл) |

`oxceAi3` убирается: в выпуске она пустая (R-434), а у игроков в `options.cfg` записано `true` — новое имя не
унаследует это значение. В DEV-сборке `play()` читает `oxceBetterAi && oxceBetterAiAi3`.

Значения читаются **один раз при запуске игры** (как `static const` в `AIModule` и `TileEngine`): строки экрана
помечены «после перезапуска», во время боя серые.

## Код игрока (без OXCE_AI_DEV)

Заглушки выпуска `AiProbe.cpp` 77–237 остаются заглушками, кроме перечисленных ниже — они читают снимок опций.
Стенд, журнал, бот, CollapsePilot (R-336) в выпуск не попадают.

**Исправления** (`fixes()` = общий вкл и строка исправлений):

| № | Как включается | Что сделано |
|---|---|---|
| О1 | `escapeSignFix()` | код в `setupEscape` есть |
| О2 | `astarCostFix()` | код в `Pathfinding` есть |
| О3 | `counterFix()`, `counterCheck()`, `counterOwn()` | состояние счётчика переносится в выпуск |
| О4 | `staleEscapeFix()` | код в `think` есть |
| О5 | `stalePatrolNode()`, `staleExact()` = 1 | код в `setupPatrol` есть, `witnessReach` в `Pathfinding` |
| О6 | `upstreamSpot()`, `upstreamVis()`, `upstreamSees()` | код есть (upstream 6ee48e7d1, 613ec4a28) |
| О7 | новое, `SavedBattleGame::getPatrolNode` | узел с рангом юнита предпочитается, среди равных — больше `flags` |
| О8 | новое, `setupPatrol` | узел без пути на остаток попыток помечается занятым, после цикла освобождается |
| О9 | новое, `meleeAction`, `meleeActionLeeroy` | сосед берётся, только если до него достаёт удар (`knownAdjacent`); первый годный не перебивается следующим |
| О10 | новое, `wayPointAction` | пустой список путевых точек — не стрелять |
| О11 | новое, `getNodeOfBestEfficacy` | граница радиуса `<=`, как в `explosiveEfficacy` |
| О12 | новое, оборона базы | комната 10×10, проверка клетки на null |
| О13 | новое, `setupEscape` | выбранное укрытие записывается в `lastCover` |
| О14 | новое, `think` | `_wasHitBy` чистится один раз в начале хода юнита, а не в каждом решении (метка `_wasHitByTurn` в сейв не пишется: после загрузки первое решение чистит, как раньше) |

В DEV-сборке `oxceFixes()` = режим игры (`play()`, где и так включены все clean-исправления) или `OXCE_AI_OXCE_FIXES`
под стендом — прогоны, снятые до О7–О14, решений не меняют.

**Внимание:** AI3 без честного знания стенд не мерил ни разу. Строка помечена «экспериментально».
