  врага (реакция танка 444 на полезную атаку 1000036) приказом не затронута. Исход боя здесь — шум: два варианта B,

## 2. Реализация (шаг 2)

Отдельная копия `scratchpad/bo/tree` = дерево D0 (exe D0 sha `0ff1e0f7…`). Изменены три файла (`cm/bo/bo.diff`):
- `AiProbe.cpp/.h` — функция `battleOrder`;
- `BattlescapeGame.cpp` — одна строка вызова перед `AiProbe::logDecision` в `handleAI`.

Сборка DEV, exe BO, `BUILD_INFO.txt`. Порядок работы:
- think() юнита и весь расход ГСЧ идут как в D0; приказ заменяет только действие, которое будет выполнено.
- Новых маршрутов, поиска клеток, видеокарты и смены очерёдности нет.
- `OXCE_AI_ORDER_FIRE=2:520:1000028=9.8,1000042=8.8,1000055=9.8,1000057=9.9`: на ходу 2 четыре стрелка по очереди своих
  решений стреляют в 520 (9 = прицельный, 8 = навскидку).
- Перед каждым выстрелом проверка в порядке очереди; при провале приказ юнита снимается, дальше решения D0:
  1. цель жива и в строю, иначе `cancel.target_out`;
  2. цель видна стороне в этом ходу, иначе `cancel.target_unknown`;
  3. при честном знании (fairKnowledge) — что сторона знает это место, иначе `cancel.target_place`;
  4. в руке огнестрел, иначе `cancel.no_weapon`;
  5. ОВ хватает, иначе `cancel.no_tu`;
  6. есть патрон, иначе `cancel.no_ammo`;
  7. есть линия огня (`canTargetUnit` из точки выстрела), иначе `cancel.no_lof`.
- `OXCE_AI_ORDER_AVOID=2`: атака по юниту игрока, на которого она по правилам не действует, не выполняется (BA_NONE).
  «Не действует» значит: прямой урон, модификатор брони ≤ 0, нет урона по клетке, дыма и огня. Законный ESCAPE не блокируется.
- Каждое изменение и каждое окончание приказа — строка `[AIORDER]`.

**Дефект первой версии и исправление.** В v1 (запуски 2 и 4, B1/D1) приказ у 1000028 заменил бросок гранаты, но think()
уже снял с него цену взвода (`AIModule::think`, AI_COMBAT: costPrime + 4 ОВ = 13 ОВ). Юнит потерял 13 ОВ за действие,
которого не было, и второй выстрел отменился `no_tu`. В v2 (запуски 5–7) эти ОВ возвращаются, пока приказ в силе,
и снимаются снова, если приказ отменён: путь D0 не меняется, строка `prime=13`. v1 сохранён в `cm/bo/v1/`. B1/D1 вошли
в лимит запусков и приведены в приложении: они хорошо показывают, насколько исход боя чувствителен к мелочам.

## 6. FAIR, ГСЧ, лишние действия

- **FAIR.** В конфигурации D0 fairKnowledge выключен (строк `[AITRACE]` нет). Приказ использует то же знание, что ИИ D0:
  цель видна стороне в этом ходу (`since=0` во всех выстрелах), позиция — текущая позиция замеченного юнита, как у D0
  в этом режиме. Скрытых сведений не подставлено. Проверка `target_place` (знание места) работает только при честном
  знании, здесь неактивна.
- **ГСЧ.** До первого изменённого решения записи совпадают (2011 строк). После — расхождение, оно ожидаемо. Повтор той же
  руки даёт тот же лог целиком (B2 = B, D = B, D1 = B1, A2 = A, C = A).
- **Лишних действий нет.** Каждый выстрел приказа заменяет ровно одно решение D0 того же юнита, счётчик решений n не
  меняется, новых решений не вставлено. Цена выстрела — `BattleActionCost`. Единственная поправка ОВ — возврат взвода
  в v2, который D0 снял за неисполненный бросок.

## 8. Ответы

1. **Сработал ли общий приказ?** Да как механизм: выстрелы исполнены законно, отмены корректны, результат воспроизводим.
   Как совместное действие — частично: стреляли двое из четырёх, цель убил один прицельный выстрел.
2. **Какая часть принесла пользу?** Только концентрация огня, и только на ходу 2 (полезный урон 0 → 29, убийство 520).
   Избегание опасных действий пользы не принесло, потому что в эпизоде нет ни одной подтверждённо бесполезной
   провоцирующей атаки. Потери врага определяет реакция 444 на полезную атаку и самоподрыв 1000053, а их приказ не трогает.
3. **Основания переносить на другие реальные ситуации?** Нет:
   - эффект — одно попадание по раненой цели, которая и так погибла бы от своего танка ходом позже;
   - к ходу игрока 3 выигрыша нет;
   - исход боя полностью во власти шума (B1 против B);
   - один бой, один сид.

   По условию GO результат не считается основанием для V2. **STOP.**

## Побочное (в бэклог, ветку не открывать)

- `AIModule::think` (AI_COMBAT) снимает цену взвода гранаты ещё до исполнения. Если после этого решение меняется
  (блок повторных think() в `handleAI`) или бросок не исполняется, эти ОВ теряются. Нужна проверка, бывает ли такое в D0
  без приказа. Только наблюдение, это не correctness ветки эксперимента.
- `[AIEXEC] dmg` — суммарный урон действия по всем юнитам, а не только по цели (1000036: 129 = 123 по 448 + 6 по 444).
  Разбор по целям учитывает это через HP на начало и конец хода (`fl_plost.py`).
- `fl_tankatt.py` берёт цель из поля `aim` решения. Для выстрелов приказа там старая цель think() (1000028: aim=448 при
  клетке 520), поэтому для рук с приказом нужно смотреть клетку `to`.
