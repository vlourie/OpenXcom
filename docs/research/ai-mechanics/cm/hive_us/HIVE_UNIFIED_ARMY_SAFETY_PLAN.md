# HIVE UNIFIED ARMY SAFETY: план и список запусков

Объявлено 05.11.2026 до первого запуска. Основа: UNIFIED ARMY CONTROL V0, дерево `hive/ua`. Новое дерево `hive/us`, флаг прежний (`OXCE_AI_HIVE`: 0 off, 1 shadow, 2 active).

## Семантика `scout` по исходникам

`AIModule::setupPatrol`, вне `STR_BASE_DEFENSE`:
- `scout=true`, если `isCheating()`, нет `_fromNode`, ранг `_fromNode` равен 0 или на клетке огонь;
- иначе `scout=false`.

`SavedBattleGame::getPatrolNode`:
- `scout=true`: все узлы карты, из подходящих случайный;
- `scout=false`: только связанные с `fromNode` узлы (комментарий движка: «shuffle around to adjacent nodes at most»), без кубика, узел с наибольшими флагами;
- большой юнит при `scout=false` без подходящих узлов сам переходит на `scout=true`.

Свободный выбор в `setupPatrol`: сначала поиск своего вида, и только если он вернул 0, движок ищет другим видом. Отказ по пути (`calculate`) вид поиска не меняет: следующая из 5 попыток.

**Итог:** `scout=false` не запрет на движение и не приказ стоять, а ограничение вида поиска. Движок снимает его только сам и только когда соседних узлов нет.

## Дефект V0

1. Ступени 1 и 3 вызывали `getPatrolNode(mapWide || scout, ...)`, то есть искали по карте при `scout=false` и при наличии соседних узлов.
2. Условие `fit` могло опустошить список у большого юнита и через «move dammit» открыть поиск по карте, хотя без условия соседний узел был.

## Исправление

- Все ступени условия ищут только вычисленным движком видом (`scout`), `mapWide` удалён. Ступеней 3: не посещённые в районе, все в районе, ближе к центру.
- При `fit` ветка большого юнита не срабатывает, она остаётся только свободному выбору.
- Ничего не подошло: свободный выбор движка, включая его собственный переход на другой вид поиска.
- Без `PO_STAND`, `_hiveStand`, HOLD, без списков по ID, COMBAT и ESCAPE не затронуты.

Для бойцов с `scout=true` выбор не меняется: прежние ступени 1 и 3 для них повторяли ступени 0 и 2.

## Журнал и время

Только запись. В `CHOICE`: `scout`, `chosen_linked`, `free_linked`, `from`, `from_rank`. В `[HIVEPERF] phase=turn`: поля на выборе узла, свободный поиск, ступени условия, проверка пути, отказы пути, обновление штаба, наибольшее время одного поля и одного выбора. Оптимизации нет.

## Запуски

На rabota, лимит 8 ходов, одна замороженная сборка, всего 6, новых нет:

| № | Плечо | Сценарий и сид | Для чего |
|---|---|---|---|
| 1 | QN (ON) | M6 s1 | главный сценарий |
| 2 | QN (ON) | M3 s1 | остальные подразделения |
| 3 | QN (ON) | M8 s1 | остальные подразделения, большой юнит |
| 4 | QO (OFF) | M6 s1 | против D0 `cc3_CO_M6_s1` и `ua4_UO_M6_s1` |
| 5 | QS (SHADOW) | M6 s1 | против запуска 4 |
| 6 | QN (ON) | M6 s1 | повтор запуска 1 |

OFF и shadow на M3 и M8 не повторяются: на них нет бюджета. Обоснование: диф `hive/ua → hive/us` на пути OFF не меняет ничего, кроме таймера вокруг `calculate`; проверяется чтением дифа. Базы OFF для сравнения на M3 и M8 — `ua6_UO_M3_s1` и `ua8_UO_M8_s1`.

Если код меняется после запуска, запуск считается устаревшим, бюджет не пополняется.
