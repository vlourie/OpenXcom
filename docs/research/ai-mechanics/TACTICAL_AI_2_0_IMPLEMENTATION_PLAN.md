## 0. Коротко

- **Первая тактика — STRIKE-V0.**
  - Сосредоточенный удар по известной уязвимой цели.
  - Исполнители — юниты, у которых со своей клетки есть законный действенный выстрел, но которые по своему решению
    за ход не атакуют.

## 2. Первый прототип: STRIKE-V0

### 2.1 Цепочка «проблема → решение → что исполнилось → польза»

- **Проблема.** Юнит может со своей клетки законно выстрелить по известной цели, по которой могут стрелять ещё ≥ 2, но
  за ход не атакует. В D0 это 746 юнит-ходов из 1937, из них 433 с оружием, ранившим пехоту в этом бою.
- **Решение.** Командир назначает его ударным по цели задачи. Исполнитель заменяет его не-атакующее решение выстрелом,
  если все проверки прошли.
- **Что исполнилось.** `[TACORDER]` и `[TACRESULT]` по каждому приказу: исполнен или отменён с причиной, сколько ОВ
  потрачено.
- **Польза.** Выстрелы с уроном по бойцам игрока, выбывшие бойцы, цена — свои выбывшие в собственный ход.

### 2.2 Уровни в прототипе

**A — в начале хода врага:**
- контакты — бойцы игрока, известные стороне: `since ≤ интеллект` юнита, место и направление из `getAiSeen`;
- матрица для каждого живого врага, не паникующего, с прямым огнём в руке:
  - лучший режим (aimed, snap или auto) по каждому контакту из текущей клетки;
  - ожидаемый урон по `fireModeEffect`;
  - линия огня `canTargetUnit`;
  - ОВ и патрон;
- «способен» — ожидаемый урон ≥ 0,5 HP при прочих законных условиях (порог тот же, что в ACTION SELECTION).

**B — задача STRIKE:**
- на контакт, у которого ≥ 2 способных;
- фокус-цель — контакт с наибольшим числом способных, при равенстве — с наибольшей суммой ожидаемого урона, затем
  меньший id;
- остальные контакты с ≥ 2 способными — запасные цели в том же порядке.

**C — роли:**
- ударный — способный по фокус-цели или по запасной;
- остальные — резерв, ход D0.

**D — на каждой активации, после `think()`:**
- подмена только если решение юнита не атака (ходьба, патруль, засада, пустое, побег без причины) и все проверки
  архитектуры §7 прошли;
- после действия — запись результата;
- выбыла цель — следующий ударный берёт следующую цель;
- при провале проверки — решение D0.

### 2.3 Не подменяются

- любая собственная атака юнита, пси, бросок, ближний бой;
- паника и берсерк — до `handleAI` они не доходят;
- побег при HP < 2/3, цель миссии (модули базы), юниты под контролем игрока, Leeroy.

### 2.4 Чего нет в V0

Клеток и путей, очерёдности (T1 не трогается), ожидания, гранат и взрывчатки, памяти между ходами, полей в сейве, ГСЧ.

### 2.5 Код (по GO, в изолированной копии дерева D0)

- `Battlescape/AiCommand.{h,cpp}`: в выпуске заглушки, на стенде — `OXCE_AI_TACTICAL=1`.
- `BattlescapeGame.cpp`:
  - вызов в T3 (первая активация хода);
  - вызов после `think` перед `AiProbe::logDecision`;
  - вызов в `popState` при `noActionsPending`;
  - сброс в `endTurn`.
- Оценка — вызов `fireModeEffect` через `AIModule` юнита. Формулы не меняются.

### 3.2 Тактический уровень (те же 48 боёв, что и боевой, окна)

- Окно — ход врага с первым приказом в бою и следующий ход игрока.
- Пара берётся, только если снимок `aistart` этого хода совпал с D0: до первого приказа бой обязан идти как D0.
  Несовпавшие пары называются в отчёте.

| # | метрика | правило |
|---|---|---|
| T1 | юнит-ходы с уроном по бойцам игрока в окне | **главная тактическая**: парная разность, бутстреп по сценариям; PASS — нижняя граница > 0 |
| T2 | выбывшие бойцы игрока в окне | направление, в отчёт |
| T3 | свои выбывшие в собственный ход в окне | цена; FAIL, если рост значим, а T1 не PASS |
| T4 | фокус-цель выбыла в этом ходу | доля против D0 на тех же целях |
| T5 | доля исполненных приказов с уроном | в отчёт; ориентир по архиву — 33 % у способных |

### 3.3 Боевой уровень (48 пар: 24 сценария × 2 сида, сценарий — кластер)

- **Главная метрика:** доля отряда игрока, выбывшая за бой (`pdead + pout`). Парная разность против D0.
  Двухуровневый бутстреп `cm/pair_boot.py`: 10 000 повторов, seed 20261027, стадии M и L с равным весом.
- **PASS:** нижняя граница 95 % ДИ > 0, падений и зависаний 0 из 48, сейв и загрузка 2 из 2.
- **INCONCLUSIVE:** ДИ задевает 0. Подбор на тех же парах запрещён. Новый набор сидов — только по GO.
- **FAIL:** верхняя граница < 0 или нарушение безопасности.
- **Вторичный анализ, заданный заранее:** то же на парах, где доля потерь отряда в D0 строго между 0 и 100 %. Набор
  определяется по одному плечу A до прогона B. Он не заменяет главную метрику.
- **Почему главная метрика может не увидеть эффект:** в P0/P1 28 пар из 48 упёрлись в 0 % или 100 %, различимый эффект
  ±4–5 п.п. Верхняя граница STRIKE-V0 по архиву — около +93…+140 юнит-ходов с уроном на 48 боёв при 554 у D0 (грубый
  признак). В потерях это, вероятно, меньше 4 п.п.

## 8. Ответы на шесть вопросов

**1. Что мешает текущему ИИ действовать организованно?**
- Решает каждый юнит сам, по броску режима с инерцией, хотя знание у стороны общее.
- В D0 38,5 % юнитов, у которых со своей клетки есть законный выстрел по известной цели, за ход не атакуют никого:
  побег без причины, патруль, засада.
- Плана стороны, приказа и проверки исполнения в движке нет. Юниты ходят по очереди, до двух активаций по два действия.
- Когда до боя доходят, оружие часто не пробивает броню: урон в 554 из 3333 атакующих юнит-ходов.
- Реакционный огонь работает на игрока: счёт реакции свежего бойца выше.

**2. Какие механизмы OXCE можно использовать?**
- Память стороны: `turnsSinceSpotted`, `getAiSeen` с местом и направлением.
- Оценка выстрела по правилам со стороной брони: `fireModeEffect`.
- Проверки движка: линия огня `canTargetUnit`, ОВ, патроны.
- `findReachable` и `findFirePoint`.
- Наводчик и снайпер.
- Точки T1–T6 хода стороны.
- Подмена действия после `think()` — проверена в STAGE 2 и COUNTERFIRE.
- Конец действия в `popState` и журналы стенда с уроном каждого действия.
- Шаблон `AiProbe`: в выпуске заглушка.

**3. Какой минимальный новый компонент нужен для настоящего командования?**
- «Командир хода стороны» `AiCommand`: состояние хода (контакты и матрица действенности), таблица приказов и
  исполнитель в трёх точках:
  - начало хода;
  - после `think()`;
  - конец действия.
- Исполнитель проверяет приказ перед действием, читает результат после и переназначает.
- Командир и роли сначала тонкие: одна задача, одна роль. Сложность растёт задачами, а не переделкой каркаса.

**4. Какая первая реальная тактика?**
STRIKE-V0 — сосредоточенный удар по известной уязвимой цели. Его делают юниты с законным действенным выстрелом со своей
клетки, которые по своему решению не атакуют. Своих атак не трогает, шагов и ожидания нет.

**5. Почему она сделает противника сильнее?**
- Она превращает несделанные законные выстрелы в выстрелы.
- По архиву таких юнит-ходов 746, из них 433 с оружием, которое ранило пехоту в этом бою. У способных урон дают
  33 % атакующих юнит-ходов.
- Верхняя граница — около +93…+140 юнит-ходов с уроном на 48 боёв при 554 у D0. Сосредоточение на одной цели
  переводит урон в выбывших бойцов: в D0 цель падала в том же ходу в 75 случаях из 481.
- Цена — больше своих под реакцией в свой ход. Её меряем отдельно.
- Это оценка сверху по грубому признаку, а не измеренный эффект.

**6. Как доказать это без бесконечных экспериментов?**
- Три уровня с порогами, заданными до прогонов (§3).
- Выключенный командир сверяется с архивом D0, и архив служит плечом A.
- Функциональный шаг — ≤ 12 боёв; тактический и боевой — один общий прогон 48 боёв. Всего около 112 боёв.
- Стоп-правила:
  - FUNCTIONAL FAIL → STOP;
  - INCONCLUSIVE → без подбора на тех же парах;
  - следующий этап — только по GO.
