### 1. state.json 21,7 МБ: многократный разбор в потоке UI, дубль Installed и Cache
- Тип: производительность
- Серьёзность: высокая
- Где: `portal/src/Xp.Launcher.Core/State.cs:118` (`LauncherState.Load`), `:141` (`Save`); вызовы `portal/src/Xp.Launcher/MainWindow.cs:1216, 1338, 1414, 1445, 1550, 1565, 1760`; `Refresh()` `MainWindow.cs:1563`
- Доказательство: настоящий `Пиратки\Dioxine_XPiratez\launcher\state.json` — 21,67 МБ, 75,3 тыс. записей, из них в `Installed` и `Cache` повторяются sha 71,5 тыс. (одни и те же файлы записаны дважды: путь+sha и путь+размер+mtime+sha). `Load` без кэша читает и разбирает файл целиком; `Refresh()` и `Activated` зовут его снова, всё в потоке UI (в Manifest/Core нет `ConfigureAwait(false)`, продолжения возвращаются в UI). На старте загрузка идёт ~4 раза (1216, 1338, 1414/1445 по пути проверки и запуска). Бенчмарк на копии файла: разбор ~0,1–0,25 с на этой машине за вызов, ~65–100 МБ мусора за вызов; на слабом ПК (оценка ×3–4) это 0,5–1 с и заметный GC на каждый заход в окно.
- Что сделать: (а) держать `LauncherState` в памяти и перечитывать только при изменении mtime файла; (б) слить `Installed` и `Cache` в одну запись (путь -> sha, размер, mtime), в сохранённом формате — компактный (бинарный/построчный) вариант; `Kept` и остальные поля оставить в маленьком JSON; (в) `Save` вызывать только при реальном изменении.
- Выигрыш: на диске ~10–11 МБ меньше (из 21,7 при слиянии дубля 71,5 тыс. sha по ~75 байт на запись — посчитано по бенчмарку); время старта −3 разбора из 4 (~0,3–0,75 с на этой машине по замеру, ×3–4 на слабой — оценка); мусор −200–300 МБ за сеанс.
- Риск: выпуск (формат state.json — нужна миграция при загрузке: читать старый, писать новый; откат -> старый лаунчер не прочтёт новый формат; сохранить чтение старого).

## Что проверено и не нашло проблем

- Цепочка доверия обновлений: указатель канала подписан Ed25519 (NSec), в нём sequence против отката (`LastSequence`), размер и sha манифеста; манифест сверяется с указателем (`RepoClient.cs:81-88`), потом подпись манифеста; блобы — по sha256 с удалением `.part` при несовпадении. `ManifestValidator` отвергает пути вне корня, `SafePath.Validate/Resolve` — обход каталогов, `InstallPolicy` — `launcher/` и `user/` кроме модов. Ни одного пути из сети, который попадал бы в файловую систему без `SafePath`.
- Распаковка пака (`Updater.Unpack`): имена записей проверяются тем же `SafePath`, размер ограничен манифестом.
- Установка через журнал (`transaction.json`, фаза «committed»), одна резервная копия `backup/last`, `Recover()` на старте: прерывание в любой точке приводит либо к откату, либо к завершению.
- SQL: все `ILike` в `Admin/Super`, `Voice`, `Wiki`, `Site/Search.cs` экранируют `%`/`_`/`\` и параметризованы; сырого SQL с конкатенацией нет.
- Авторизация: API билетов (гостевой токен), бота (`X-Bot-Key`, ограничение сетей), устройств (`X-Device-Token`, на сервере хэш), статистики, обзора, голоса — у каждого маршрута своя политика; админ-страницы за ролью; Argon2id, TOTP, rate-limit по IP.
- Секреты: ключи и пароли берутся из окружения/`portal.env`, в репозитории и логах не найдены; `CheckConfig` останавливает запуск при пустых ключах.
- HttpClient: в лаунчере один общий `NewHttpClient` (HTTP/2, бесконечный таймаут отменяется через `CancellationToken`); на сайте — `IHttpClientFactory`. Утечек потоков/клиентов не видно.
