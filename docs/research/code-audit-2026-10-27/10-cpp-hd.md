## Ошибки

### 1. Метрики шрифта `_metrics` ключом по адресу и без сброса
- Тип: ошибка
- Серьёзность: низкая (редко, но тихо)
- Где: `src/Engine/HdUiDraw.cpp:776-783`, `src/Engine/HdUi.h:281`, `src/Engine/HdUi.cpp:1168-1176` (`clearCaches`), `src/Mod/Mod.cpp:3197` (`loadFonts`)
- Доказательство: `std::unordered_map<const Font*, FontMetrics> _metrics;` (HdUi.h:281) заполняется в `HdUi::metrics()` (`auto it = _metrics.find(font); ... ### 4. Куча `pixelMaskArray` на каждую клетку каждый кадр
- Тип: производительность
- Серьёзность: средняя
- Где: `src/Battlescape/Map.cpp:3523-3528` (внутри `viewX/viewY/itZ`, цикл начинается на :3095-3100)
- Доказательство:
  ```
  const int pixelMaskBase[] = { 0, 2, 1, 3 };
  std::vector<int> pixelMaskArray(4 * _k * _k);
  for (int my = 0; my < 2 * _k; ++my)
      for (int mx = 0; mx < 2 * _k; ++mx)
          pixelMaskArray[my * 2 * _k + mx] = pixelMaskBase[(my / _k) * 2 + (mx / _k)];
  SurfaceRaw<int> pixelMask(pixelMaskArray, 2 * _k, 2 * _k);
  ```
  В оригинале (`git show 441cae1b0:src/Battlescape/Map.cpp`, строки 1173-1174) это `int pixelMaskArray[] = { 0, 2, 1, 3 };` на стеке. Блок исполняется для каждой клетки в экране (условие :3119-3120). Маска используется только в ветке `!softVapor` (:3543-3547, :3648-3652), то есть при режимах HD (`getHdMode() != HD_MODE_NEAREST`) она не нужна совсем.

### 5. `HdUi::drawImage`: готовые картинки блендятся одним потоком попиксельно
- Тип: производительность
- Серьёзность: средняя
- Где: `src/Engine/HdUiDraw.cpp:469-489`; вызовы: `HdBattleHud.cpp:1867` (`panelMetal`, всё полотно панели), `:1765` (каждая кнопка), `:1898-1906` (колодцы, рамки), `:1901` (тень предмета), `:1775-1780` (гало, вспышки)
- Доказательство: цикл `for py ... for px ... if (c >> 24) blendPixel(row[px], c, 1.0f);` без HdWorkers, тогда как рядом `fillRoundRect` (:367-372, порог 128 строк) и `shadeRows` (:510-515, порог 64 строки) режутся на `pool.run`. `blendPixel` (:101-111) на непрозрачном пикселе делает деление `(color >> 24) / 255.0f * cov` и сравнение (быстрый путь копирования есть, но через float). Панель боя при k=8: 2560 x 448 = 1,15 млн пикселей, при k=4: 0,29 млн, и `Surface::blit` перерисовывает HUD каждый кадр (Surface.cpp:709-742: `hdMirror()` в каждом `blit`). Это та самая R-009 («Однопоточность в коде не ловится»).
- Что сделать: в `drawImage` при `(y1 - y0) >= 64` резать строки на `pool.run`, как в `shadeRows`; для непрозрачных пикселей писать `row[px] = c | 0xFF000000u` без float. Можно и вовсе класть непрозрачную панель в слой копированием строк.
- Выигрыш: оценка 2-4 нс/пиксель x 1,15 млн = 2,3-4,6 мс (k=8) или 0,6-1,1 мс (k=4) на кадр только на панели, делится на число потоков. Строк: +10
- Риск: нет по механике; кадр: HD-слой UI (не классический k=1; порядок блендинга пикселей не пересекается между строками, результат тот же)

### 6. Растеризация экипажа базы: 960 фигур на основном потоке
- Тип: производительность
- Серьёзность: средняя (затык при первом входе, не покадровый)
- Где: `src/Engine/HdBaseLife.cpp:154-259` (`makeStamps`), вызов `:1164`, константы `:42-48` (`DIRS = 16, PHASES = 6, AA = 4`, ролей 10)
- Доказательство: `raster` — четыре вложенных цикла (S x S x AA x AA) на фигуру, затем (10 ролей x 16 направлений x 6 фаз = 960 штук + ходовые позы научников/инженеров). S = `31 * cell / 128`, при k=8 `cell` 128 → S=31: 961 x 16 x ~7 овалов x ~10 флоп x 960 ≈ 0,9 Гфлоп на одном ядре. Условие повтора `if (stamps.cell == cell) return;` значит перестройка при каждой смене масштаба. В файле нет ни одного `HdWorkers`.
- Что сделать: по `role` (10 задач) на `HdWorkers::run`, фигуры пишут в непересекающиеся срезы `stamps.rgba`.
- Выигрыш: оценка 0,2-1 с затыка на первом входе на базу при k=8 (до 4-5x быстрее на 10+ потоках). Строк: +6
- Риск: нет (цвета те же; порядок независим)
