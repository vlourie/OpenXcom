# Дефект: у TFTD-процедур кадр выстрела совпадает с кадром двуручного хвата

Статус: **записан, не исправляется** (решение Vitali 03.10, ТЗ `docs/HD_UNITS.md`, раздел 12).
Исправление и переснятие эталонных дампов — отдельная задача. HD-юниты рисуются по тем кадрам, которые
движок реально выбирает сейчас.

## Что

`src/Battlescape/UnitSprite.cpp:299-351`, процедура 0 для `_drawingRoutine` 13 (акванавт, обе ветки `_helmet`)
и для всего, что идёт в ветку `else` (14, 15, …):

```
rarm1H = 248;
larm2H = 232;
rarm2H = rarmShoot = 240;
```

У UFO-процедур (`<= 10`) это четыре разных кадра: 232 / 240 / 248 / 256. У TFTD правая рука при выстреле
(`rarmShoot`, `:493`, `:557`) берёт тот же кадр, что двуручный хват без выстрела (`rarm2H`) — при атаке картинка
не меняется.

Тот же дефект описан в апстриме: OpenXcom issue #1491 (16.04.2026, «TFTD: Missing shooting animations + misaligned
weapon sprites», https://github.com/OpenXcom/OpenXcom/issues/1491). По описанию там же ещё два пункта, которые
в нашем форке не проверялись:
- левая рука при выстреле из двуручного должна возвращаться в стойку, а остаётся в двуручной позе;
- смещения оружия `offX/offY` (`UnitSprite.cpp:360-373`) не подходят TFTD-листам — у мутонов для этого
  свои смещения, у TFTD нет.

## Почему не сейчас

Правка меняет классический кадр: режим 0 перестанет совпадать с прежними эталонными дампами, и их придётся
переснимать. Это картинка, не механика, но смешивать её с работой над HD-юнитами нельзя — иначе IDENTICAL
перестанет отличать «сломалось» от «так задумано».

## Когда возьмёмся

1. Сверить с DOS-версией TFTD, какие кадры листа — выстрел, двуручный, одноручный (по issue #1491 и по листам).
2. Проверить два других пункта issue в нашем коде.
3. Правка + переснятие эталонов + контрольный опыт (R-086); дамп каждой из четырёх броней в выстреле.
4. HD-кадры этих листов, если уже нарисованы, проверить на новый выбор кадров.
