Справка для ТЗ на генерацию HD-графики юнитов. Только то, что видно в коде (ветка hd-render, 03.10.2026)

### 2.2 Canvas32::blitScripted — `src/Engine/HdCanvas.cpp:599-816`

1. Скрипт (перекраска, тень, вспышка) выполняется на **базовом 8-битном** кадре.
2. Режим ≥ 1, k ≥ 2 и есть пак нужного размера:
   - скрипт ничего не изменил → HD-кадр как есть;
   - иначе каждый HD-пиксель = цвет cb из палитры × (яркость HD + 2)/(яркость ca + 2) — **скалярно по яркости** (R-030);
   - «плоский» результат (скрипт сам поднял уровень рампы — вспышка): множитель 1 + 0,3·(… − 1) (R-128);
   - HD-пиксель над пустым базовым берёт перекраску ближайшего непустого соседа в окне 3×3; **дальше 1 базового пикселя — без перекраски и без тени**.
3. Режим 2 без пака — xBRZ результата скрипта (smoothBase). Иначе — nearest (BLIT_SCALED).
4. Результат кэшируется в `_smoothScripted` по хэшу (буфер, shade, вывод скрипта): 80 КБ на запись при k = 4.
5. Светового поля HdLight на скриптовом пути **нет** (у террейна — есть, Canvas32::blit `:468-523`).

Скрипт по умолчанию: юнит — `unit.getRecolor new_pixel; add_burn_shade new_pixel burn shade; return new_pixel;` (`BattleUnit.cpp:7124`); предмет — `add_shade` (`src/Savegame/BattleItem.cpp:1604`); пустой контейнер парсится этим же скриптом (`src/Engine/Script.cpp:3872`).
**Следствие:** все юниты и предметы в руке идут через blitScripted. При shade > 0 изменён почти каждый пиксель, и цветность HD-кадра заменяется цветом рампы палитры — от пака остаётся только яркость. Свои цвета пак показывает лишь при shade 0 и без перекраски.

Перекраска групп: лицо, волосы, utile, rank — setRecolor, `BattleUnit.cpp:930-950`.

## Ограничения для ТЗ

1. Кадр — ровно 32×40 базы: в паке k·32 × k·40, при ×4 — 128×160. Опора ступней и высота — как в классике (предмет в руке сдвигается на 22 − standHeight).
2. Альфа — по силуэту оригинала; индекс 0 прозрачен.
3. За силуэт не выходить больше чем на 1 базовый пиксель: дальше нет ни тени, ни перекраски, а за 32k по ширине кадр режет маска клетки (у идущего — колонка клетки).
4. Цвет HD-кадра в бою почти всегда заменяется рампой палитры (тень > 0, перекраска), сохраняется **только яркость**. Значит: яркостный рисунок обязан быть верным; зоны лица, волос, utile и rank — там же, где классические индексы групп (6, 9, 14 …), иначе перекраска ляжет мимо.
5. Тело собирается из частей (торс, ноги, две руки, предмет); порядок наложения меняется по направлению (`UnitSprite.cpp:612-649`); руки и оружие стыкуются по таблицам смещений (`:360-373`) — части рисовать в тех же точках, что оригинал.
6. Кадры смерти без направления (r0: 264 + fallPhase); у больших юнитов (2, 3, 5, 11, 12, 20, 21) анимации падения нет.
7. Номера кадров — по таблицам раздела 1 и по самому листу брони; число кадров в паке = числу кадров набора (r0 — 283, r5 — 160 и т. д.).
8. Большой юнит — 4 части по 32×40 (part 0..3), башня — отдельные кадры с поворотом turretDir.
9. Мод, меняющий картинку кадров, заводит свой набор (R-175).
10. Предмет в руке (HANDOB), трупы (FLOOROB), кукла — отдельные наборы со своими путями.

## Возможности

1. Свой HD-счётчик для промежуточных кадров ходьбы и idle (дыхание, качание) по образцу hoverBob и вариантов `.vN` — без изменения `_animFrame`, walkPhase и интервалов.
2. Плавное смещение между фазами шага (калькуляция смещения уже в `Map.cpp:2918-3013`, только экранная).
