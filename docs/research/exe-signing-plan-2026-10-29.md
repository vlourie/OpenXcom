# Подпись exe: SignPath Foundation, Azure Artifact Signing или Certum — план (29.10.2026)

Только план, правок нет. Повод — R-528 и R-529: Defender базой 1.463.16.0 удаляет `openxcom_hd.exe` как
`Program:Win32/Contebrew.A!ml`, а форма ложного срабатывания Microsoft с личной учётной записью не работает.

## Что у нас сейчас

| Файл | Чем собран | Подпись |
|---|---|---|
| `openxcom_hd.exe` (игра) | MinGW-w64, ninja в `build-release`, затем **Enigma Virtual Box** (`tools/build/build.ps1`, `Invoke-ExeStep`) | нет |
| `XPiratezLauncher.exe`, `xp-bootstrap.exe` | .NET 10 NativeAOT, `portal/publish.ps1` | нет |
| `livekit_ffi.dll` и прочие DLL | чужие | не наши — не подписываем |

- Неподписанный лаунчер — открытый риск R-P11 в `docs/portal/RISKS.md` («отдельный организационный вопрос»).
- Enigma Virtual Box вшивает в exe всего пять DLL: libFLAC, libvorbisfile-3, libwinpthread-1, libogg-0, libvorbis-0
  (`dist/_work/openxcom.evb`). Размер растёт с 24.9 до 27.1 МБ.
- Манифест выпуска подписан Ed25519 (это наша подпись для лаунчера, не Authenticode); его не трогаем.
- Репозиторий `vlourie/OpenXcom` публичный, GPL-3.0, форк MeridianOXC.

## Главное до выбора

1. **Подпись не гарантирует, что ML Defender отстанет.** Официального заявления Microsoft нет. Есть отчёты, что подписанные
   (даже EV) файлы тоже ловили `!ml`, а каждый новый файл начинает репутацию с нуля. Подпись помогает: репутация копится на
   сертификат, а не на каждый хэш, и SmartScreen перестаёт пугать «неизвестным издателем». Но «подписали — и чисто» обещать
   нельзя.
2. **Enigma Virtual Box — вероятный спусковой крючок, и убрать его можно бесплатно.** Сам разработчик Enigma на своём
   форуме называет срабатывания на упакованные файлы известными и случайными; у его пользователей Defender ловил упаковкой
   даже «Hello World». У нас упаковка нужна ради пяти маленьких DLL.
   - Без упаковки: класть DLL рядом с exe, как делает сам OXCE, — лаунчер всё равно раздаёт файлы поштучно.
   - Или собрать их статически. `libvorbisfile-3.dll` SDL_mixer грузит сам, на лету (`DynamicDlls`), поэтому её проще
     оставить рядом.
   - Это шаг 0: не стоит денег и не требует ничего от Vitali, кроме «да» на правку сборки.
   - Механику не задевает. Проверка — запуск невидимым прогоном и сверка, что exe не тянет ничего из MSYS2.

## Три пути подписи

| | SignPath Foundation | Azure Artifact Signing (бывш. Trusted Signing) | Certum Open Source Code Signing |
|---|---|---|---|
| Цена | бесплатно | $9.99 в месяц (Basic, 5000 подписей), нужна платная подписка Azure (pay-as-you-go; бесплатная и пробная не подходят) | порядка €49–70 в год (на сайте не сверено — смотреть shop.certum.eu) |
| Чьё имя в сертификате | «SignPath Foundation» | Vitali или его компании | «Open Source Developer, <имя Vitali>» |
| Кому дают | открытым проектам по заявке, на их усмотрение | частным лицам — **только США и Канада**; организациям — США, Канада, ЕС, Великобритания и ещё несколько стран | частным лицам, после проверки документов |
| Где подписывать | только сборка в GitHub Actions из публичного репозитория, каждая подпись — ручное одобрение в SignPath | на нашей машине: signtool + клиент Azure, ключ в облаке Microsoft | на нашей машине: signtool + SimplySign Desktop (вход с кодом с телефона, сессия на несколько часов) |
| Репутация у Defender и SmartScreen | копится на общий сертификат фонда | лучшая из трёх (сертификат от CA самой Microsoft), но не гарантия | копится с нуля |
| Автоматический выпуск в 21:00 | ждёт клика Vitali в SignPath | идёт сам | ждёт, пока Vitali войдёт в SimplySign |

### SignPath Foundation — почему не первым

Условия (`signpath.org/terms`) мы закрываем не все:

- **Игра — изменённый OXCE.** Подписывать свою версию чужого проекта разрешено, только если сам upstream выпускает
  подписанные сборки. MeridianOXC подписанных не выпускает. По букве правил exe игры могут не взять — остаётся лаунчер,
  а ругается Defender как раз на игру.
- **Нужна проверяемая репутация проекта.** Фонд прямо пишет, что вправе отказать без объяснений. Лаунчер раздаёт ещё
  моды и графику 18+, которые не открытый код.
- **Сборка только в GitHub Actions.** У нас всё собирается локально (MSYS2, `build-release`, Enigma). Переезд в CI —
  отдельная работа на несколько дней.
- **Приватность.** Лаунчер шлёт отчёты, сейвы и логи (с галочкой) и держит голос. Политику нужно показывать при установке
  и давать выключатели.
- **Мелочи:** страница «Code signing policy» на сайте и в разделе загрузки, двухфакторный вход в GitHub и SignPath,
  одинаковые ProductName и версия во всех подписываемых файлах.

Итог: самый трудоёмкий путь и самый высокий риск отказа. Брать, только если два других закрыты.

### Azure Artifact Signing — лучший, если подходит по стране

- Встраивается в нынешний локальный выпуск без CI.
- Сертификат короткий, поэтому подписывать обязательно с меткой времени (так и делается по умолчанию).
- Нужно от Vitali:
  1. Платная подписка Azure (карта, pay-as-you-go).
  2. Проверка личности: частное лицо с документом США или Канады, либо организация в разрешённой стране.
  3. Учётная запись или сервис-принципал для `release.ps1` на машине сборки. Секрет вне репозитория (R-P06).

### Certum Open Source — если Azure недоступен

- Сертификат на имя Vitali, облачный, без токена. Цену и то, подходит ли он для Authenticode сейчас, сверить на сайте Certum
  до покупки: старые сообщения противоречат друг другу.
- Нужно от Vitali:
  1. Документы для проверки личности.
  2. Покупка.
  3. Вход в SimplySign Desktop перед каждым выпуском.
- По слухам, такой сертификат не продлевается, а покупается заново каждый год.

## Вопросы Vitali (от них зависит выбор)

1. Страна гражданства и проживания. Есть ли организация в США, Канаде, ЕС или Великобритании? Это решает, доступен ли Azure.
2. Готов ли Vitali, что его настоящее имя будет в свойствах exe у всех игроков? Так в Azure и Certum; в SignPath — имя фонда.
3. Можно ли выпуску ждать ручного шага (клик в SignPath или вход в SimplySign)? Или подпись должна идти сама?
4. Бюджет: $10 в месяц или около €50–70 в год.

## Как встроить в выпуск (одинаково для Azure и Certum)

1. **Exe игры** — в `tools/build/build.ps1`, `Invoke-ExeStep`, после Enigma или копии в `openxcom_boxed.exe`, до стейджа.
   - Подпись с меткой времени меняет байты при каждом запуске. Без кэша игроки качали бы ~27 МБ каждый выпуск — та же
     беда, что была с Enigma (`size-audit-2026-10-27.md`).
   - Поэтому подписанный файл кэшировать по хэшу неподписанного, как сейчас `openxcom_boxed.exe.key`, и подписывать
     заново только новый exe.
2. **Лаунчер** — в `portal/publish.ps1`, после публикации AOT: подписать `XPiratezLauncher.exe` и `xp-bootstrap.exe`.
   Чужие DLL не трогать.
3. **Проверка** — в `Выпуск/release.ps1`, перед подписью манифеста: `Get-AuthenticodeSignature` у каждого нашего exe
   должен быть `Valid`, иначе выпуск останавливается. С `nobuild` проверять то же.
4. **Манифест Ed25519 не меняется**: он подписывает хэши уже подписанных файлов. Лаунчер сверяет хэш как раньше.
5. **Исключения Defender на машине сборки** (`D:\xp-repo`, `E:\OpenXCom\dist`) остаются — подпись их не заменяет.
6. **Грабли и решение** — запись в DECISIONS (какой путь выбран и почему). Закрыть R-P11 в `docs/portal/RISKS.md`.

## Порядок

1. **Шаг 0 — сделан 29.10, выпуск 2026.10.29** (коммит 55d3ecb98, грабли R-530). Проверка MpCmdRun до правки: exe без
   упаковки и пять DLL чистые, упакованный Enigma — Contebrew.A!ml. DLL теперь лежат рядом с exe (компонент engine).
2. **Ответы на вопросы выше.** Затем заявка: Azure (несколько дней на проверку личности) или Certum.
3. **Встроить подпись по разделу выше.** Первый подписанный выпуск — с проверкой `Get-AuthenticodeSignature` у игрока
   (тикет или ручная проверка).
4. **Смотреть за срабатываниями:** `Get-MpThreatDetection` на машине сборки и тикеты игроков. Новое `!ml` на подписанный
   файл — снова подать в Microsoft. С сертификатом заявка весомее, но форма у личных учётных записей сломана (R-529).
