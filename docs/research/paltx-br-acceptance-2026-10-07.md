## Пробелы

- **HdItems и HdUi подменой не покрыты.** Предметы в инвентаре и картинки интерфейса остаются в
  своих цветах.
- **Дым и огонь перекрашиваются через M1t, не через BR.** Это не террейн, правило соблюдено, но
  M1t может усиливать мерцание анимации с близкими цветами. На сериях MAGMA и Стикса этого не
  видно; другие окружения в движении не снимались.
- **colorAuthority проверена только по коду.** В замороженных модах нет ни одного `color.txt`,
  поэтому кадр «в своих цветах» под подменой в прогонах не встречался.
- **Кадры без файла** (`Entry` с пустым `path`, собранные в памяти) подмена не трогает: их нет в
  списке ни при декодировании, ни в `setRecolour`.
- **Одна функция на набор убирает не все швы между наборами.** Это свойство метода, а не ошибка.
- **Эталон Стикса в замере — 2 повтора, а не 3:** во всех пяти попытках третьего шла чужая игра.
- **Exe эталона и чистая сборка того же кода отличаются на 15 байт** (метки и ресурс версии,
  R-279). Повтор прогона чистой сборкой не делался: секции кода совпадают побайтно.
- **Вне пруда допуск не задан.** Трава Стикса (зелёный канал −15–18) и прочие участки вне
  пруда допуском ±8 не покрыты — наблюдение, не критерий.

## 2. Код перекраски при декодировании

| место | что делает |
|---|---|
| `src/Engine/HdSprites.cpp:252` `decodeShown` | `decodeBlob` (PNG → кадр), затем `recolourHook(key, кадр)` на декодированной копии |
| `HdSprites.cpp:266` `settle` | кладёт кадр в запись, `recoloured = recolourHook != nullptr` (стр. 276) |
| `HdSprites.cpp:292` `loadFile`, `:763` `preload` | все загрузки кадра идут через `decodeShown` |
| `HdSprites.cpp:893` `setRecolour` | `beforeChange`; сбрасывает перекрашенные кадры и всем ставит `recoloured = false`; ставит функцию; перекрашивает уже загруженные на `HdWorkers::run`; помечает их; `++registryGeneration`; строка в журнале |
| `HdSprites.cpp:1010`, `:1030` `scanPictures` | берёт кадр в своих цветах (не `recoloured`) или декодирует PNG через `decodeBlob`, без функции |
| `src/Engine/HdPaletteShift.cpp:120` `recolour` | ключ в `terrainKeys` → таблица BR, иначе LUT M1t |
| `HdPaletteShift.cpp:487`, `:500` | `setRecolour(&recolour)` последним шагом `install`; `setRecolour(nullptr)` в `remove` |
| `src/Battlescape/BattlescapeState.cpp:147`, `:854` | `install` при входе в бой с подменой; `remove` в `resetPalettes` |

Почему так безопасно:

- **Потоки.** Отдельных потоков загрузки нет: в `HdSprites.cpp` нет `std::thread`, `async`,
  мьютексов и атомиков. Пул `HdWorkers::run` (`HdWorkers.cpp:109–139`) блокирующий и вызывается
  из главного потока. Функция перекраски меняется только в `setRecolour` из главного потока, когда
  ни один батч не идёт. Каждая задача батча пишет в свою запись `Entry`; таблицы BR и M1t
  строятся до `setRecolour` и дальше только читаются.
- **Повторная перекраска исключена.** `setRecolour` сначала обнуляет всё, что перекрасила
  прежняя функция (кадр будет перечитан из файла), и только потом перекрашивает кадры в своих
  цветах — каждый один раз. Кадр, вытесненный по бюджету (`HdSprites.cpp:~825`), обнуляется и при
  следующем обращении снова проходит `decodeShown` из PNG.
- **PNG не меняются.** Файлы паков только читаются (`readBlob`). Перекрашивается декодированная
  копия в памяти, исходные пиксели для расчёта BR (`scanPictures`) берутся мимо функции.

Аудит журналов (`recolour_audit.py`, 85 журналов, 34 пары вкл/выкл):

- при включении сброшено 0 кадров везде;
- при выключении сброшено ровно `T + O` во всех одиночных боях (`T` — перекрашенный террейн,
  `O` — прочие кадры), `T` не больше просканированных картинок;
- в последовательностях сброшено меньше `T + O`: наборы выгружаемого боя `removeSet`
  (`MapDataSet.cpp:277`) стирает раньше выключения.

## 4. Стикс в фазах анимации

Чистые HD-кадры F12 без заморозки (дамп Ctrl+F8 замораживает анимацию, R-268), пауза между
снимками 2,4 с, всё в одном запуске каждой сборки:

Пиксель «движется», если между соседними снимками серии он меняется больше чем на 8.

**Движется только у одной сборки** (допуск 5×5): у BR 1616 пикселей (0,08 % кадра), у эталона

Из 1616 пикселей BR 1252 лежат в двух тёмных участках, где пол переключается между двумя

## 5. Пруд ±8, BR и M1t, colorAuthority

**Пруд** — методика передачи (`art/paltx/handoff/inputs/paltx_pond4.py`): средний цвет
непрозрачных HD-пикселей кадра FORESTSWAMPSTYX.PCK 56 против классического кадра в показанной
палитре. Перекраска — таблицами самого движка (дамп `OXCE_HD_PALSHIFT_DUMP`), с тем же
округлением, что в `apply()` (`pond_check.py`, `art/paltx/acceptance/pond_check.json`).

Критерий передачи: каждый канал в ±8 — выполнен; BR не хуже M1t — выполнен.

**BR только для террейна.** `HdPaletteShift::recolour` (`HdPaletteShift.cpp:120`) выбирает таблицу
по `terrainKeys`. Это ключи кадров наборов террейна боя (`HdPaletteShift.cpp:434–445`), всё
прочее идёт через M1t. Счётчики в журнале на Стиксе:
- 439 кадров террейна — ровно столько картинок 14 наборов просканировано для BR;
- 75–112 прочих кадров (бойцы, предметы на полу и в руке, дым, огонь) — через M1t.

На hot — 538 кадров террейна и 39 прочих.

**colorAuthority.** Подмена перекрашивает каждый кадр пака независимо от `ownColour`.
`color.txt` влияет только на ветку скриптовой перекраски и света (`HdCanvas.cpp:854`), а в
`HdPaletteShift` и `decodeShown` он не учитывается. Пак подчиняется палитре миссии. Прогоном это
не проверено: в замороженных модах нет ни одного `color.txt` (см. «Пробелы»).

## Что сделано в движке

- `src/Engine/HdPaletteShift.*` — при входе в бой с `enviroEffects paletteTransformations`
  строит таблицы: BR для наборов террейна (сетка 32³, splat, размытие σ=1,25,
  T=(r+LUT)/(w+1)), M1t для остального (LUT 64³, σ=12). Строка в журнале
  `HD palette shift: <палитра> of the battle, N terrain set(s)`.
- `src/Engine/HdSprites.*` — перекраска при декодировании кадра на HdWorkers; флаг
  перекраски ставится в settle, повторно кадр не перекрашивается; `setRecolour` сбрасывает
  уже декодированные кадры, они перечитываются из PNG.
- `HdPaletteShift::remove()` в resetPalettes. Вызывается при выходе из боя, загрузке другого
  сейва и Ctrl+Home: в журнале строка `palette shift: off`, сброшенные кадры перечитываются из
  исходных PNG.
