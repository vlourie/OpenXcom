## 2. Дерево в лаунчере

На диске раскладка остаётся плоской: `user/mods/<папка>/metadata.yml`. FileMap::scanModDir (src/Engine/FileMap.cpp)
смотрит ровно один уровень, и вложенные папки потребовали бы правки движка. Поэтому дерево — это вид в лаунчере
и в каталоге, а не папки на диске.

```
Пиратки (piratez)                      ← игра: папка-узел, master
  ├ Танк: башня, Танк: задний ход, Кися, Apple Processing, EnemyRandomizer, OAK, Cities Lore, RU-патч …
  └ HD Пираток (hd), голоса RU/EN, шаги
X-Com Files (x-com-files)
  ├ Dark Geoscape
  └ XCF Cyrillic Names
Warhammer 40k (40k)
  ├ ROSIGMA                             ← дополнение, которое меняет игру целиком (kind: game-overhaul)
  └ Blood Angels, Imperial Fists, Salamanders
X-Chronicles (Xchr)
  └ XCHR Cyrillic Names
Mars-com (Mars-com)
UFO (xcom1) · TFTD (xcom2)
  └ TWoTS                               ← только при импортированных данных TFTD
Для всех игр
  └ HD-шрифты (hd_core)
```

**Правило раскладки.** Мод попадает под игру, если его `master` — игра или её мод. Мод попадает в «Для всех игр»,
если его `master: "*"` **и** каталог помечает его как `targetGames: "*"` (то есть проверено на всех играх).
Мод с `"*"` без проверки (как `intro_voice` сейчас) лаунчер кладёт под ту игру, для которой он сделан
(поле `targetGames`), а не в общую группу.

**Где это в лаунчере** (0.3.18):

- `SetupPage.ShowParts` и список «Свои моды» сейчас плоские — нужна группировка по `GameNode`.
- Сборка (`Builds.cs`) получает поле `targetGame`. Профили (`xp-profiles.json`) — по одному на игру.
  Сейчас профиль есть только у piratez, и «Новая сборка» для другой игры падает с «no profile».
- `ComponentInfo` получает поле `targetGames`, а ещё `kind: game` для узла игры и `kind: game-overhaul` для ROSIGMA.
  Поле `Master` остаётся как факт из `metadata.yml`.
- Лаунчер пока каталог вообще не читает. Чтение каталога схемы 2 — первым шагом (этап 2 в MULTIMOD §11).

## 3. Загрузка у автора (source: upstream)

Права на раздачу всех пяти игр не подтверждены (MULTIMOD §9). Поэтому мы их файлы **не раздаём**:
лаунчер скачивает архив с mod.io на машине игрока.

Что проверено 27.10:

- Скачивание без ключа API:
  `https://g-51.modapi.io/v1/games/51/mods/<mod>/files/<file>/download` → 302 на CDN.
  CDN отдаёт `Range`, поэтому оборванную загрузку можно продолжить.
- Список файлов и номер последней версии **без ключа API не отдаются**.

Запись в каталоге (схема 2, `source: upstream`):

```json
{ "id": "x-com-files", "kind": "game", "engineMaster": "x-com-files", "source": "upstream",
  "upstream": { "site": "mod.io", "mod": 158, "file": 8236968, "version": "4.2",
                "size": 248338351, "sha256": "b93057bf…0f385",
                "extract": { "XComFiles/": "user/mods/XComFiles/", "DarkGeoscape/": "user/mods/DarkGeoscape/",
                             "XCF Cyrillic Names/": "user/mods/XCF Cyrillic Names/" } },
  "checked": { "probe": "PASS", "date": "2026-10-27", "engine": "2026.10.26" } }
```

- **Номер файла и sha256 закреплены.** Если у автора вышла новая версия, лаунчер её **не берёт**, пока мы её
  не проверили. Игрок получает только проверенную пару «игра + наш движок».
- Распаковка — в плоский `user/mods`, по карте `extract`. Это защищает от путей с `..` и от чужих папок.
  Затем лаунчер проверяет `metadata.yml`: id и master должны совпасть с каталогом.
- Загрузчик берёт код Range и sha256 из `RepoClient`. Нужна только распаковка zip. В .NET есть
  `System.IO.Compression`, отдельной библиотеки не нужно.
- Скачанный архив лаунчер не хранит: после проверки sha256 и распаковки он удаляется.
  При обновлении версии игры заменяются только папки из `extract`, сейвы и `options.cfg` сборки не трогаются.

## 4. Свежие версии — работа на нашей стороне

Проверку новой версии делает задача на нашей стороне, а не лаунчер игрока:

1. Раз в сутки — запрос к mod.io API с нашим ключом: `GET https://g-51.modapi.io/v1/games/51/mods/<mod>/files?api_key=…`.
   Вопрос: появился ли у мода файл новее закреплённого. Ключ аккаунта выдаётся на https://mod.io/me/access
   (раздел API Access). Это строка из 32 символов, только для чтения: ей можно лишь читать, ничего менять нельзя.
   Ключ лежит в `portal.env` станции, не в репозитории.
2. Новый файл: скачать → распаковать в отдельную пустую папку → `mod_probe.py run <игра> --variant all`
   (невидимо, по 3 варианта).
3. PASS → строка в `compat.tsv` и новая пара `file` + `sha256` в каталоге; выпуск каталога — по слову Vitali.
   FAIL → тикет на нас, игроки остаются на прежней версии.

Пока ключа нет, задача может читать страницу мода на mod.io: номер файла виден в ссылке «Download».
Делать так можно только как временную меру — разметка страницы меняется без предупреждения.

## 5. TFTD и TWoTS

TWoTS работает поверх TFTD (`xcom2`). Данных TFTD у нас нет, и раздавать их мы не можем, как и UFO.
Нужен импорт «укажите папку с TFTD (Steam/GOG)» по образцу UFO. До этого TWoTS в дереве показывается серой строкой
с причиной. Steam кладёт данные в подпапку `TFD` (GEODATA, MAPS, UNITS…), её и надо брать.
Движок ищет первую папку `TFTD` по списку `-data`. В установке Пираток она есть, но в ней только README —
поэтому импорт должен **заменить** её содержимое, а не положить данные рядом.
Проверка 27.10 на Steam-версии: PASS (§1).

## 6. Базы, звуки, голоса в чужих играх

Подробно — `docs/research/modio-bases-sounds-2026-10-27.md`. Для лаунчера важно:

- Наш HD-пак `hd` ищет тайлы баз по номеру кадра. В чужой игре он легко положил бы картинку другой постройки.
  Поэтому `hd`, голоса и шаги остаются под Пиратками (master `piratez`), а для каждой игры понадобится свой мод
  `hd_<игра>`.
- Слоя HD-звуков в движке нет. Для общих ванильных звуков один HD-набор подошёл бы всем играм,
  свои звуки каждой игры — отдельная работа.
- Голосовые наборы годятся только как конвейер (`tools/sfx/build_voicepack_mods.py`). Записи привязаны к типам
  бойцов Пираток. У 40k и ROSIGMA голос брони стоит выше голоса бойца.

## 6а. Как это сделано в лаунчере (27.10, 0.3.19 — ещё не выпущен)

Каталог схемы 2 оказался не нужен: **игра = её профиль** в `portal/profiles/xp-profiles.json`, который и так едет
в подписанном выпуске в корень игры. У профиля новые поля:

| Поле | Зачем |
|---|---|
| `id` | имя профиля, когда у двух игр один мастер: `rosigma` и чистый `40k` оба на `40k`. Профиль с `id` находится **только** по нему — ванильная TFTD (`xcom2`) не получит моды TWoTS |
| `title` | имя игры в лаунчере |
| `requires` | игра, поверх которой эта ставится (`rosigma` → `40k`), качается первой |
| `data` | `"TFTD"` — нужны данные Terror from the Deep игрока |
| `source` | `url`, `version`, `size`, `sha256`, `folders` (`name` = папка в архиве и в `user/mods`, `id` = что обязан сказать её `metadata.yml`) |

- **Сборка помнит профиль** (`Build.Template` = ключ профиля), и перед запуском лаунчер применяет его, а не первый профиль мастера.
- **`GameInstaller`** (`Xp.Launcher.Core/Games.cs`):
  1. качает в `launcher/downloads` с докачкой (`RepoClient.DownloadFileAsync` — тот же код, что у блобов выпуска);
  2. сверяет размер и sha256;
  3. распаковывает только папки из `folders`, каждую запись проверяет `SafePath`;
  4. сверяет `id` в `metadata.yml`;
  5. меняет папки целиком (старые уходят в сторону и возвращаются при сбое);
  6. записывает `launcher/games.json`, удаляет архив.

  Под запущенной игрой ничего не делает.
- **`TftdData`** ищет TFTD в Steam (`…\X-COM Terror from the Deep\TFD`), GOG и OpenXcom и копирует 10 папок в `<игра>/TFTD`.
  Готовой считается папка, в которой не меньше 9 записей: столько требует движок.
- **Окно «Новая сборка»:** если игр больше одной, сначала спрашивает игру. Под каждой строка состояния:
  «установлена» / «скачать N МБ с mod.io» / «нужна ваша копия TFTD». Затем подтверждение загрузки,
  прогресс на главной кнопке, копия TFTD и имя сборки.
- **Headless:** `--headless games list|install <id>|tftd [--from dir]`.
- **Проверено 27.10:**
  - тесты: 10 `GameTests` и UI-тест окна;
  - вживую на папке-пустышке: Mars-com и TWoTS скачаны с mod.io, sha256 сошёлся, TFTD скопирована из Steam;
  - сборки `twots` (`xcom2` + TWoTS) и `rosigma` (`40k` + ROSIGMA) записали верные моды.
- **Подпапки «под игрой»** — только группировка в лаунчере: движок читает `user/mods` на один уровень (§2).
