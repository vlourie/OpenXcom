# Общение в стиле IRC — проект

Версия 0.1 · 2026-11-05 · задание Vitali: «переработать Голос на сайте и в лаунчере, сделать более похожим на IRC,
оповещение в игре о новых сообщениях, осовременить дизайн лаунчера».
Дополняет `VOICE_CHAT.md` (доступ, пропуска, голос, журнал). Что здесь не сказано, остаётся как там.

## 1. Решения Vitali 05.11

| Вопрос | Решение |
|---|---|
| Каналы | **общие и личные**: несколько общих каналов со свободным входом (текст и голос); личные комнаты по-прежнему с разрешения владельца |
| Оповещение в игре | **плашка в самой игре**: лаунчер кладёт локальный файл, движок его читает и рисует |

## 2. Значения по умолчанию (не спрашивались, Vitali может поменять)

| Что | Значение | Почему |
|---|---|---|
| Хранение текста | 30 дней, потом удаление; сообщения из жалобы хранятся по правилу журнала `VOICE_CHAT.md` §10 | как журнал входов, и есть чем разбирать жалобы |
| Общие каналы при запуске | `#общий`, `#english`, `#помощь` | заводятся сидом, список меняет суперадминистратор |
| Плашка в игре по умолчанию | личные сообщения и упоминания ника; все сообщения каналов — опция лаунчера | в общем канале иначе плашка не сходит с экрана |
| Кто модерирует общие каналы | Admin и SuperAdmin; запрет голоса аккаунту по-прежнему только SuperAdmin | полномочия персонала из `VOICE_CHAT.md` §10 |
| Гости | нет: читать и писать можно только с учётной записью | как весь раздел сейчас |

## 3. Что значит «как IRC»

- Три колонки: слева каналы и личные диалоги, в середине лента, справа список участников.
- Лента строками `12:34 <ник> текст`, без пузырей. Строка темы над лентой.
- Отметка у ника в списке: `@` владелец или персонал, `+` сейчас в голосе, приглушён — без права говорить.
- Входы, выходы, смена темы, исключения — серые служебные строки в ленте.
- Ввод одной строкой, команды через косую черту.
- Личные сообщения — это прежний `MessageService`, показанный как диалог в той же левой колонке (query в IRC). Таблицы и API личных сообщений не меняются.
- Голос — кнопка канала, а не отдельный экран: «Войти в голос» внизу ленты, там же микрофон, клавиша разговора и настройки. На сайте вместо неё кнопка, открывающая лаунчер (`xpiratez://voice/<id>`): голос в браузере не появляется.

### Команды

| Команда | Что делает | Где выполняется |
|---|---|---|
| `/me текст` | строка действия `* ник текст` | сервер |
| `/topic текст` | тема канала (владелец, персонал) | сервер |
| `/msg ник текст` | личное сообщение через `MessageService`, с его правилами блокировок | сервер |
| `/kick ник`, `/ban ник`, `/unban ник`, `/mute ник`, `/unmute ник` | те же действия и журнал, что у кнопок модерации, те же права | сервер |
| `/join #канал`, `/part`, `/who`, `/help` | перейти, выйти, список, справка | клиент |

Неизвестная команда отвечает строкой-подсказкой и никуда не уходит: текст с `/` в начале никогда не становится сообщением случайно.

## 4. Сервер

**Данные (одна миграция):**
- `VoiceRoom`: новые `IsPublic bool` (по умолчанию false) и `Topic string?`. Общие каналы — обычные комнаты: тот же пропуск, та же вместимость, тот же журнал. Предел числа комнат на владельца их не считает.
- `RoomMessage`: `Id bigint` по возрастанию (он же курсор), `RoomId`, `AuthorId`, `Kind` (text, action, system), `Body`, `CreatedAt`, `DeletedAt?`, `DeletedById?`. Индекс `(RoomId, Id)`.
- `RoomChannelState`: `RoomId`, `UserId`, `LastReadId`, `SeenAt`, `Joined bool`. Отсюда непрочитанное и кто сейчас в канале.

**Доступ.** Читать и писать текст может тот же, кому `VoiceService` выдал бы пропуск; в общий канал — любой с учётной записью без бана в канале и без запрета голоса. Правило одно и лежит в `VoiceService`: API и страницы только переводят HTTP. Сообщения авторов из `UserBlock` читателю не отдаются.

**API (рядом с `/voice/rooms`):**
- `GET /voice/channels` — общие каналы, мои комнаты, непрочитанное и упоминания: один запрос на весь список;
- `GET /voice/rooms/{room}/messages?after=<id>&limit=` — новые строки и участники. Клиент спрашивает раз в 3 с, пока канал открыт на экране, и пока окно не свёрнуто; фоном список каналов раз в 60 с;
- `POST /voice/rooms/{room}/messages` — строка или команда, разбирает сервер;
- `DELETE /voice/rooms/{room}/messages/{id}` — удалить чужую строку: владелец и персонал; своя — автор.

**Пределы:** строка до 1000 символов, 20 строк в минуту на человека (`voice-write`), 200 строк истории за раз. Удаление старых строк и состояний — в `VoiceWorker`. Текст хранится как есть, на выводе экранируется везде; ссылки на сайте с `rel="nofollow noopener"`, в лаунчере не кликабельны.

**Сайт.** `/voice` становится трёхколоночной страницей канала, `/voice/rooms/{id}` — той же страницей с открытым каналом. Управление комнатой (приглашения, участники, закрыть, удалить) уходит за кнопку «Управление» на отдельную страницу с нынешним содержимым `Room.cshtml`. Ввод — обычная форма с antiforgery, обновление ленты — небольшой `wwwroot/js/channel.js`; без скриптов страница работает с перезагрузкой. На телефоне колонки сворачиваются в вкладки.

## 5. Лаунчер

Раздел «Общение» переписывается на те же три колонки вместо вкладок «Голос/Сообщения». Логика сеанса (`VoiceSession`, `TalkHook`, настройки звука, проверка микрофона) не меняется. Опрос сервера — только пока раздел открыт и окно не свёрнуто; фоном идёт только список каналов и счётчики. Клавиша разговора, трей и работа голоса под игрой остаются как есть.

**Дизайн лаунчера:** вариант выбирает Vitali по макету (§8). Меняется `Skin.cs` и то, как страницы собирают кнопки и меню; раскладка главной и логика обновления не меняются. Принципы `LAUNCHER_UI.md` §2 остаются, особенно «одна главная кнопка».

## 6. Плашка в игре

Образец уже есть: `HdUpdateNotice` читает `launcher/update.txt`. Делается соседняя `HdChatNotice`.

- **Лаунчер** (`Core/ChatNotice.cs`, рядом с `UpdateNotice.cs`) при новом личном сообщении или упоминании атомарно заменяет `launcher/chat.txt`: первая строка — счётчик по возрастанию, вторая — `ник: начало текста`. Игра запущена — пишет, нет — не пишет; при выходе лаунчера файл удаляется.
- **Движок** смотрит файл раз в 2 с (один `stat`, чтение только при новой дате). Новый счётчик — плашка на 6 с в правом верхнем углу: длина строки ограничена, лишнее обрезается, управляющие символы отбрасываются. Текст приходит от других игроков, поэтому для движка это только строка на показ.
- **Не трогает механику:** состояние игры, сейвы и случайные числа не затрагиваются, ввод не перехватывается, сеть движку не нужна («Движок в сеть не ходит» остаётся верным).
- **Опция** `oxceHdChatNotice` (по умолчанию включена) рядом с `oxceHdUpdateNotice`. Строки — в `bin/common/Language/OXCE`, с переносом в установку Пираток (исключение святого правила).
- **Приёмка:** без файла режим 0 при `k = 1` и `k = 4` IDENTICAL. С файлом плашка видна на глобусе, базе и в бою, снимается сама, кириллица читается, длинная строка обрезана, мусор в файле не роняет игру. Кадр снимается только через hdbench, невидимо.

## 7. Порядок работ

1. Сервер: миграция, `VoiceService`, API, разбор команд, тесты правил доступа.
2. Сайт: страница канала.
3. Лаунчер: дизайн по выбранному макету, затем раздел «Общение».
4. Плашка в игре: движок через очередь правок, запись файла в лаунчере.
5. Прогон пачки, номер версии лаунчера от Vitali, выпуск по его слову; архив сайта и `station.ps1 up` — Vitali.

Шаги 1, 3 и 4 идут параллельно: их общая опора — API и формат файла из этого документа. Шаг 2 идёт после шага 1.
