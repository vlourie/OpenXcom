# Голос в продакшн — план и проверки выпуска

Проект голоса — `docs/portal/VOICE_CHAT.md` (0.4, утверждён 2026-09-29). Здесь — как он доводится
до выпуска игрокам после пробы этапа 1: что делается, в каком порядке, и что проверяется перед
выпуском. Решения ниже — ответы Vitali от 2026-10-03.

## Решения 2026-10-03

| Вопрос | Решение |
|---|---|
| Порядок | серверная часть портала (друзья, комнаты, приглашения, права владельца, пропуск) — сейчас; параллельно — голос в обычный лаунчер, новый пропуск на каждом входе |
| Боевой LiveKit | машина с публичным IP, как утверждено; станция остаётся пробой. Пока адреса нет — готовится конфигурация и список портов, размещение — когда машина будет готова |
| Регистрация | доводится до рабочего состояния ДО открытия комнат игрокам: SMTP через секреты на сервере, проверка пути регистрация → письмо → подтверждение → вход → привязка лаунчера. Провайдера и учётные данные Vitali сообщает отдельно, пароль в чат не идёт |
| Диагностика | записи WAV, отводы и тестовые ключи из публичной сборки убираются; безопасная диагностика звука (уровни, счётчики, устройства — без звука) включается флагом для расследования сбоев |
| Проверка выпуска | отдельно: обычная сборка содержит голос, ходит на боевой сервер с боевыми ключами, пропусков `voice-token` в ней нет |
| Лаунчер 0.3.7 (нужен `hd_core`) | выходит с голосом в основной сборке, раздел «Голос» не скрывается: «неработающий войс не страшен». Пока медиасервер — проба станции, сайт отказывает игрокам в пропуске (`voice_unavailable`), и лаунчер пишет «Голос сейчас недоступен на сервере» — это условие сохраняется. Перед повышением версии — готовая выпускная сборка: лаунчер открывается, игра запускается, обновление работает. Живой разговор и боевой сервер — следующий этап, выпуск `hd_core` их не ждёт |
| Удаление аккаунта | план ниже принят с решениями: сообщения форума остаются под «Удалённый пользователь», оценки арта удаляются с пересчётом, отмена — 30 дней. Само удаление пока не включается |

## Части работы

**Портал (`Xp.Portal`).**
1. Таблицы §7 и миграция: `FriendRequest`, `Friendship`, `UserBlock`, `VoiceRoom`, `RoomInvite`,
   `RoomBan`, `RoomSpeakingRestriction`, `VoiceAccountBan`, `VoiceEvent`, `VoiceEventTicket`, плюс
   очередь команд медиасерверу `VoiceJob` (исключение и запрет речи повторяются из очереди, как
   `NotificationJob`).
2. Пропуск: JWT HS256 на одну минуту, `room = VoiceRoom.Id`, `identity = PortalUser.Id`,
   `canSubscribe`, `canPublish` только без запрета говорить, `roomAdmin` никогда. Ключ — только в
   `portal.env` (`LiveKit__ApiKey`, `LiveKit__ApiSecret`).
3. API `/api/v1/voice/...` (cookie сайта или `X-Device-Token`): друзья, комнаты, приглашения, вход,
   модерация, присутствие; webhook LiveKit со сверкой участника на `participant_joined`.
4. Страницы сайта: друзья, мои комнаты и приглашения, страница комнаты `/voice/rooms/{publicId}`
   с состояниями «нет доступа», «приглашение отозвано», «вы заблокированы», «комната закрыта».
5. Жалобы — тикеты категории `voice` (право `tickets.voice`); запрет голоса аккаунту и закрытие
   любой комнаты — страница суперадминистратора; ежесуточная чистка журнала по срокам §7.
6. Регистрация: адрес возврата сохраняется через регистрацию и подтверждение (путь из лаунчера к
   `/me/devices?code=`), повторное письмо подтверждения. Удаление аккаунта — не включается до
   решения, как обезличивается то, что остаётся (план ниже).

**Лаунчер.**
1. `Xp.Voice` без диагностики пробы: нет записи WAV, отводов loopback, тона, речи из файла,
   переключателей WASAPI; безопасная диагностика по флагу пишет в лог только числа.
2. Новый пропуск у портала на каждом входе и переподключении (сейчас переподключение берёт старый).
3. Раздел «Голос» в главном окне, трей, клавиша разговора с проверкой конфликта по `options.cfg`,
   ссылка `xpiratez://`.
4. Голос в обычной сборке: `Xp.Voice` подключён к лаунчеру всегда, ключа `-Voice` у `publish.ps1`
   больше нет; `livekit_ffi.dll` и `xpaudio.dll` в списке файлов лаунчера (`build.ps1`,
   `ReleaseRepo.cs`). Прототип `--voice` (`VoiceWindow.cs`) собирается только в Debug. Машине сборки,
   в том числе станции, нужна папка `portal/third_party/voice` (proto и DLL, `tools/voice_deps.py`).
5. Ссылку `xpiratez://` в реестр (HKCU) пишет только выпускная сборка при запуске; вторая копия
   лаунчера передаёт ссылку первой по именованному каналу и выходит.

**Сервер.**
1. Боевой LiveKit: compose и `livekit.yaml` с webhook на портал и TURN/TLS, свои ключи.
2. До переезда проба станции служит закрытой приёмке (`station.ps1 voice-testers`, ниже); после
   переезда снимается: команда `station.ps1 voice-token`, страница пробы, эхо-бот, ключи пробы.
3. SMTP: секреты кладутся на сервере командой, которая спрашивает пароль, не показывая его.

## Порты боевой машины

Конфигурация — `portal/deploy/voice-server` (`compose.yaml`, `setup.sh`, README): схема генератора
LiveKit, Caddy с модулем layer4 делит 443 по имени между сигналингом и TURN/TLS. Сайт остаётся на
станции; ключи LiveKit создаёт `setup.sh` на медиасервере, на станцию их вносит `station.ps1 livekit`
(секрет скрытым вводом), связь проверяет `station.ps1 voice-test` (`Xp.Portal voice check`).

| Порт | Что |
|---|---|
| 80/TCP | выпуск сертификатов Let's Encrypt (HTTP-01) |
| 443/TCP | по имени сервера — сигналинг и API комнат; по имени `turn.` — TURN/TLS |
| 7881/TCP | медиа, если у игрока закрыт UDP |
| 7882/UDP | медиа, один порт на всех (UDP mux) |
| 3478/UDP | TURN/UDP для строгих NAT |

7880 и 5349 наружу не открываются: к ним ходит только Caddy на той же машине. Машине нужны Linux
(сеть хоста), постоянный IPv4 и два имени DNS — сервера и TURN.

`station.ps1 livekit` не принимает адрес самой станции: это проба, и сайт выдаёт её пропуска только
тестерам. После `livekit` строка `voice check` обязана быть `production`, а не `PROBE`.

## Закрытая приёмка на пробе станции

Выпуск игрокам — после неё и после переезда на боевую машину. Проба станции для этого годится:
сайт выдаёт её пропуска только названным адресам, игроки слышат «голосовой сервер недоступен»,
даже если к ним уже пришёл лаунчер с голосом.

На станции (`C:\xp-portal\portal\deploy`), после `.\station.ps1 voice` (проба запущена, режим
internet, проброшены 7882/UDP и 7881/TCP):

```powershell
.\station.ps1 voice-testers vlourie@gmail.com
```

Второй тестер — его почта на сайте через запятую, без пробела, в той же команде. Строка проверки — `PROBE: ... passes only for 2 tester(s)`. У каждого тестера — аккаунт сайта с
этой почтой и лаунчер, привязанный к нему (`/me/devices`). У пробы нет webhook (`voice-probe/livekit.yaml`):
вход со старым пропуском после бана выводит сторож, в пределах 30 секунд. Серия из 50 попыток (§9)
снимается на боевой схеме с webhook, не здесь.

Сборка для тестеров — обычная выпускная, не прототип: `XPiratezLauncher.exe` и DLL голоса из
`dist\_launcher_rel` после `OXCE_Release.cmd` или автовыпуска (боевые ключи, версия `0.3.6+<коммит>`),
без `.pdb` и без `xp-bootstrap.exe` — у тестера остаётся свой. Кладётся поверх лаунчера в папке
игры, а перед заменой файлов тестер сохраняет копию своего нынешнего лаунчера (exe и DLL рядом) —
ею откатываются, если сборка не запустится. Самообновление её не откатит: оно ставит только версию строго выше (`SelfUpdate.CheckAsync`),
а в `launcher-stable` та же 0.3.6. Архивы прототипа `xp-voice-launcher_*` с `token.txt` для приёмки
не годятся: в них пропуск из командной строки и окно диагностики.

Две машины Windows, у каждой своя учётная запись; для каждого пункта смотреть и окно лаунчера, и
фактический звук у второй стороны:

- [ ] ссылка комнаты с сайта открывает лаунчер (`xpiratez://`), вход в комнату;
- [ ] разговор во время игры: игра на переднем плане, клавиша разговора работает, конфликт
      клавиши с `options.cfg` предупреждается;
- [ ] трей: окно свёрнуто, голос идёт, из трея — выход из комнаты;
- [ ] удаление из друзей во время разговора — удалённый теряет право входа и выводится из комнаты по правилам §3;
- [ ] запрет речи и возврат во время соединения — микрофон глохнет и возвращается, лаунчер это
      показывает;
- [ ] бан во время соединения — забаненный выведен, лаунчер показывает «вы заблокированы»,
      повторный вход не проходит;
- [ ] обрыв сети на 10–20 секунд и восстановление — повторный вход с новым пропуском (в журнале
      сайта новая выдача), без перезапуска лаунчера.

## Удаление аккаунта — план, не включено

Сейчас удаление пользователя каскадом унесло бы лишнее (`PortalDb`): его темы форума вместе с
ответами других людей (`ForumTopic.AuthorId`, `ForumPost.AuthorId` — Cascade), записи журнала
голоса о нём (`VoiceEvent.UserId` — Cascade), а с ними и записи, на которых стоят жалобы, хотя
их положено хранить год после закрытия тикета (`VoiceEventTicket`). Поэтому кнопки удаления нет.
Решения Vitali 03.10 вписаны в схему ниже; включать удаление он пока не велел.

Схема — обезличивание, а не удаление строки `PortalUser`:

1. Строка пользователя остаётся пустой оболочкой: почта и имя входа `deleted-<id>@invalid`
   (настоящая почта свободна для новой регистрации), отображаемое имя «Удалённый пользователь»,
   пароль, внешние входы и второй фактор сняты, штамп безопасности сменён (выход везде),
   блокировка навсегда, роли и права сняты.
2. Лаунчеры: привязки устройств удаляются (токены перестают работать сразу).
3. Форум: темы и сообщения остаются, автор показывается как «Удалённый пользователь»; ответы
   других людей не трогаются.
4. Голос: дружбы, заявки, блокировки, приглашения, запреты речи и свои комнаты удаляются (с
   выводом из комнат через очередь `VoiceJob`); журнал `VoiceEvent` остаётся на оболочке без имени
   и чистится по срокам §7, записи под жалобами — как положено жалобам; баны в чужих комнатах
   остаются (оболочка войти не может, а новый аккаунт — новый человек).
5. Тикеты и вики: автор и редактор уже отвязываются (SetNull) — без изменений.
6. Оценки арта (`PackReview` с кадрами `PackReviewFrame`) удаляются. Итоги дорожной карты
   (`Roadmap`) считаются из живых оценок запросом, хранимых сумм нет — они пересчитываются сами;
   тест: итог набора после удаления равен итогу, посчитанному без этого человека.
7. В журнале действий одна запись `account.delete` с идентификатором, без почты.

Отмена — 30 дней. Запрос удаления не обезличивает сразу, а ставит срок: обезличивание по пунктам
1–7 делает ежесуточная чистка, когда срок истёк, и оно необратимо. До срока человек отменяет
удаление входом на сайт. Что аккаунт может в эти 30 дней (предложение, утвердить при работе):
пропуска голоса не выдаются и из комнат он выведен, писать на форуме и ставить оценки нельзя,
вход на сайт открывает только страницу «удаление через N дней — отменить», лаунчеры отвязаны
сразу — после отмены привязываются заново.

Решено: сообщения форума остаются под «Удалённый пользователь» (Vitali 03.10); оценки арта
удаляются с пересчётом; срок отмены 30 дней. Открыто: удаляет ли администратор по просьбе, если
человек не может войти.

## Проверка перед выпуском

- [ ] Обычная сборка (`OXCE_Release.cmd`) содержит голос: `livekit_ffi.dll` и `xpaudio.dll` в
      комплекте лаунчера, раздел «Голос» на месте.
- [ ] Адрес медиасервера лаунчер берёт из пропуска портала, в сборке его нет: в `portal.env`
      станции `LiveKit__Url` — боевой (`wss://...`), не станция и не localhost; проверка —
      `station.ps1 voice-test`, вторая строка вывода `production`, не `PROBE`.
- [ ] Лог `publish.ps1` (из `OXCE_Release.cmd`) содержит строку `tools/voice_deps.py --check`
      «на месте и собраны из нынешних исходников».
- [ ] Лаунчер 0.3.7 (`launcher-stable` сейчас 0.3.6, `hd_core` требует 0.3.7) уносит игрокам
      раздел «Голос» — так решено 03.10, раздел не скрывается. Пока медиасервер — проба, игроки
      видят в нём «Голос сейчас недоступен на сервере. Попробуйте позже.»: пропуска пробы сайт
      отдаёт только тестерам. Порядок: сначала архив сайта и `station.ps1 up` (API голоса и миграция
      Voice; `up` сам снимает копию базы в `deploy\backups`), потом выпуск лаунчера. До повышения
      версии — готовая выпускная сборка: лаунчер открывается, игра запускается, обновление работает.
      Поднять `<Version>` в `Xp.Launcher.csproj` — и есть этот выпуск: автовыпуск очереди правок
      (`release.ps1`) публикует лаунчер сам, если его версии ещё нет в `launcher-stable`, и
      собирает его из рабочего дерева — незакоммиченные правки лаунчера и `Xp.Bootstrapper` уедут
      вместе с ним.
- [ ] Строк `voice-token`, `--voice`, `--record`, `loop_raw`, `--mic-file`, `--listen`,
      `--stop-device-after`, `VoiceWindow` в exe лаунчера нет (grep по exe).
- [ ] Команда `station.ps1 voice-token`, страница пробы и эхо-бот сняты со станции после переезда
      на боевую машину.
- [ ] Ключи LiveKit боевые: заданы только в `portal.env` боевой машины, в сборке их нет вовсе.
- [ ] Полный путь регистрации пройден на боевом SMTP: регистрация → письмо → подтверждение →
      вход → привязка лаунчера.
- [ ] Серия из 50 попыток после бана (§9) — ни одна не нарушила предел 60 секунд.
- [ ] Приёмка §9 VOICE_CHAT.md целиком.
