# Голос в продакшн — план и проверки выпуска

Проект голоса — `docs/portal/VOICE_CHAT.md` (0.4, утверждён 2026-09-29). Здесь — как он доводится
до выпуска игрокам после пробы этапа 1: что делается, в каком порядке, и что проверяется перед
выпуском. Решения ниже — ответы Vitali от 2026-10-03.

## Решения 2026-10-03

| Вопрос | Решение |
|---|---|
| Порядок | серверная часть портала (друзья, комнаты, приглашения, права владельца, пропуск) — сейчас; параллельно — голос в обычный лаунчер, новый пропуск на каждом входе |
| Боевой LiveKit | машина с публичным IP, как утверждено; станция остаётся пробой. Пока адреса нет — готовится конфигурация и список портов, размещение — когда машина будет готова |
| Регистрация | доводится до рабочего состояния ДО открытия комнат игрокам: SMTP через секреты на сервере, проверка пути регистрация → письмо → подтверждение → вход → привязка лаунчера. Провайдера и учётные данные Vitali сообщает отдельно, пароль в чат не идёт |
| Диагностика | записи WAV, отводы и тестовые ключи из публичной сборки убираются; безопасная диагностика звука (уровни, счётчики, устройства — без звука) включается флагом для расследования сбоев |
| Проверка выпуска | отдельно: обычная сборка содержит голос, ходит на боевой сервер с боевыми ключами, пропусков `voice-token` в ней нет |

## Части работы

**Портал (`Xp.Portal`).**
1. Таблицы §7 и миграция: `FriendRequest`, `Friendship`, `UserBlock`, `VoiceRoom`, `RoomInvite`,
   `RoomBan`, `RoomSpeakingRestriction`, `VoiceAccountBan`, `VoiceEvent`, `VoiceEventTicket`, плюс
   очередь команд медиасерверу `VoiceJob` (исключение и запрет речи повторяются из очереди, как
   `NotificationJob`).
2. Пропуск: JWT HS256 на одну минуту, `room = VoiceRoom.Id`, `identity = PortalUser.Id`,
   `canSubscribe`, `canPublish` только без запрета говорить, `roomAdmin` никогда. Ключ — только в
   `portal.env` (`LiveKit__ApiKey`, `LiveKit__ApiSecret`).
3. API `/api/v1/voice/...` (cookie сайта или `X-Device-Token`): друзья, комнаты, приглашения, вход,
   модерация, присутствие; webhook LiveKit со сверкой участника на `participant_joined`.
4. Страницы сайта: друзья, мои комнаты и приглашения, страница комнаты `/voice/rooms/{publicId}`
   с состояниями «нет доступа», «приглашение отозвано», «вы заблокированы», «комната закрыта».
5. Жалобы — тикеты категории `voice` (право `tickets.voice`); запрет голоса аккаунту и закрытие
   любой комнаты — страница суперадминистратора; ежесуточная чистка журнала по срокам §7.
6. Регистрация: адрес возврата сохраняется через регистрацию и подтверждение (путь из лаунчера к
   `/me/devices?code=`), повторное письмо подтверждения, удаление аккаунта с каскадом.

**Лаунчер.**
1. `Xp.Voice` без диагностики пробы: нет записи WAV, отводов loopback, тона, речи из файла,
   переключателей WASAPI; безопасная диагностика по флагу пишет в лог только числа.
2. Новый пропуск у портала на каждом входе и переподключении (сейчас переподключение берёт старый).
3. Раздел «Голос» в главном окне, трей, клавиша разговора с проверкой конфликта по `options.cfg`,
   ссылка `xpiratez://`.
4. Голос в обычной сборке: `build.ps1` публикует с `-Voice`, DLL голоса в списке файлов лаунчера.

**Сервер.**
1. Боевой LiveKit: compose и `livekit.yaml` с webhook на портал и TURN/TLS, свои ключи.
2. Проба снимается: команда `station.ps1 voice-token`, страница пробы, эхо-бот, ключи пробы.
3. SMTP: секреты кладутся на сервере командой, которая спрашивает пароль, не показывая его.

## Порты боевой машины

Конфигурация — `portal/deploy/voice-server` (`compose.yaml`, `setup.sh`, README): схема генератора
LiveKit, Caddy с модулем layer4 делит 443 по имени между сигналингом и TURN/TLS. Сайт остаётся на
станции; ключи LiveKit создаёт `setup.sh` на медиасервере, на станцию их вносит `station.ps1 livekit`
(секрет скрытым вводом), связь проверяет `station.ps1 voice-test` (`Xp.Portal voice check`).

| Порт | Что |
|---|---|
| 80/TCP | выпуск сертификатов Let's Encrypt (HTTP-01) |
| 443/TCP | по имени сервера — сигналинг и API комнат; по имени `turn.` — TURN/TLS |
| 7881/TCP | медиа, если у игрока закрыт UDP |
| 7882/UDP | медиа, один порт на всех (UDP mux) |
| 3478/UDP | TURN/UDP для строгих NAT |

7880 и 5349 наружу не открываются: к ним ходит только Caddy на той же машине. Машине нужны Linux
(сеть хоста), постоянный IPv4 и два имени DNS — сервера и TURN.

## Проверка перед выпуском

- [ ] Обычная сборка (`OXCE_Release.cmd`) содержит голос: `livekit_ffi.dll` и `xpaudio.dll` в
      комплекте лаунчера, раздел «Голос» на месте.
- [ ] Адрес медиасервера в сборке — боевой (`wss://...`), не станция и не localhost.
- [ ] Строк `voice-token`, `--record`, `loop_raw`, `--mic-file` в exe лаунчера нет (grep по exe).
- [ ] Ключи LiveKit боевые: заданы только в `portal.env` боевой машины, в сборке их нет вовсе.
- [ ] Полный путь регистрации пройден на боевом SMTP: регистрация → письмо → подтверждение →
      вход → привязка лаунчера.
- [ ] Серия из 50 попыток после бана (§9) — ни одна не нарушила предел 60 секунд.
- [ ] Приёмка §9 VOICE_CHAT.md целиком.
