# Проба голоса на станции — этап 1, часть А

Проект — `VOICE_CHAT.md` (утверждён, версия 0.4). Это инструкция и протокол пробы. Результаты
вписываются в раздел «Протокол» этого файла.

**Что проверяет часть А:** медиасервер LiveKit на станции, доступность портов снаружи, разговор двух
человек из разных сетей, задержку, переподключение и звук при запущенной игре. Клиент здесь —
страница пробы в браузере.

**Чего часть А не проверяет** — это часть Б, прототип лаунчера:
- клиент в NativeAOT;
- глобальную клавишу разговора;
- трей;
- размер DLL.

Два порта 7882/UDP и 7881/TCP — начало пробы, а не схема боевого сервера. TURN/TLS для сетей без
UDP проверяется на машине с публичным IP.

## Что приезжает в архиве сайта

| Файл | Что это |
|---|---|
| `portal/deploy/compose.voice.yaml` | LiveKit (`livekit/livekit-server`) и эхо-бот поверх стека станции |
| `portal/deploy/voice-probe/livekit.yaml` | настройки LiveKit: 7881/TCP, 7882/UDP (один порт на всех), внешний IP через STUN |
| `portal/deploy/voice-probe/echo/` | эхо-бот (Python, официальный SDK LiveKit): возвращает писк страницы для замера задержки |
| `portal/deploy/voice-probe/web/index.html` | страница пробы `/voice-probe/`: подключение, участники, сеть, замер задержки, журнал |
| `Caddyfile.station`, `Caddyfile.internet` | маршруты `/rtc` (сигналинг LiveKit) и `/voice-probe/` |
| `station.ps1` | команды `voice`, `voice-check`, `voice-token`, `voice-off` |

Пропуск в комнату `probe` выдаёт `station.ps1 voice-token`. Это JWT, подписанный ключом из `.env`.
Он лежит в адресе после `#`, поэтому в журналы сервера не попадает. Портал в пробе не участвует:
друзья, комнаты и права появятся на этапах 2–3.

## Порядок

### 0. Подготовка

1. На станции разложить новый архив сайта (`pack.ps1`) поверх прежнего. `.env` и `portal.env` не
   трогаются.
2. Сайт в режиме `internet`: `.\station.ps1 status` — `Healthy`, а сайт открывается с телефона на
   мобильном интернете по `https://x-piratez.mywire.org:<HTTPS_PORT>`.
3. На роутере пробросить на станцию **7882/UDP** и **7881/TCP**.

### 1. Сервер и порты изнутри

```powershell
cd portal\deploy
powershell -ExecutionPolicy Bypass -File .\station.ps1 voice
```

Команда создаёт ключи LiveKit в `.env`, запускает `livekit`, `voice-echo` и `caddy` и печатает
проверку `voice-check`. Всё должно быть так:

- `сигналинг /rtc через Caddy: отвечает LiveKit (HTTP 401)`;
- `7881/TCP на машине: слушает`, `7882/UDP на машине: открыт`;
- брандмауэр — есть входящее правило Docker для профиля текущей сети (строка «профиль сети»);
- `livekit:` — строка с внешним IP совпадает с `внешний IP по DNS`;
- эхо-бот — последняя строка `connected`.

### 2. Порты снаружи

- **TCP 7881.** С машины в другой сети, например ноутбука на раздаче с телефона:
  `Test-NetConnection x-piratez.mywire.org -Port 7881` → `TcpTestSucceeded : True`.
  Если такой машины нет — любой онлайн-проверщик TCP-порта.
- **UDP 7882.** Выдать ссылку: `.\station.ps1 voice-token phone`. Открыть её на телефоне **с
  выключенным Wi-Fi** и нажать «Подключиться». Раздел «Сеть» должен показать:
  - `транспорт: udp`;
  - `адрес медиасервера: <внешний IP>:7882`.

  Если там `tcp` и порт 7881, UDP снаружи не проходит, а TCP проходит. Это тоже результат, его
  записать.

### 3. Разговор двух людей из разных сетей

- Участник A — ПК дома. Участник B — телефон на мобильном интернете или друг в другой сети.
  Ссылки разные: `voice-token vitali`, `voice-token phone`. Одно имя — одно подключение.
- Оба включают микрофон и говорят пару минут. Записать: слышно ли обоих, есть ли обрывы, эхо,
  «робот».
- **Грабли.** Если ПК дома не подключается к `x-piratez.mywire.org` из своей же сети, роутер не
  умеет NAT loopback. Тогда ПК подключают через раздачу с телефона. Это не ошибка сервера.

### 4. Задержка

- Каждый участник нажимает «Замерить» (30 сигналов, ~20 секунд), не трогая сеть.
- Страница показывает два числа, точность ±11 мс:
  - **круг** — сигнал до эхо-бота и обратно (мин / медиана / 95% / макс);
  - **сеть** — RTT до сервера по ICE в момент каждого сигнала (медиана / макс).
- В отчёт записать оба числа как есть и число потерянных сигналов.

**Круг — не задержка разговора, и делить его пополам нельзя.** Эхо-бот добавляет собственную
задержку: декодирует сигнал и кодирует заново, а по пути стоят два джиттер-буфера. В разговоре
A→B этого прохода через бота нет. Локально 29.09 (LiveKit 1.13.7 на той же машине, сеть 1 мс)
медиана круга в трёх сериях была 139, 162 и 225 мс, и это вся без остатка цена замера.
Поэтому круг и сеть — справочные числа для сравнения прогонов, а не порог.

**Качество решает разговор двух людей** (шаг 3): слышно ли друг друга, нет ли заметной
задержки, обрывов, «робота». Решение принимает Vitali. Для проверки замера: потерянных сигналов
0 из 30.

### 5. Переподключение

1. **Телефон:** во время разговора переключить Wi-Fi на мобильные данные и обратно.
2. **ПК:** отключить сетевой адаптер на 5 секунд и включить.
3. **ПК:** то же на 30 секунд.

Журнал страницы пишет `обрыв медиа, переподключаюсь` и `переподключено за N мс`, либо `отключено`.

**Порог:** после коротких обрывов (1–2) разговор возвращается сам, без перезагрузки страницы, не
позже чем через 5 секунд после возврата сети. Для обрыва на 30 секунд записать, что произошло.

Время считается от первого обрыва, сигнального или медиа, до `переподключено`. Строка
`переподключение висит больше 20 с - захожу заново` — провал порога, даже если потом голос
вернулся: страница зашла заново сама, лаунчер так уметь обязан, а библиотека сама не смогла.
Локально так было после перезапуска сервера целиком во вкладке, которая была в фоне.

### 6. Голос при запущенной игре

- На ПК открыть страницу, подключиться, включить микрофон.
- Запустить игру из лаунчера (полный экран) и провести 10 минут в бою, разговаривая с участником B.

**Порог:**
- голос в обе стороны не пропадает;
- игра не тормозит заметно (F8-дамп или строка HD perf до и во время);
- после выхода из игры звук на месте;
- в журнале страницы нет `переподключение висит`: вкладка всё это время в фоне, а Chrome
  замедляет таймеры фоновых вкладок.

Клавиша разговора здесь не проверяется: браузер её не умеет, это часть Б.

### 7. Отчёт

На каждом устройстве нажать «Скопировать отчёт» (JSON: сеть, задержка, переподключения, журнал) и
вставить в `REPORT.md` станции. Выводы вписать в протокол ниже.

### Убрать пробу

`.\station.ps1 voice-off` — LiveKit и эхо-бот удаляются, сайт остаётся. После этого проброс портов
на роутере можно снять.

## Если что-то не так

| Признак | Где смотреть |
|---|---|
| `HTTP 404` на `/rtc` | Caddy со старым Caddyfile: `.\station.ps1 voice` пересоздаёт caddy |
| `HTTP 502` на `/rtc` | `docker compose ... logs livekit`: не стартовал, ключ короче 32 знаков |
| «Подключиться» висит, потом ошибка | сигналинг прошёл, медиа нет: смотреть транспорт в «Сети», проброс и брандмауэр |
| транспорт всегда `tcp` | UDP 7882 режет роутер, брандмауэр или провайдер |
| эхо-бот не ответил за 5 секунд | `logs voice-echo`: `connected` есть? бот ходит к LiveKit внутри сети Docker |
| после смены IP дома никто не подключается | LiveKit узнаёт IP при старте: `docker compose ... restart livekit` |

**Запасной путь — если UDP через Docker Desktop не проходит, а проброс верный.** Docker Desktop
пропускает UDP через свой прокси, а LiveKit рассчитан на host-сеть. Тогда запустить
`livekit-server.exe` для Windows прямо на станции с тем же `livekit.yaml` и заменить в Caddyfile
адрес `livekit:7880` на `host.docker.internal:7880`. Это решение записывается в протокол.
