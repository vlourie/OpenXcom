# Комплекты, компоненты и невидимый лаунчер

Проект, не решение: после согласования уходит записью в `docs/DECISIONS.md`, а схемы — в
`ARCHITECTURE.md`. Читать вместе с ARCHITECTURE §3.1, §3.2 и §4.

## 1. Что нужно

Игрок выбирает и скачивает один из четырёх комплектов:

| № | Комплект | Движок | Арт |
|---|---|---|---|
| 1 | Оригинал | OXCE как у Meridian | Пиратки Dioxine как есть |
| 2 | HD | наш OXCE | Пиратки + HD-арт |
| 3 | HD 18+ | наш OXCE | Пиратки + HD-арт + 18+ (выбор при запуске, `AdultChoiceState`) |
| 4 | Наши Пиратки с оригинальным артом | наш OXCE | Пиратки без HD-паков |

Кроме того:

- вступление на шести языках встроено в игру, а не лежит отдельным модом, который надо включать;
- лаунчер становится **невидимым помощником**: игрок запускает игру, об обновлении узнаёт
  в главном меню, а окно лаунчера видит, только когда обновляется или пишет отчёт;
- позже на той же схеме живут другие моды X-COM (XCF уже лежит в `user/mods/XComFiles`).

## 2. Главная мысль: комплекты 2, 3 и 4 — одна установка с переключателями

Комплекты 2–4 отличаются только набором файлов поверх общего основания: наш exe, наши `common`
и `standard`, Пиратки, вступление. HD-арт и 18+ — **компоненты**, которые ставятся и снимаются
галочкой, без переустановки. 4 ⊂ 2 ⊂ 3.

Комплект 1 — **отдельная папка**: у него свой exe и свои `common`/`standard`, в одной папке
с нашими они бы затирали друг друга.

Итого у игрока не больше двух установок на мод:

```
X-Piratez\            оригинал: OpenXComEx.exe Meridian, common/standard Dioxine, user\mods\Piratez
X-Piratez HD\         наш: openxcom_hd.exe, наши common/standard, Piratez, intro,
                      [hd] [hd 18+]  <- переключатели
```

Сохранения совместимы в обе стороны (механику мы не меняем), но у каждой папки свой `user\`.
Перенос сейвов между установками — кнопка в лаунчере, позже.

## 3. Каталог — что вообще можно скачать

Новый подписанный файл в хранилище релизов, лаунчер читает его первым:

```
catalog.json + catalog.json.sig
```

```json
{
  "schema": 1, "sequence": 7,
  "products": [
    { "id": "piratez", "title": {"ru": "X-Piratez", "en": "X-Piratez"},
      "lines": [
        { "id": "original", "title": {"ru": "Оригинал"}, "channels": ["piratez-original-stable"] },
        { "id": "hd", "title": {"ru": "HD"}, "channels": ["piratez-hd-stable", "piratez-hd-test"],
          "components": [
            { "id": "base",  "required": true },
            { "id": "intro", "required": true },
            { "id": "hd",    "default": true,  "size": 0 },
            { "id": "hd18",  "default": false, "requires": ["hd"], "adult": true }
          ] }
      ] }
  ]
}
```

- Новый мод или новая линия — это новая запись в каталоге и новые каналы, **без выпуска
  лаунчера**.
- `sequence` защищает от отката каталога так же, как у указателя канала.
- Комплекты для игрока — это пресеты галочек: «HD» = base+intro+hd, «HD 18+» = +hd18,
  «оригинальный арт» = base+intro.

## 4. Manifest, схема 2

Поле `component` у файла уже есть в схеме 1. Добавляется:

- раздел `components`: id, заголовок на языках, размер, `requires`, `adult`;
- `deletes` у каждого компонента свои;
- правило разметки при сборке: `ReleaseBuilder` получает таблицу «префикс пути → компонент»
  (`user/mods/hd/hd_18+/` → `hd18`, `user/mods/hd/hd/` → `hd`, остальное — `base`).
  Файл без правила — ошибка сборки, а не молчаливый `base`.

Лаунчер ставит только выбранные компоненты. Снятие галочки удаляет файлы компонента. Скачанные
блобы остаются в локальном кэше (`launcher/cache/`, по SHA-256), поэтому повторное включение
идёт без сети. Лимит кэша настраивается.

`InstallPolicy` не меняется: запись только в `roots`, в `user/` — только в
`user/mods/<мод>/`, сейвы и `options.cfg` не трогаются никогда.

## 5. Уже установленные Пиратки — не качать 1,9 ГБ заново

У большинства игроков Пиратки уже стоят. При выборе папки лаунчер хэширует её (быстрая
проверка, как при восстановлении) и сравнивает с манифестом:

- совпало с «Оригиналом» — установка **принята как есть** (adopt), скачивать нечего;
- ставится HD рядом — совпадающие файлы копируются из этой папки локально, из сети приходят
  только наш exe, `common`/`standard`, вступление и арт.

Источник файла для загрузчика — «сеть или локальный файл с тем же SHA-256», хэш
проверяется одинаково.

## 6. Вступление внутри игры

- Движок уже выбирает вариант катсцены по языку: `intro_ru` рядом с `intro` (правка в
  `CutsceneState.cpp`). Схема на N языков: `intro_<язык>` + дорожка `intro_voice_<язык>.ogg`.
  Нет своего языка — `intro_en`, нет и его — обычный `intro` Пираток.
- Слайды общие, свои у языка только голос и подписи (подписи — строками мода).
- Шесть голосовых дорожек по 5–6 минут в OGG — десятки мегабайт, поэтому ставятся **все**:
  сменил язык в игре — вступление сразу на нём.
- Где лежит: отдельный мод `user/mods/xp_intro/` в компоненте `intro` линии HD. Чтобы игроку
  не надо было его включать, движок включает мод с `autoEnable: true` в `metadata.yml` **один
  раз**, когда тот впервые появился, и помнит это. Выключил игрок сам — больше не
  включается. Та же метка пригодится моду `hd`.
- Грабли R-032 остаются: голос идёт по каналу музыки. При `musicVolume: 0` вступление немое,
  поэтому движку стоит поднимать громкость музыки на время вступления, если она на нуле.

## 7. Невидимый помощник

1. Игра на старте запускает `XPiratezLauncher.exe --headless check --status <файл>` без окна
   и не ждёт его. Сети в C++ по-прежнему нет.
2. Лаунчер пишет `launcher/status.json`: есть ли обновление, версия, размер, обязательное ли.
3. Главное меню читает файл, если он появился, и показывает строку
   «Доступно обновление 1.3 (240 МБ) — Обновить». Кнопка сохраняет опции, закрывает игру и
   запускает лаунчер с `--update-and-play`: окно показывает только прогресс, а после установки
   снова запускает игру.
4. Первое открытие лаунчера (установка) — экран выбора комплекта с карточками из каталога.
   Дальше лаунчер открывается сам только на обновление, отчёт F8 и «Проверить/восстановить».
   Выбор компонентов и канала — в меню опций игры, строкой «Лаунчер…».

Правка движка: запуск процесса, чтение одного JSON, строка с кнопкой в главном меню.

## 8. 18+

- Компонент `adult: true` лаунчер ставит только после подтверждения возраста. Подтверждение
  хранится в `settings.json` лаунчера, а не в папке игры.
- На сайте страница загрузки 18+ — за таким же подтверждением.
- Не установлен компонент — `AdultChoiceState` не показывается (`adultArtShipped` уже это
  проверяет).
- Где физически лежит 18+-арт (страна сервера и CDN) — вопрос юридический, решает владелец
  проекта.
- **Замер 2026-09-23:** `user/mods/hd/hd` — 5043 файла, 2,2 ГБ (из них UI 2,09 ГБ);
  `hd_18+` — 4977 файлов, 2,2 ГБ, и **все 4977 байт в байт совпадают** с файлами `hd` по тем же
  путям. Своего 18+-арта в папке пока нет. Хранилище по содержимому скачает такие файлы один
  раз, но на диске игрока они займут место дважды. В компонент `hd18` должны входить только
  файлы, которые **отличаются** от `hd`: `ReleaseBuilder` выбрасывает из `hd_18+` точные копии
  (движок и так берёт обычный кадр, если 18+-варианта нет) и печатает, сколько выбросил.

## 9. Другие моды

Продукт = мастер-мод. Мод `hd` объявлен с `master: "*"`, а паки террейна привязаны к именам
наборов. Поэтому HD-арт ванильных наборов работает и в XCF, который стоит на `xcom1`. Для
нового мода в каталоге появляется продукт со своими каналами. В линии HD один `openxcom_hd.exe`
может держать несколько мастер-модов в одной папке: компонентами становятся сами моды.

## 10. Порядок работ

1. Каталог, manifest схемы 2, разметка компонентов в `ReleaseBuilder`, два канала Пираток на
   dev-сервере.
2. Лаунчер: выбор комплекта при первой установке, компоненты, кэш блобов, приём
   существующей установки, подтверждение возраста.
3. Движок: `autoEnable`, фоновая проверка и строка обновления в главном меню, запуск лаунчера
   на обновление.
4. Вступление на шести языках — как только готовы дорожки.
5. Страница загрузки на сайте по каталогу.
6. Оформление лаунчера и сайта — после утверждения арта (см. ниже).

Этап 4 ТЗ (отчёты о падениях) от этого не зависит и идёт параллельно или следом.

## 11. Открытые вопросы (решает владелец проекта)

1. **Языки вступления** — какие шесть?
2. **Что входит в «Оригинал».** Релиз Dioxine как есть — или с RU-патчем (XPZ RU-patch,
   OAK patch), наборами имён и Cities Lore? Это чужие работы: разрешение Dioxine покрывает
   Пиратки, а на раздачу патчей нужно согласие их авторов.
3. **Версия OXCE для «Оригинала»** — последний релиз Meridian или та, под которую выпущены
   текущие Пиратки (`requiredExtendedVersion`).
4. **Оформление.** Лаунчер и сайт получают арт после утверждения окончательного варианта;
   до этого — нейтральная тёмная тема без картинок.
