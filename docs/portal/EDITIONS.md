# Комплекты, компоненты и невидимый лаунчер

Проект, не решение: после согласования уходит записью в `docs/DECISIONS.md`, а схемы — в
`ARCHITECTURE.md`. Читать вместе с ARCHITECTURE §3.1, §3.2 и §4.

## 1. Что нужно

Игрок выбирает, что скачать:

| № | Комплект | Движок | Мод и арт |
|---|---|---|---|
| 1 | Оригинал | OXCE Meridian | релиз Dioxine как есть |
| 2 | HD | наш OXCE-HD | наши Пиратки + HD-арт |
| 3 | HD 18+ | наш OXCE-HD | наши Пиратки + HD-арт + 18+ (выбор при запуске, `AdultChoiceState`) |
| 4 | Наши Пиратки, оригинальный арт | наш OXCE-HD | наши Пиратки без HD-паков |

Кроме того:

- **Вступление встроено в игру** на языках: сейчас ru, en, de, es, it, pl, список не
  окончательный. Новый язык появляется в игре сам, стоит добавить его запись — без правки
  кода. Картинки у всех языков общие, в трёх видах: оригинал, HD, HD 18+.
- **Дополнения** (RU-патч, OAK patch, наборы имён, Cities Lore…) не входят ни в один
  комплект — это отдельные галочки, привязанные к своему моду.
- **Несколько модов в одной папке**: Пиратки и RoSigma (и дальше XCF и другие) ставятся в одну
  установку движка, а не в две копии игры.
- **Наши Пиратки на OXCE Meridian не ставятся**: там нет ×4 и остального.
- **Лаунчер — невидимый помощник**: игрок запускает игру, об обновлении узнаёт в главном меню.

## 2. Установка = движок, моды внутри неё — компоненты

Проверено на установке Пираток (2026-09-23): всё содержимое Пираток лежит в
`user/mods/Piratez`, а `common`/`standard` стандартные для OXCE. Совпадают с нашими 240 и 616
файлами, различий 0. Значит, папку делит между собой любое число мастер-модов, и так
OXCE и задуман.

Установка — это **линия движка**. Всё остальное — компоненты внутри неё:

```
X-COM (OXCE)\       OpenXComEx.exe Meridian + common/standard
    user\mods\Piratez           релиз Dioxine
    user\mods\ROSIGMA           …
    user\mods\XPZ RU-patch      дополнение, master: piratez
X-COM HD\           openxcom_hd.exe + наши common/standard
    user\mods\Piratez           наши Пиратки
    user\mods\ROSIGMA
    user\mods\hd                hd\  -> компонент hd,  hd_18+\ -> компонент hd18
    user\mods\xp_intro          вступление
```

Комплекты 2–4 — это одна установка «X-COM HD» с разными галочками (4 ⊂ 2 ⊂ 3), комплект 1 —
установка «X-COM (OXCE)». Обе могут стоять рядом. Сейвы совместимы (механику мы не меняем),
но у каждой установки свой `user\`: перенос сейвов — кнопка в лаунчере, позже.

### Кто к чему привязан — читается из самих модов, руками не пишется

`ReleaseBuilder` при сборке читает `metadata.yml` каждого мода. Так же делает лаунчер с модами,
которые игрок поставил сам:

| Поле мода | Что значит для каталога |
|---|---|
| `isMaster: true` | мастер-мод, отдельная карточка («Пиратки», «RoSigma») |
| `master: piratez` | дополнение Пираток: видно и ставится только при установленных Пиратках |
| `master: "*"` | общее для всех модов (hd, вступление) |
| `requiredExtendedEngine: "OXCE-HD"` | только для нашего движка |

**Защита от «наших Пираток на оригинальном OXCE»** держится с двух сторон:

- движок: в `ModInfo.cpp` у OXCE есть список поддерживаемых движков (`supportedEngines`),
  так форки и отделяются. Наш движок добавляет туда `"OXCE-HD"`, а наши моды объявляют
  `requiredExtendedEngine: "OXCE-HD"`. OXCE Meridian такой мод не загрузит сам, даже если
  скопировать его руками. Правка — одна строка в списке, механики не касается;
- лаунчер: не предложит такой компонент для установки Meridian и скажет почему.

Дополнение, чей мастер не установлен, в списке показывается серым: «нужен мод X-Piratez».
Удаление мастера спрашивает, удалить ли его дополнения.

## 3. Каталог — что вообще можно скачать

Новый подписанный файл в хранилище релизов, лаунчер читает его первым:
`catalog.json` + `catalog.json.sig`.

```json
{
  "schema": 1, "sequence": 7,
  "lines": [
    { "id": "oxce",    "title": {"ru": "Оригинальный OXCE"}, "channels": ["oxce-stable"] },
    { "id": "oxce-hd", "title": {"ru": "OXCE-HD"},           "channels": ["hd-stable", "hd-test"] }
  ],
  "presets": [
    { "id": "piratez-original", "line": "oxce",    "components": ["engine", "piratez"] },
    { "id": "piratez-hd",       "line": "oxce-hd", "components": ["engine", "piratez", "intro", "hd"] },
    { "id": "piratez-hd18",     "line": "oxce-hd", "components": ["engine", "piratez", "intro", "hd", "hd18"] },
    { "id": "piratez-classic",  "line": "oxce-hd", "components": ["engine", "piratez", "intro"] }
  ]
}
```

- Карточки при первой установке — это `presets`: готовые наборы галочек.
- Состав компонентов, размеры и привязки лежат в manifest каждой линии (§4). Каталог только
  называет линии, каналы и пресеты.
- Новый мод или новая линия — запись в каталоге и новые каналы, **без выпуска лаунчера**.
- `sequence` защищает от отката каталога так же, как у указателя канала.

## 4. Manifest, схема 2

Поле `component` у файла уже есть в схеме 1. Добавляется раздел `components`:

```json
"components": [
  { "id": "engine",  "kind": "engine", "required": true },
  { "id": "piratez", "kind": "master", "mod": "piratez", "version": "v.o1.1.1", "size": 0 },
  { "id": "xpz-ru",  "kind": "addon",  "mod": "XPZ_EX_RU-patch", "master": "piratez" },
  { "id": "intro",   "kind": "addon",  "mod": "xp_intro", "master": "*" },
  { "id": "hd",      "kind": "art" },
  { "id": "hd18",    "kind": "art", "requires": ["hd"], "adult": true }
]
```

Разметка файлов при сборке — по правилам, без списков руками:

| Путь | Компонент |
|---|---|
| `user/mods/<мод>/hd_18+/…` в любом моде | `hd18` |
| `user/mods/<мод>/hd/…` в любом моде | `hd` |
| остальное в `user/mods/<мод>/` | компонент этого мода |
| exe, `common/`, `standard/`, DLL | `engine` |

Файл, который не попал ни под одно правило, останавливает сборку.

- **Копии в `hd18` выбрасываются.** Замер 2026-09-23: в `user/mods/hd/hd_18+` 4977 файлов на
  2,2 ГБ, и все они **байт в байт** совпадают с `hd` по тем же путям. Движок и так берёт
  обычный кадр, если 18+-варианта нет (`HdSprites::artPath`), поэтому в компонент идут только
  отличающиеся файлы. `ReleaseBuilder` печатает, сколько копий выбросил.
- Лаунчер ставит только выбранные компоненты. Снятие галочки удаляет файлы компонента.
  Скачанные блобы остаются в локальном кэше (`launcher/cache/`, по SHA-256), поэтому
  повторное включение идёт без сети. Лимит кэша настраивается.
- `InstallPolicy` не меняется: запись только в `roots`, в `user/` — только в
  `user/mods/<мод>/`, сейвы и `options.cfg` не трогаются никогда.

## 5. Уже установленная игра — не качать гигабайты заново

У большинства игроков Пиратки уже стоят. Лаунчер хэширует указанную папку и сравнивает с
манифестом:

- совпало с линией «OXCE» — установка **принята как есть** (adopt), скачивать нечего;
- ставится «X-COM HD» — совпадающие файлы копируются из той папки локально, из сети приходят
  только отличия.

Источник файла для загрузчика — «сеть или локальный файл с тем же SHA-256», хэш
проверяется одинаково.

Моды, которые игрок поставил сам и которых нет в каталоге, лаунчер не трогает (`InstallPolicy`).
Он лишь показывает, к какому мастеру они привязаны.

## 6. Вступление

- **Язык появляется сам.** Голос каждого языка лежит в своей папке у сборщика
  (`E:\intro\voice\<язык>\01.wav…`). `tools/intro/build_intro.py` проходит все папки и на
  каждую делает катсцену `intro_<язык>` и дорожку `intro_voice_<язык>.ogg`. Движок уже
  выбирает катсцену по языку игры (`intro_ru` рядом с `intro`, `CutsceneState.cpp`).
  Добавить язык = положить папку голоса и пересобрать, без правки кода. Дальше новые файлы
  приходят игроку обычным обновлением.
- Нет своего языка — `intro_en`, нет и его — обычный `intro` Пираток.
- **Картинки общие для всех языков, в трёх видах**, по тому же правилу, что и весь арт:

  | Вид | Путь в моде `xp_intro` | Компонент |
  |---|---|---|
  | оригинал | `Resources/Intro/intro_NN.png` (320×200) | `intro` |
  | HD | `hd/UI/intro_NN.png` | `hd` |
  | HD 18+ | `hd_18+/UI/intro_NN.png` | `hd18` |

  Комплект 4 показывает оригинальные слайды, 2 — HD, 3 — 18+, если игрок его выбрал.
- Дорожки ставятся все: шесть по 5–6 минут в OGG — десятки мегабайт, сменил язык в игре —
  вступление сразу на нём.
- Мод `xp_intro` включается сам: движок включает мод с `autoEnable: true` в `metadata.yml`
  **один раз**, когда тот впервые появился, и помнит это. Выключил игрок сам — больше не
  включается. Та же метка нужна моду `hd`.
- Грабли R-032: голос идёт по каналу музыки, при `musicVolume: 0` вступление немое. Движку
  стоит поднимать громкость музыки на время вступления, если она на нуле.

## 7. Невидимый помощник

1. Игра на старте запускает `XPiratezLauncher.exe --headless check --status <файл>` без окна
   и не ждёт его. Сети в C++ по-прежнему нет.
2. Лаунчер пишет `launcher/status.json`: есть ли обновление, версия, размер, обязательное ли.
3. Главное меню читает файл, если он появился, и показывает строку
   «Доступно обновление 1.3 (240 МБ) — Обновить». Кнопка сохраняет опции, закрывает игру и
   запускает лаунчер с `--update-and-play`: окно показывает только прогресс, а после установки
   снова запускает игру.
4. Первое открытие лаунчера — выбор комплекта карточками из каталога. Дальше окно открывается
   само только на обновление, отчёт F8 и «Проверить/восстановить». Компоненты, дополнения и
   канал — в меню опций игры, строкой «Лаунчер…».

## 8. 18+

- Компонент с `adult: true` лаунчер ставит только после подтверждения возраста. Подтверждение
  хранится в `settings.json` лаунчера, а не в папке игры.
- На сайте страница загрузки 18+ — за таким же подтверждением.
- Не установлен компонент — `AdultChoiceState` не показывается (`adultArtShipped` уже это
  проверяет).
- Где физически лежит 18+-арт (страна сервера и CDN) — решает владелец проекта.

## 9. Порядок работ

1. **Сборка:** manifest схемы 2, разметка компонентов по правилам, выброс копий `hd18`, чтение
   `metadata.yml` (мастер, дополнение, движок), каталог; две линии на dev-сервере.
2. **Движок:** `"OXCE-HD"` в `supportedEngines`, `autoEnable`, фоновая проверка и строка
   обновления в главном меню, запуск лаунчера на обновление.
3. **Лаунчер:** выбор комплекта, компоненты и дополнения с привязкой к мастеру, кэш блобов,
   приём существующей установки, подтверждение возраста.
4. **Вступление:** `build_intro.py` по папкам языков, мод `xp_intro`, три вида картинок.
5. **Сайт:** страница загрузки по каталогу.
6. **Оформление** лаунчера и сайта — после утверждения арта. До этого нейтральная тёмная
   тема, но раскладка уже правильная: большая «Играть», редкое — в меню.

Этап 4 ТЗ (отчёты о падениях) от этого не зависит.

## 10. Решено 2026-09-23

- Языки вступления: ru, en, de, es, it, pl — пока неточно, поэтому язык определяется папкой,
  а не списком в коде.
- «Оригинал» — только релиз Dioxine. Патчи и дополнения — отдельные галочки с привязкой к
  своему мастеру.
- OXCE для «Оригинала» — релиз Meridian.
- Один каталог игры на несколько мастер-модов внутри одной линии движка.

## 11. Открыто

- Раздача чужих дополнений (RU-патч, OAK patch, наборы имён) через наш сервер требует согласия
  их авторов. Без него лаунчер может показывать ссылку на страницу автора вместо загрузки.
- RoSigma и другие моды: у каждого свой автор и своё разрешение на раздачу.
