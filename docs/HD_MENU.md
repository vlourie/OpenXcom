# Меню HD: настройки и проверка арта игроками

Статус: проект, 2026-09-23. Порядок работ — в конце. Связано: `docs/portal/EDITIONS.md` (линии,
комплекты, невидимый помощник), `tools/hdart/review_floors.py` и `pedia_review.py` (приёмка арта у нас).

## 1. Вкладка «HD» в настройках

Сейчас всё HD лежит в «Дополнительно» вперемешку с опциями OXCE: 9 строк с описаниями
(`oxceHdScale`, `oxceHdMode`, `oxceHdLight`, `oxceHdGroundVariants`, `oxceHdPictures`,
`oxceHdUiSmooth`, `oxceHdUi`, `oxceHdUiSkin`, `oxceHdUiFont`) и 4 без описаний, которых игрок не
видит вообще (`oxceHdThreads`, `oxceHdFrameSkip`, `keyBattleHdModeToggle`, `keyBattleHdTestDump`).
Выбор арта (`oxceAdultArt`, `oxceAdultAsk`) меняется только вопросом при запуске.

**Где.** Восьмая кнопка в левой колонке `OptionsBaseState`: y = 148, под «Папками». Место
свободно (колонка кончается на 144, OK/Отмена на 176), остальные кнопки не двигаются.
Кнопка есть всегда в нашем движке. Если мод hd выключен, экран говорит об этом первой строкой
и даёт его включить — иначе игрок крутит опции, которые ни на что не действуют.

**Что внутри** (список того же вида, что в «Дополнительно», с описанием внизу):

| Группа | Опции |
|---|---|
| Арт | версия арта: оригинал / HD / HD 18+ (`oxceHdMode` 0 и `oxceAdultArt`, см. ниже); спрашивать при запуске (`oxceAdultAsk`) |
| Поле боя | масштаб, HD-спрайты, свет, варианты земли |
| Интерфейс | HD-интерфейс, вид, шрифт, HD-картинки, сглаживание |
| Скорость | потоки (`oxceHdThreads`, 0 = все ядра), пропуск кадров (`oxceHdFrameSkip`) — получают описания |
| Клавиши | переключение режима (F9), дамп кадра для сравнения (Ctrl+F8) |
| Помочь проекту | кнопка «Проверить арт» — раздел 2 |
| Обновления | строка невидимого помощника: версия, «доступно обновление», кнопка проверки |

«HD 18+» в выборе появляется только после подтверждения возраста — тем же вопросом, что сейчас
задаёт `AdultChoiceState`, и тем же хранением (в лаунчере — `settings.json`, см. EDITIONS).

**Как, с минимальным дифом.** Новый `OptionsHdState` на базе `OptionsBaseState`, список строится
тем же `addSettings` из `OptionInfo`, у HD-опций в `Options.cpp` своя категория `STR_HD` вместо
`STR_GENERAL`/`STR_BATTLESCAPE`. «Дополнительно» категорию `STR_HD` не показывает — это одна
проверка при построении списка. Особые случаи (`oxceHdUiFont` по имени, применение шрифта на месте)
переезжают как есть. Строки опций и новых групп — в `bin/common/Language/OXCE/*.yml`, где уже лежат
все `STR_HD_*`: **Святое правило** (предупредить до правки, перенести в Пиратки, написать отдельно).
Класть их в мод hd нельзя: экран показывается и при выключенном моде (грабли R-036).

Механику не трогает: меняется только место, где показаны уже существующие опции.

## 2. Проверка арта игроками («Проверить арт»)

Цель — бета-тестеры. Игрок, который хочет помочь, открывает просмотр в самой игре, листает пары
«оригинал | HD», отмечает брак и одной кнопкой отправляет файл с отметками на сайт. Нам приходит не
«что-то не так с пустыней», а список конкретных кадров конкретной версии арта.

### Просмотр

- Отдельный экран из вкладки HD, вне кампании: сейвы и механика не участвуют.
- Слева оригинал (nearest ×k, пиксели остаются пикселями), справа HD-кадр — оба на том фоне,
  где их покажет игра: у боя тёмный пол, а не шахматка (R-041).
- Полы и проходимые объекты показываются **полем** 5×5, а не одним ромбом: решётка и повтор
  видны только в укладке (R-005, R-039). Картинки педии и интро — рядом с заголовком статьи.
  Юниты — кадр и его анимация по кругу.
- Клавиши как в `review_floors.py`, чтобы у нас и у тестеров был один язык: стрелки листают,
  **1** годно, **2** брак, **3** сомнительно, **0** снять. При 2 и 3 — причина одной кнопкой:
  цвет, форма, подложка/фон, не тот предмет, шов/решётка, другое; плюс короткий комментарий
  (`TextEdit` движка).
- Кадры берутся через `HdSprites` лениво, по одному; попиксельной работы нет, только блиты (R-009).
- 18+ кадры показываются только после подтверждения возраста.

### Что сохраняется

`user/art_review/<дата>_<время>.tsv`, UTF-8, одна строка на отметку:

```
engine  hdVersion  set  frame  sha256  verdict  reason  comment  lang  nick
```

`nick` — последнее поле, необязательное: ник или имя, которое тестер один раз вписывает в
просмотре (строка «Как вас подписать», можно оставить пустой). Просмотр запоминает его в
`user/art_review/nick.txt` и подставляет в следующие файлы; в `options.cfg` он не пишется.
Если файл пришёл через сайт от вошедшего пользователя, портал ставит ник его учётной записи и
этим полем не пользуется. Ник виден в сводке админки и в списке благодарностей, если тестер не
оставил поле пустым.

`sha256` — хэш PNG, который игрок видел. Отметка привязана к **версии** картинки, а не к имени:
перерисовали кадр — хэш сменился, старые отметки к нему больше не относятся и не всплывают.

### Отправка

- Кнопка «Отправить» в просмотре делает то же, что F8: лаунчер (`--report`) с приложенным `.tsv`
  и видом отчёта «проверка арта». Отдельной сетевой части в движке нет.
- Портал принимает `.tsv` как текст (правила вложений те же) и дополнительно проверяет каждую
  строку: `sha256` обязан быть в одном из опубликованных манифестов — у сборщика релизов есть
  хэш каждого файла. Выдуманные кадры и мусор отсекаются без ручного разбора.
- В админке — сводка по кадрам: сколько «брак», «сомнительно», «годно», от скольких людей, какие
  причины и комментарии; сортировка по числу «брак». Выгрузка списка наборов через запятую —
  готовый `--sets` для перерисовки, как делает `review_floors.py --report`.
- Лимиты: не больше N строк в файле и M файлов в сутки от одного отправителя (настраиваемые,
  `ArtReview__MaxLines`, `ArtReview__MaxPerDay`).

### Очередь

Сначала — все кадры мода по порядку наборов из переписи (`census/`). Дальше — очередь с сайта:
что перерисовано недавно и что никто ещё не смотрел; лаунчер кладёт её в
`user/art_review/queue.txt` вместе с проверкой обновлений. Так тестеры не смотрят в десятый раз
одну пустыню.

## Порядок

1. Вкладка HD — вместе с шагом 2 EDITIONS (движок: `OXCE-HD`, `autoEnable`, строка обновлений —
   она и так ложится во вкладку HD).
2. Просмотр и `.tsv` в движке — без сети, польза сразу: мы сами можем гонять приёмку в игре.
3. Отправка через лаунчер, проверка по манифестам, сводка в админке — вместе с этапом 4 (отчёты
   о падениях идут той же дорогой).
4. Очередь с сайта.
