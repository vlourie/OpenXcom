# PHOTO-база предметов

Статус на 01.10: **preferred baseline, не PRODUCTION_APPROVED.** Прямой RGBA (`obj_photo.py --rgba`, turbo) -
только эксперимент. Следующая веха - PHOTO acceptance v1 на геометрию и альфу (см. внизу).

Основание: PHOTO v2 вслепую, A (PHOTO) лучше на 6 из 8 (`art/objects/generation/probes/photo-v2/summary.md`),
специалист 01.10: база - фото-рендер, а геометрию и альфу решать отдельными ступенями, не промптом.

## Ступени

```
кадр 32x40 ─► guide ─► рендер PHOTO на подложке ─► fit_shape ─► conformity ─► FAIL: не вырезать
                                                         │                   RERENDER: перерисовать на panel_for
                                                         ▼
                                            fit (правка пропорций до 1.3) ─► managed_alpha ─► decontaminate
                                                         ─► match_tone 0.7 ─► split по клеткам ─► qa
```

Код - `tools/hdart/photo_base.py`, проверка - `tools/test_photo_base.py` (синтетика, без видеокарты).

| Ступень | Что делает | Почему так |
|---|---|---|
| `guide` | силуэт k=1, прорези (внутренняя пустота больше 4 пикселей; до 4 - шум индекса 0), тонкие части (не переживают открытие 3x3), тёмное (яркость < 60), силуэт x4 линиями через xBRZ | прорези probe_object заливал до 48 пикселей - решётки и спинки стульев теряли окна |
| рендер | параметры A made01 (#259): полный Qwen-Image-2.1, 40 шагов, cfg 4, 1 Мп, bicubic x16 на подложке, промпт `obj_photo.PHOTO` - `RENDER` в коде | своего запуска пока нет; будет отдельным скриптом. **obj_photo.py не править**: он в `CODE_PARTS` turbo, правка снимает утверждение пилота до нового smoke |
| `panel_for` | подложка: серые, если запас тела до подложки (10-й перцентиль, худший канал) не меньше 40, иначе зелёная или синяя | серое тело на серой подложке контуром не отделить (R-089) |
| `fit_shape` | ответ в пропорциях модели: единый масштаб, низ/верх/середина - берётся положение с лучшим совпадением с силуэтом | `fit` с правкой пропорций растягивает тело на место пропавшей ножки и прячет её (контрольный опыт в тесте: охват тонкого 1.0 против 0.09) |
| `conformity` | охват и вылет с допуском полпикселя базы, охват тонкого, прорези сохранены (фон или подложка и её тень), куски больше 1 процента, пропорции | вердикт PASS / REVIEW / FAIL / UNVERIFIABLE |
| `managed_alpha` | тримап от силуэта оригинала: ядро (силуэт минус 6 пикселей x4, минус прорези) - 1; дальше 6 пикселей от силуэта и глубина прорезей - 0; полоса - по ответу. В прорези подложка и её тень (0.6-1.0 яркости) - фон; в кольце вокруг прорези - только сама подложка. Ровный карман подложки над тёмным оригиналом - щель, прозрачно; над светлым - не прячется, идёт в `core_panel` | порог по цвету подложки один на весь кадр выгрызал серый металл (R-062); матт по контуру не доходит до закрытых карманов - серые окна в решётках у A |
| `decontaminate` | цвет полупрозрачной кромки без подложки: F = (C - (1 - a) B) / a | серый ободок (R-067) |
| `qa` | cover_final, spill_final, semi, core_panel (тело не нарисовано - подложка в ядре), rim_panel (подложка по кромке) | |

Вердикт кадра: **FAIL** - форма другая, вырезкой не чинится (тонкое < 0.5, прорези < 0.4, охват < 0.80,
пропорции > 1.6). **REVIEW** - охват < 0.92, вылет > 0.12, другое число кусков, пропорции 1.3-1.6 (тогда и
FAIL по деталям уходит в REVIEW: детали в чужих пропорциях съезжают с места), core_panel > 0.03, rim_panel >
0.25. **RERENDER** - запас подложки < 40 и недобор по охвату или тонкому: матт не отделил тело, форма
неизвестна. Пороги черновые (`GEOM` в коде).

## Находка: модель не держит подложку

made01 подавал подложку `po.pick_background` (тёмную для светлых предметов), а все 20 ответов вернулись на
светло-серой 165-191 (`panel_drift` в eval.tsv: у 9 из 20 больше 100). Значит выбор подложки на входе ничего
не решает: рендер базы обязан задавать цвет подложки и в промпте, и проверять его в ответе (`panel_drift`),
иначе светлые и серые предметы снова на подложке своего цвета.

## PHOTO acceptance v1 (утверждено специалистом 01.10; рендер готов, ждёт вердикта Vitali)

Код - `tools/hdart/photo_accept.py` (отбор, машинный отчёт, слепая страница, матрица) и
`tools/hdart/photo_render.py` (рендер photo_render_v1), проверка - `tools/test_photo_accept.py`. Всё - в
`art/objects/generation/probes/photo-accept-v1/`. В пак не идёт; статус PRODUCTION_PILOT_SIMPLE_OBJECTS
решается только по итогу.

**Набор** (`photo_accept.py select`, зерно `photo-accept-v1`): ворота pilot_batch без фильтра сложной
геометрии по названию (тонкие и с прорезями - и есть предмет проверки); исключено всё виденное - photo-v2,
20 регрессии, регрессия детали (с копиями кадров), все задания made01 (87 в один кусок и составные), слова
DETAIL_CRITICAL, обломки и куски корпуса (R-153), касание края кадра, меньше 150 пикселей. Из 61 годного - 20,
не два кадра одного набора: трудный край 2 (лучшая серая подложка ближе 40 - рендер на цветной), светлые 3,
прорези 4, тонкие 4, тёмные 3, простые 4. Светлых с яркостью выше 165 в пуле только три, и две из них с
прорезями - порог светлых 155. Код photo_base и photo_accept заморожен sha256 в `selection.json`.

**Рендер** photo_render_v1 (generator_rev `b5c0fcb9227f`, вырезка cut_rev - sha256 photo_base.py): параметры
A, модель по замку (коммит, без сети, без LoRA). Подложка `panel_for` - и картинкой, и текстом: серая фраза
PHOTO заменена цветом, в конце "Render the object on a uniform neutral background: RGB(r, g, b). The background
must remain completely flat and unchanged." Подложка ответа (медиана полосы 8 пикселей) дальше 24 от
поданной - PANEL_MISMATCH, перерисовка новым зерном (+1000), а не вырезка из чужого фона. Форма не
проверяется (тело цвета подложки ответа) - перерисовка на следующей по запасу подложке. До 3 попыток.

**Машина** (`checks`): PANEL, ALPHA, SILHOUETTE, FOOTPRINT (нижние 20 процентов силуэта закрыты ответом),
MISSING_MAJOR_PART, EDGE_SPILL, OPENING_PRESERVATION -> PASS / REVIEW / RERENDER / FAIL. Пороги формы -
`photo_base.GEOM`, свои - `photo_accept.MACHINE`. ALPHA FAIL - только явная поломка (подложка в ядре > 0.10,
по кромке > 0.50); полупрозрачное - REVIEW (у тонких полоса 1.5 пикселя - известное, её сейчас не меняем:
это была бы подгонка под обучающий набор). Форма не проверяется - всё, что меряется по матту, тоже RERENDER,
а не FAIL. Итог: PASS / PASS_AFTER_RERENDER / REVIEW (в том числе незакрытый RERENDER) / FAIL.

**Человек** (`page`): вслепую - без вердикта машины, страта и числа попыток, порядок перемешан. PASS / FAIL,
класс брака ALPHA / GEOMETRY / IDENTITY / MATERIAL / DETAIL / INVENTION, критерии OBJECT_IDENTITY,
MATERIAL_QUALITY, MAJOR_GEOMETRY, INTERNAL_STRUCTURE, PHOTOREALISM, INVENTED_DETAIL.

**Ворота PHOTO_ACCEPTANCE_V1** (`report`): human PASS >= 80 %; machine false-accept <= 10 % - доля брака по
человеку среди принятых машиной (PASS и PASS_AFTER_RERENDER), то есть сколько плохих прошло бы без человека;
alpha hard fail <= 5 % (машина ALPHA FAIL или класс ALPHA у человека); GEOMETRY у человека меньше чем у 3;
